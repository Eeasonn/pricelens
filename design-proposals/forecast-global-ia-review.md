# ForecastPage 全局信息架构审视

> 日期：2026-11-04  
> 范围：量价预测推演工作台（ForecastPage）；仅设计审视与目标设计，保持 `computeWorkbench` 的①→④阶段顺序。  
> 标尺：Eason 的四类内容心智模型与①基线 → ②大盘 → ③库存 → ④成本及销毛计算顺序。  
> 状态：已完成；七部分及拍板后的统一方案附录齐全。

## 审视口径与红线

- 类 1：必须人工输入；类 2：历史可生成可信参考并允许快速修改；类 3：Agent 情报先转为带时长、幅度的确定性事件，再由人审核；类 4：用界面明确表达固定计算顺序。
- 概率语言已删除，统一使用证据语言；微调原因与事件名称均选填。
- 图上只保留数据与控件；事件与调整不进入 `WorkbenchParams` 既有边界。
- 成本不进入销量/价格的需求数学映射；成本只形成人工调价参考回路与销毛输入。
- 事实引用到 `文件:行号`；未见实现直接支撑的判断标注「推断」。

## 一、四类情况 × 现状映射总表

### 1.1 总体判断

当前工作台已经具备五张业务卡和一套共享结果，但四类内容的完成度不均衡：**类 2 的大盘证据最完整，类 1 的 SI 有输入控件但缺作业状态，类 3 只有占位和人工录入，类 4 有局部链路文字但没有统一的全局顺序语言。** 页面共享 `params` 与 `result`，不是五张各自计算的卡（`pricelens/src/pages/ForecastPage.tsx:124-130`）；问题主要在设计如何揭示这一份结果的形成过程，而非再造计算链。

另一个必须显式记录的事实差距：当前预测基线直接读取 fixture 的 `basePath`，其语义是已包含大盘延续、黑五形状和上一代形态的演示序列（`pricelens/src/pages/forecast/workbenchFixture.ts:212-213`、`pricelens/src/pages/forecast/workbenchFixture.ts:254-258`）；预测周再乘大盘、产品事件和上一代比值（`pricelens/src/pages/forecast/workbenchModel.ts:745-758`）。因此，“上一代 + 本品历史量价关系生成第一轮基线”在界面上不能声称已经完整实现；本品历史在当前函数中主要进入历史库存、历史销量与销毛，而不是动态拟合 `basePath`（`pricelens/src/pages/forecast/workbenchModel.ts:760-791`、`pricelens/src/pages/forecast/workbenchModel.ts:903-908`）。本文后续只做呈现与交互设计，不把这一点改写成模型已具备的能力。

### 1.3 映射结论

1. **类 1**：不是“有没有输入框”的问题，而是“用户是否知道必须确认什么、缺省时发生什么、改后影响哪里”。SI 目前只有第三项的一部分。
2. **类 2**：大盘已形成可复用的证据范式；主图、参考和成本分别只有构成、历史读数、公式之一，尚未成为同一种证据语言。
3. **类 3**：主图历史回放是“人工选事件后参考幅度”，不是 AI 情报审核；大盘 Top5 则只是静态占位。两端尚未连成数据流。
4. **类 4**：卡内表达优于全局表达。尤其主图位于页面首位且只露最终值，容易让用户把“微调最终结果”误认为“第一轮基线编辑”。

## 二、管线顺序呈现审视

### 2.1 页面卡序与计算顺序不是同一问题

当前视觉卡序是：**主图 → 量价参考 → 大盘 → 库存 / 成本销毛左右列**，代码顺序与此一致（`ForecastPage.tsx:294-409`）。这套卡序适合“先看结果、再核对原因”的会议场景，应保留；不应为了模拟计算顺序而把主图搬到底部。

但当前界面没有同时说清另一件事：计算顺序是**①基线 → ②大盘修正 → ③库存修正 → ④成本及销毛**。`computeWorkbench` 在预测周把预置 `basePath`、大盘、产品事件和上一代比值合成库存前销量，再做库存截断，最后叠加手调并计算最终销毛（`workbenchModel.ts:745-815`）。因此需要采用“双序”而不是二选一：

- **阅读顺序**：结果总览永远居首。
- **计算顺序**：由固定的①–④管线导航和卡头徽标表达。
- **主图身份**：不是①，而是「结果总览 · ①–③后的最终 SO；④使用其价格与最终 SO」。这样可消除“主图在第一屏，所以它就是第一步”的误读。

### 2.2 IoBar / FlowBar 能表达什么、不能表达什么

`IoBar` 是一行“输入 → 输出”文本（`WorkbenchBits.tsx:77-97`），适合说明单卡职责；库存与成本的 `FlowBar` 能表达卡内依赖和触发状态（`InventoryValidationCard.tsx:78-112`、`ForecastMarginCostCard.tsx:70-104`）。它们不足以承担全局 IA，原因有四：

1. **编号冲突**：库存、成本各自从 1 编到 5（`InventoryValidationCard.tsx:88-106`、`ForecastMarginCostCard.tsx:80-99`），与全局①–④没有从属关系。
2. **没有跨卡方向**：主图 IoBar 同时罗列大盘、参考、小事件和库存最终结果（`ForecastPage.tsx:319-322`），但没有告诉用户应去哪张卡核对或修改。
3. **没有阶段前后值**：能读“发生了什么”，不能稳定回答“这一步之前的口径是什么、这一步改变了什么”。目前可用的是 `unconstrained`、`supplyCapped`、`final`、`manual` 等结果字段，不应在 UI 另算一套阶段数。
4. **状态分散**：AI/人工、库存修正、参考草稿各自有标，但没有“哪一步被改过”的统一扫描方式。

结论：**保留 IoBar 作为卡内口径，精简 FlowBar 作为卡内子步骤；新增一条页级管线导航承担全局顺序，而不是继续加長 IoBar。**

### 2.3 改进设计：一条全局管线、两种序号、三类回跳

#### A. 页级 `PipelineNav`（设计名，不要求新增视觉体系）

位置：首卡范围行之下、结果主图之上；复用 `WorkbenchBits` 的紧凑 chip、hairline、`canvasSoft2` 和文字状态，不新增颜色或卡片套卡片。

```text
推演顺序  [① 基线预测 · 已选上一代] → [② 大盘修正 · AI/人工] → [③ 库存修正 · 未触发/W50 起] → [④ 成本及销毛 · $…]
           查看参考                    查看大盘                  查看库存                       查看结果
```

- 四个节点都是按钮，点击只滚动并聚焦目标卡，**不写 `WorkbenchParams`、不重算**。
- 节点常态只显示名称和一个最关键状态；详细输入输出仍留在卡内。
- 当前定位用既有选中色 + `aria-current="step"` 的文字等价；库存触发继续使用琥珀，人工修改使用墨色/文字，不以颜色单独表达。
- ④不是“对主图的第五步修正”，节点 title 固定写明「读取最终 SO、价格与成本，输出经营结果；不回写主图」。
- 在窄屏或卡内横滚场景，节点允许横向滚动，不把四个节点压成难以点击的小字。

#### B. 卡头统一徽标

| 现有卡 | 卡头身份 | 处理 |
|---|---|---|
| 量价预测主图 | `结果总览` | 不占①；副标只保留最终口径与微调入口。 |
| 量价参考产品 | `① 基线预测 · 历史参照` | 面板继续保留「主链 · 同周龄校正 / 仅对照」。 |
| 大盘 · 总量总线 | `② 大盘修正` | 保留「AI 推测 · 可改」及证据三步链。 |
| 库存验证 | `③ 库存修正` | 卡内五节点改为无编号或 `3a–3e`，避免第二套 1–5。 |
| 成本销毛 · 经营结果 | `④ 成本及销毛` | 卡内链路改为无编号或 `4a–4d`；末端继续标「不回写主图」。 |

类 1/2/3 不与序号混写：另用「需确认」「历史参考」「待审核」等任务状态标。序号只回答计算位置，不能兼作进度百分比或完成度。

#### C. 卡内 IoBar / FlowBar 收敛

- 主图不再用一条长 IoBar 复述所有输入，改为「结果口径：①–③后的最终 SO · 手调只改展示终值」；保留库存截断事实与手调优先的说明。
- ①参考卡**不恢复旧 IoBar**；由卡头「① 基线预测 · 历史参照」与现有首预测周比值行共同承担输入/输出说明。事件补录和颜色配置不列为模型输入。
- ②大盘 IoBar 固定为「输入：历史月度指数 + 已审核事件 → 输出：大盘修正」；月调整和事件的实际差异在证据浮框解释。
- ③库存 FlowBar 保留“基线 SO → 反算 → 判定 → 上限修正 → 回写主图”，但不再从 1 编号。
- ④成本 FlowBar 保留“价格 + 成本 → 单台销毛 → × 最终 SO → 期销毛”，但新增的是跳转动作而非更多节点。

#### D. 跨卡联动导航

统一使用短暂的 `crossCardFocus` 视图态（**设计推断/建议**）：只存来源卡、目标卡、周或月、事件 id，不进入 `WorkbenchParams`，不触发模型 setter。

1. 主图 `WeekTooltip` 的「大盘」→ ②并打开该周所属预测月证据；「上一代」→ ①并定位当前主链面板；「库存上限修正」→ ③并定位同一周；「预测期销毛」摘要 → ④。
2. ③修正周 / 输出框 → 返回主图同一周，主图仅临时强调该柱；不清除手调、不改库存。
3. ④「回到量价调整」→ 主图对应周；若来自成本调价参考，则携带的是**建议参数草稿**，需人工再确认，详见第四节。
4. 目标卡头出现一行非阻塞来源条：「来自结果总览 · 2026W50　返回」；返回只恢复滚动与选中，不回滚任何编辑。
5. 大盘月与主图周的粒度转换只用于定位；统一为附录 A 的 12 个月后，月与周必须能互相定位。只有超出共同预测日历的情报才显示「范围外 · 仅收藏」，不伪造落点。

### 2.4 管线中的孤儿组件处置原则

- 不再接入旧 `CalculationPath` 来充当全局管线：它消费 simple-v1 的旧 `ForecastComputation`，会带入另一套口径。页级导航应直接消费当前 `WorkbenchResult` 和 `params`。
- 不接 `DriverWaterfall` 重画贡献：主图已有 `WeekTooltip`，再接会形成第二套构成语言。
- `WeeklyLedger` 是唯一值得保留“表格职责”的候选，但须改造成 v2 的阶段明细并合并进主图现有数据表，不能成为第二个主账。
- 其余逐项删/改理由见第六节；本方案不要求为消灭孤儿而把它们全部接回页面。

### 2.5 不越界的实现意图（仅设计）

管线导航、卡头徽标、跨卡选中与返回都是呈现层状态；不需要改变 `computeWorkbench` 的管线结构，也不需要把事件、调整或跳转状态塞进 `WorkbenchParams`。若未来要展示“仅①后、仅②后”的独立数值序列，当前结果并未完整暴露这些中间阶段；届时应另做只读阶段快照设计评审，不能在 tooltip 中自行反推。**本方案没有红线变更建议。**

## 三、逐类体验设计

### 3.1 类 1：SI 是必须确认的人工输入，不只是一个数字格子

#### 设计原则

1. **必须逐月确认，不阻断参考预览**：首次载入可沿用基准 SI 生成参考结果，但③卡头和全局管线显示「SI 待确认 12 / 12」；结果主图也显示轻量「③ SI 待确认」。用户逐月确认后才成为人工已确认的推演，不把 fixture 默认值冒充用户输入。
2. **空、零、无效是三种不同状态**：`0` 是明确的“本月不补货”；空白是未完成；负数、非数字、超上限是无效。不得把空白静默写成 0，也不得在用户输入过程中把非法值直接钳成另一个数。
3. **按月确认、按周解释**：输入仍是月粒度；每格下方或 title 显示实际拆周结果和余数分配。模型已有“先整除、余数从月初周起 +1 台”的守恒逻辑（`workbenchModel.ts:676-693`），界面应把它说成事实，不另算一套。
4. **有效提交即联动，错误不打断草稿**：合法值在 blur / Enter 时提交并立即重算；输入中的半截文本只留在本地编辑态。Esc 恢复最后有效值。
5. **可恢复优于强校验**：每格提供「恢复基准」，最近修改提供「撤销」；清空不会偷偷回默认值，而是显示「未填写」及一键恢复。

#### 目标格子结构与状态

```text
SI 月计划 · 2026-11—2027-10   [待确认 12 / 12]                 [恢复基准]
2026-11  [ 220 ] 千台  [基准·待确认] [确认本月]   拆周 55 / 55 / 55 / 55 千台
2026-12  [  32 ] 千台  [已修改]     [确认本月]   拆周 8 / 8 / 8 / 8 千台
…        每个月独立确认；不提供“全部确认”
```

- `基准·待确认`：有可参考默认值，但用户尚未操作；点击「确认本月」或修改并提交后转为「已确认 / 已修改」。
- `未填写`：保留空框和错误提示，提交被阻止；其他月份和上一次有效推演仍可查看。
- `无效`：字段红边 + 文案 + `aria-invalid`；显示允许范围，不把错误只放在 title。
- `已修改`：显示相对基准差值；「恢复基准」只恢复本月，不等同页面级「重置基准」。
- `保存失败`：保留内存值并标「未持久化 · 重试」；参考卡已有相同语言可复用（`ReferencePanel.tsx:945-956`）。

现状 `InputNumber` 在 `value == null` 时直接不提交，负值会被钳 0（`InventoryValidationCard.tsx:243-266`），归一化对错型又会回基准（`workbenchModel.ts:1049-1057`）。目标设计需要把这些“后台兜底”变成用户可理解的前台状态；不改变后台 sanitize 兜底。

#### 错误、缺省与恢复路径

| 场景 | 界面行为 | 模型/结果行为（设计边界） |
|---|---|---|
| 首次未确认 | 显示基准值与「待确认」 | 继续出参考结果，但不标为人工确认。 |
| 清空 | 保留空白，提示「请输入 0 或恢复基准」 | 继续显示最后有效结果并标「有未提交输入」，不把空白当 0。 |
| 负数/超范围/非数字 | 就地错误，提供恢复 | 不提交；不静默钳制后伪装成功。 |
| 输入 0 | 正常提交，显示「本月不补货」 | 立即重算库存、DOS、修正周和主图。 |
| 恢复基准 | 回填基准并给出撤销 | 回到该月基准；其他人工编辑不动。 |
| 会话坏数据被后台剔除 | 卡片显示「部分输入已恢复基准」并列月份 | 保留 normalize 的安全结果，同时让恢复可见。 |
| 页面级重置基准 | 二次确认说明会清 SI、事件与手调 | 沿用现有 `resetParams` 边界（`useWorkbenchParams.ts:44-47`），参考卡独立工作区不清。 |

#### 与图即时联动

- 提交前：格子显示「待应用」仅在采用显式按钮方案时出现；推荐默认 blur/Enter 自动提交，不增加“应用”步骤。
- 提交后同一帧语义反馈：③库存柱/DOS 更新，受影响月临时强调；主图修正周同步更新；页级③节点更新「未触发 / Wn 起」。
- 结果条写前后变化，例如「12 月 SI +10 千台 → W50 起修正已解除」；仅当前后结果确实存在该变化时显示，不生成泛化赞美。
- 手调优先的现有规则不变：若某周有人工手调，库存截断事实仍保留但最终显示手调值（`workbenchModel.ts:803-815`）。联动反馈须写「截断事实仍在，主图该周显示手调值」，不能声称 SI 已改变手调结果。
- 所有反馈有 `aria-live` 文字等价；键盘可完成编辑、确认、恢复和跳转，不要求 hover 图柱。

### 3.2 类 2：统一“证据语言”，不是给每卡机械复制同一张图

#### 统一浮框骨架

以大盘 `MonthEvidencePopover` 为交互标杆，以主图 `WeekTooltip` 的紧凑构成为密度标杆，形成四层：

```text
[时间 / 对象]                         [AI 基线 / 人工确认 / 仅历史]
[条件状态] 含事件、含手调、缺数、样本不足、成本版本等
[证据三件套] 来源高亮 + 必要的趋势/对照小图 + 构成算例
[动作] 调整此月/周 · 还原基线 · 定位来源 · 关闭
```

视觉复用白底、`hairline`、`radius.card`、`shadow.l5`、`canvasSoft2` 算例底；现有大盘浮框已是这套语言（`MarketBusPanel.tsx:108-113`）。浮框默认可 hover 预览、点击/Enter 固定；进入编辑态后保持粘滞，Esc 先返回证据态，再关闭。

#### 三件套适用规则

| 构件 | 什么时候必须有 | 什么时候不适用 / 替代 | 红线 |
|---|---|---|---|
| **趋势 sparkline / 对照小图** | 预测确实使用时间趋势、季节或同周龄形态时；至少 2 个有效点 | 单一版本值、事件名录、纯库存截断不强行画趋势；改用前后值或三柱对照 | 小图必须来自模型/事实点；缺数显示不足，不补点。 |
| **构成算例** | 每一个派生预测值、调整值、销毛值 | 原始事实行只列来源和口径，不伪造公式 | 公式、输入、舍入与模型一致；UI 不另编贡献。 |
| **来源高亮** | 来源点在当前图或参考面板可见时 | 来源在窗外时显示「定位来源」；跨卡来源用第二节导航 | 高亮是临时证据锚，不新增常驻装饰，不把相关性画成因果。 |

三件套是**语义完整度规范**，不是视觉拷贝：大盘需要“近 6 月 + 去年同季三柱”，参考需要“同周龄段 + 比值算例”，成本需要“版本阶梯 + 单台/期销毛算例”。

#### 分卡落地

**① 量价参考**

- 浮框头：`Mate 80 · 同周龄 W1–W8 · 仅历史`。
- 小图：当前参考与默认参照的同周龄有效点；若只比较一个预测序位，显示两点/对照柱，不强画趋势。
- 算例：严格按当前模型写 `所选参照同序位值 ÷ 默认参照同序位值 = ×比值`（模型依据见 `workbenchModel.ts:708-733`）。
- 来源高亮：主图预测周 → 参考图对应周龄段；参考面板锁定时只展开详情，不改窗口，沿用现有规则（`ReferencePanel.tsx:781-793`）。
- 事件时段读数保留现有前后段、覆盖率和公式（`ReferenceVolumeChart.tsx:645-658`），只统一外壳和动作位置；预标影响永远与实测分栏。

**结果主图**

- 浮框头区分「①自动学习基线 / ②大盘修正后 / ③库存修正后 / 手调后显示值」，避免只给一个最终值。
- **目标基线 = 自动学习**：浮框列训练样本时间窗、有效周数、实际使用的历史特征、上一代同周龄映射、促销/特殊事件、模型版本和回测误差；这些字段都来自学习器输出，不能只换一个「AI」徽章。
- 小图使用本品历史实际、学习拟合段和预测段；另列上一代同周龄来源段。回测只展示 MAE/MAPE 等可复核误差，不使用概率或置信区间。
- 算例按阶段展示「①学习基线（含参考与产品范围事件） → ②大盘修正 → ③min(可售) → 手调（如有）」。学习器应导出可复算的参数/规则与中间值；UI 不根据图点反推学习结果。
- **迁移期诚实口径**：当前实现仍读取预置 `basePath`（`workbenchFixture.ts:212-213`）。自动学习完成前只准标「预置基准走势（演示）」，不得把现有序列冒称已学习。
- 来源高亮：大盘项跳②对应月，上一代项跳①同周龄，库存项跳③同周；学习样本可定位到①本品历史与参考段，没有证据来源时不放假锚。
- 价格→销量关系未定前，自动学习不得暗自使用价格弹性作为因果特征；浮框明确「价格关系未纳入」。
- 快速修改仍进入现有逐周微调，原因选填；增加「清除手调」和撤销即可，不把证据浮框改成多字段编辑器。

**② 大盘**

- 保留现有 sparkline、三柱、算例、双锚和两态浮框，作为其他卡的实现参照（`MarketBusPanel.tsx:187-313`）。
- 补一条状态说明：人工月值优先于该月事件后的生效值（`workbenchModel.ts:367-377`）；显示「本月已手调，事件仍保留但不再改变本月生效值」。
- 修改后保留 AI 基线虚线和「还原 AI」，继续作为类 2 的快速恢复范式。

**④ 成本参考与销毛**

- 小图：成本月版本阶梯；只有真实多点时才称趋势。成本点与对应主图价格点同读，不推导价格建议。
- 算例：`价格 − 当月版本成本 = 单台销毛`；`单台销毛 × 最终 SO = 周销毛`，与现有口径一致（`ForecastMarginCostCard.tsx:276-299`）。
- 来源高亮：成本版本切换点；点击价格来源回主图同周，点击 SO 来源回③或主图最终结果。
- 快速人工修改只修改成本/销毛工作区的版本假设，绝不进入销量、价格或事件的需求数学映射；具体回路见第四节。

#### 通用证据状态

- `模拟 / 模拟历史 / 混合` 文字标继续存在；证据来源写名称、采集/版本时间和覆盖范围，符合 `PRODUCT.md:108-124`。
- 数据不足显示「无法计算 + 缺少什么」；参考卡已有“有效周/事件周”范式，可推广。
- 不使用概率、P10/P50/P90、置信区间或“把握”话术；证据强弱改写成「来源齐全 / 缺少幅度依据 / 待人工确认」等可核查状态。
- 所有 hover 都有 focus/click 等价；所有小图都有文字算例或数据表替代。

### 3.3 类 3：AI 情报 → 转化推荐 → 人工审核

#### 体验总原则

**情报事实与推演假设必须是两层。** 情报卡回答“外部发生了什么、来源是什么”；转化推荐回答“若把它当作模型事件，建议落在哪里、持续多久、幅度多少”。AI 不得直接把情报写进事件，也不得把“ AI 推测 · 可改”的本地时间序列徽章当作情报审核能力；该徽章目前明确是本地确定性规则、未调用模型服务（`WorkbenchBits.tsx:36-52`）。

闭环固定为：

```text
情报进入候选区（只读事实）
  → 生成确定性事件建议（落点 + 起始 + 时长 + 幅度 + 依据状态）
  → 用户先浏览 Top5，移除明显无关项
  → 逐条 接受 / 改参 / 拒绝
  → 接受或改参后先看影响预览
  → 人工确认应用
  → 写入既有事件集合 + 图上落点 + 可撤销
```

AI 抓取、排序模型和幅度算法另议；本节只规定界面、状态和现有事件接口的数据流。

#### A. 情报入口与候选区

- **主入口仍在②大盘卡右 1/3**：把当前五个禁用假行（`MarketBusPanel.tsx:434-470`）换成真实候选列表容器。能力未接入时只显示一个空态和禁用按钮，不再展示五条看似有数据的占位记录。
- **主图产品事件入口增加候选页签**：「AI 候选 / 人工录入」。人工录入继续保留历史回放；AI 候选只在选择“应用到主图”后进入同一回放/预览，不另建产品事件编辑器。
- **成本情报只进④的“调价参考”**：例如内存涨价若只证明成本变化，默认落点是成本参考，不是大盘需求事件。若候选同时声称影响需求，必须由人选择目标并看到重复计入提醒。
- 页首「让 Agent 解释」仍是解释入口，不 silently 变成抓取或写入入口。

候选区标题建议改为「情报候选 · 待审核」，保留 Top5 数量语义但不使用 AI 专属色。每行先展示：**名称/摘要、来源与日期、建议落点、起始、时长、幅度建议、依据状态**；来源未核实、缺字段或超出演示窗都直接写出。

#### B. 情报与推荐的数据分离

以下是逻辑字段契约，不要求把来源元数据塞进现有事件 seed：

| 层 | 字段 | 界面用途 |
|---|---|---|
| `IntelligenceItem` 情报事实 | `intelligenceId`、标题、摘要、原文摘录 | 只读事实区；编辑事件不改写情报原文。 |
| 同上 | 来源名、可访问链接、发布时间、抓取时间、`real/simulated/mixed` | 证据与数据状态；无链接写「暂无来源链接」。 |
| 同上 | 国家/产业/渠道/产品范围、观察到的发生时间 | 判断是否能匹配当前工作台；范围不符时禁止直接应用。 |
| `EventRecommendation` 转化建议 | `candidateId`、`intelligenceId`、建议目标 `market-month / product-week / cost-reference` | 决定②、主图或④的落点；目标可人工改选，但需重新校验。 |
| 同上 | 事件类型、建议起始月/日或起止周 | 映射到统一预测日历；超出 2026-11—2027-10 则只收藏，不可应用。 |
| 同上 | **范围建议** `rangeSuggestion { start, end, unit }` + 派生时长 | 大盘映射起始月/日 + 月时长；主图映射任意起止周闭区间，不再限制单周。 |
| 同上 | **幅度建议** `magnitudeSuggestionPct`、方向、建议理由 | 只作可改假设；不得写成情报事实或确定因果。 |
| 同上 | **转换置信** `confidence: supported / partial / insufficient` | 不显示概率或百分比；分别呈现「依据齐全 / 部分待核 / 需人工补参」，并列出缺少的字段或证据。 |
| 同上 | 历史类比 id、依据摘要、缺失字段、重复候选 id | 支持回放、人工补参和去重；历史类比不等于未来必然幅度。 |
| 审核状态 | `new / removed / editing / accepted / rejected`、编辑草稿、审核时间、已生成 eventId | 支撑先列后删、逐条审核、撤销和已应用定位。 |

“转换置信”仅描述**情报能否完整、明确地转换为事件参数**，不是预测发生概率，也不是模型置信区间。UI 主文案统一用「依据状态」。

#### C. 到统一目标模型的字段映射

| 推荐字段 | ②大盘月事件 | 主图产品范围事件 | ④成本参考 |
|---|---|---|---|
| 目标 | `target = market-month` | `target = product-range` | `target = cost-reference` |
| 起始/范围 | `startMonth + startDay` | `startWeekId + endWeekId`，使用跨年唯一周 ID | 成本版本月份/生效周；仅人工参考回路 |
| 时长 | `durationMonths`；首月按日均摊，后续月按现有线性递减 | `durationWeeks = endWeekIndex − startWeekIndex + 1`；任意闭区间，单周只是特例 | 作为成本版本覆盖期；不进入销量/价格需求公式 |
| 幅度 | `magnitudePct` | `magnitudePct` + 明确的 `decay = decreasing / flat` | 成本差值或版本假设，不映射成销量幅度 |
| 名称 | `label`，选填；空值显示未命名事件 | 类型默认名可保留，允许选填覆盖 | 情报标题作参考名，不改事件名口径 |
| 类型/回放 | 大盘行业事件类型 | 三类 `type` + 有效 `replayId`；回放可提供范围与形状建议 | 不适用 |
| 证据关联 | 外部审核表保存 `eventId ↔ intelligenceId` | 同左 | 同左；不扩展 `WorkbenchParams` 来存来源 |

**主图自由范围规则（本次已拍板）**：

- 编辑器提供起周、止周下拉与图上拖选；反向拖选自动排序，始终显示实际起止日期和派生周数。范围可与任意月份交叉，不按季度或档期截断。
- `magnitudePct` 表示起始峰值；`decreasing` 沿用现有周事件线性递减公式，`flat` 表示范围内恒定。形状默认递减，历史回放有明确依据时可预填恒定；用户可改，预览必须显示逐周影响。
- 一个范围只生成一个事件，不自动拆成多条相乘事件。计算适配逐周读取范围乘子，①→②→③→④阶段顺序不变。
- 主图锚点由单点竖线扩展为「A1 + 起止端点 + 顶部范围线」；不铺全高色带，详细名称与参数仍在名录/浮框。
- 当前代码的单周 `ProductEventSeed` 是迁移起点（`EventReplayModal.tsx:99-105`）；实施时需按附录 A 的红线变更记录扩展契约，不能再以“当前只支持单周”拒绝长范围候选。

#### D. 候选列表：先列后删，再逐条审核

初始状态一次列出最多 5 条，不自动勾选、不自动应用：

```text
情报候选 · 待审核 5                         [更新候选]
┌ 内存供应涨价                    [②大盘 / ④成本 待选择] [部分待核] ┐
│ 来源 · 发布时间 · 摘要                               [查看原文] │
│ 建议：2026-11-15 起 · 2 个月 · −6%（需求侧假设，待确认）         │
│ [接受] [改参] [拒绝]                                [移除出列表] │
└──────────────────────────────────────────────────────────────┘
```

- **移除出列表**：只清理明显无关候选，移入「已移除」并可撤销；不删除情报源，不等同“接受后删除”。
- **拒绝**：表示“这条不应进入本次推演”，记录拒绝状态；拒绝原因选填。与移除的视觉/数据状态可合并，但列表文案只保留一个主动作，避免同义按钮。
- **接受**：打开已映射的事件草稿和影响预览，不是立即写入。
- **改参**：打开同一草稿并聚焦首个需确认字段；缺时长/幅度时「接受」也进入补参，不允许空参数应用。
- **逐条原则**：不提供“一键全部接受”；无预览的批量应用不做。

#### D2. 批量处理：批量整理可以，批量生效必须有汇总审核

- 每行提供复选框，表头支持选择当前 Top5；默认不勾选。已应用项不可与待审核项混选。
- **批量移除 / 批量拒绝**：用于明显无关或本次不采用的候选；操作条显示数量，拒绝原因选填，整组作为一个可撤销动作。
- **批量预览**：仅当所选项依据齐全、目标相同、均通过范围/时长校验且互不重复时可用；否则按钮不可用并逐项列出原因，用户可转为逐条处理。
- 批量预览页按「共同情报范围 → 每条事件参数 → 合并影响 → 重复计入」顺序展示；主按钮是「确认应用 N 条」，不是“接受全部”。确认后作为一个审核批次写入现有事件集合并生成批次号，撤销以批次为单位；其中任一单项在预览后被改参，则退出批量确认，回到逐条审核。
- 跨②/主图/④的候选不允许多目标一键生效；只能批量移除/拒绝，或按目标分组分别预览。这样批量处理减少整理成本，但不绕过人的参数责任。

#### E. 审核抽屉 / 弹层：事实、建议、预览三栏顺序

在既有 Modal/Popover 语言中采用单弹层，不新增悬浮工作台：

1. **情报事实**：标题、原文摘录、来源、时间、数据状态、适用范围。整段只读。
2. **转化建议**：目标卡、类型、起止范围、派生时长、幅度与形状；字段均可改，名称选填。每个 AI 预填值旁标「建议」，人工改动后标「已改」。
3. **影响预览**：列出将影响的月/周、逐周范围乘子、现有同类事件、是否重复；用完成范围适配后的 `computeWorkbench` 对临时参数做只读预览，展示总销量/修正周等前后差，**在用户确认前不调用页面 setter**。这只是复用主链顺序，不新增一条计算链。
4. **动作**：主按钮「确认应用事件」；次按钮「返回候选」；有未保存修改时关闭不丢草稿。

依据不足时仍可人工完成，但必须显示「该幅度为人工假设」；无来源、范围不符或起止无效时，不以高置信口吻诱导接受。

#### F. 应用后的落点、重复与撤销

- ②事件：写入现有 `marketMonthEvents`，在大盘轴下出现次要标记，并能在对应月证据浮框看到复算提示；现有添加路径可复用（`ForecastPage.tsx:385-390`）。
- 主图事件：合法自由范围候选写入扩展后的 `productEvents`，出现 A 范围锚、派生时长和图下名录；现有单点锚/名录是迁移起点（`MainForecastChart.tsx:336-350`、`MainForecastChart.tsx:427-441`）。
- ④成本参考：只新增成本参考记录或成本版本草稿；不生成主图事件，不自动改价。
- 候选行转为「已应用 · 查看落点」，不消失；点击跳第二节的跨卡定位。已拒绝/已移除收进折叠区，可撤销。
- 审核工作区单独保存 `candidateId / intelligenceId / eventId / 审核状态 / 参数草稿`，事件数值仍走现有事件集合。来源映射不进入 `WorkbenchParams`。
- 撤销采用该事件的 before/after patch，不回滚整页后续编辑；删除已应用事件时，候选状态变为「事件已删除」，可重新进入预览而不是静默再写入。
- 同一 `intelligenceId` 已生成事件，或同类型同时段已有事件时，显示「可能重复计入」并列出落点。大盘与主图同时接受同一情报需要额外确认，因为两条链可能同时影响同一周。
- 页面「重置基准」后，已接受候选标为「事件已随重置移除」；重新应用仍需预览确认，不自动恢复。

#### G. 空、载入、失败和过期状态

| 状态 | 呈现 |
|---|---|
| 能力未接入 | 「候选生成能力待接入」+ 禁用按钮；不画五条假候选。 |
| 载入中 | 保留已有候选，显示「正在更新」；首次载入用中性骨架，不填事件名。 |
| 无候选 | 「当前情报没有可转化事件」；仍提供人工录入。 |
| 部分可转化 | 全部先列出；缺参行显示缺什么，允许改参，不允许空参应用。 |
| 来源失败 | 显示失败来源与重试；已有候选和人工事件不受影响。 |
| 情报已更新 | 标「来源已更新」；已应用事件不静默改参，用户选择查看新建议或保留现值。 |
| 超出当前窗口 | 可查看情报，但应用按钮禁用并说明缺失的预测范围；不造落点。 |

此设计沿用既有卡片、弹层、徽章、事件名录与 `WorkbenchBits` 语言，不引入概率表达、不自动写价格、不改变成本不进入需求模型的红线。

## 四、成本双重性呈现：人工调价参考回路 + 销毛输入

### 4.1 一句话边界

成本在页面上承担两个角色，但只有两个方向合法：

```text
角色 A · 调价参考：成本证据 → 人判断是否调价 → 人设置价格 → 主图价格微调
角色 B · 销毛输入：成本版本 + 主图价格 + 最终 SO → 单台销毛 / 周销毛 / 预测期销毛

禁止：成本变化 --自动公式--> 主图价格或销量
```

当前代码已守住数学边界：成本只形成 `unitMargin = price − unitCost`，并进入销毛（`workbenchModel.ts:667-674`、`workbenchModel.ts:770-791`）；④卡文案也明确“不回写主图、回头调价”（`ForecastMarginCostCard.tsx:324-338`）。差距在于“回头调价”没有动作，主图现有微调又只编辑周销（`ForecastPage.tsx:86-112`），不能拿周销弹窗冒充调价。

### 4.2 ④卡内部改成“两个阅读区、一个结果”

不新增 card-within-card，只用 hairline 分区：

1. **成本参考区**：月版本、来源/证据状态、相对上一版变化、成本证据浮框；未来版本可人工调整或还原基准。
2. **经营结果区**：现有销毛柱、价格线、成本阶梯和公式；主数字仍是预测期销毛。
3. **唯一人工动作**：「带到主图调价」。它是跳转与草稿预填，不是自动映射；没有用户输入的价格参数时，只提供方向性提示「成本上升 · 请核对价格」，不自动给出精确涨价金额。

成本建议与销毛结果必须使用不同文案：前者是「参考 / 待确认」，后者是「按当前量价与成本计算」。不得把成本上涨直接写成销量下降或价格必涨。

### 4.3 人工调价参考回路

#### 步骤 1：在④核对成本

- 用户选择未来成本版本，打开第三节的证据浮框，查看来源、版本覆盖、算例和当前单台销毛。
- 若是类 3 情报（如内存涨价），先经人工审核进入成本参考工作区；不生成大盘或主图事件，除非用户另行选择并确认需求侧假设。
- 用户可修改成本版本假设，原因选填，随时「还原成本基准」；修改只改变④的销毛结果，不改变销量、库存或事件。

#### 步骤 2：人设置调价参考，而非系统计算映射

在成本版本行选择「带到主图调价」，展开三个字段：

| 字段 | 规则 |
|---|---|
| 目标周/月 | 默认选成本版本首个未来生效周；用户可改，不能批量静默覆盖全预测期。 |
| 调价方式 | 「调整后价格」或「增减额/增减幅」；默认展示当前主图价格，不自动加成本差额。 |
| 参考说明 | 选填；可自动带入「参考④ 11 月成本版本」作为可编辑文本，但用户可清空。 |

AI 可以建议方向、提供历史类比和证据完整度；**精确价格参数必须可编辑且经人确认**。若没有任何定价依据，不预填数值建议，只预填当前价让用户决定。

#### 步骤 3：带参跳主图，人工再次确认

- 跳转后主图定位目标周，打开**价格微调**弹窗，而不是现有周销微调；显示「来自④成本参考」、当前价、参考价和返回④入口。
- **关系未定前的过渡预览**：只重算单台销毛、周销毛和预测期销毛；销量、DOS、库存修正保持不变，并在弹窗固定显示「价格→销量关系未纳入 · 暂不联动销量」。
- **关系拍板后的目标预览**：人工价格情景进入①自动学习基线，依次重跑②大盘、③库存和④销毛；预览同时列价格、销量、库存修正和销毛前后值。没有已拍板的价格关系时不得启用此路径。
- 用户点击「应用价格调整」才生效；原因选填；主图价格点以既有手调墨色小标表示，title/图下名录显示「价格手调 · 来自成本参考」及是否已联动销量。
- 应用后可撤销、清除价格手调；返回④可看到同一价格与销毛，不出现两个结果。

#### 步骤 4：结果回读

④经营结果区显示「含主图价格手调 Wn / 含成本假设 N 项」；点击分别回跳对应来源。全局④节点只展示销毛结果和「含人工假设」，不显示“已自动调价”。

### 4.4 数据流设计：成本只进④；价格联动销量等待独立关系契约

过渡态继续保持单一数字来源和“成本不进需求模型”红线：

```text
④成本参考 ──人工判断/设参──► 主图价格情景
                                  │
                                  ├─ 当前：MarginView + 主图价格显示值
                                  │          （明确「暂不联动销量」）
                                  │
                                  └─ 价格关系拍板后：①自动学习基线
                                                   → ②大盘 → ③库存 → ④销毛
```

- `computeWorkbench` 的①→④阶段顺序不动；成本 override 不进入需求公式，成本也永不直接生成价格。
- **价格影响销量是已确认的方向，不是已确认的公式。** 关系需要另行定义价格口径、参照价、弹性/分段形式、促销交互、样本与回测；未定前只能走过渡态。
- 所有卡片和摘要在过渡态消费同一个 `MarginView`，避免④改了成本而主图摘要仍显示旧销毛；目标态则消费同一份全链新结果。
- 成本/价格工作区需要会话持久化、版本和撤销；页面「重置基准」是否清它见开放问题，默认提供④独立「还原成本与价格基准」，不与参考卡工作区混清。

### 4.5 红线自检

| 检查 | 本方案 |
|---|---|
| 成本是否自动改主图价格？ | 否；必须人工设参、跳转、再确认。 |
| 成本是否进入销量/需求数学映射？ | 否；只进入④销毛。 |
| 是否借用现有周销微调伪装调价？ | 否；明确新增价格微调的独立交互语义。 |
| AI 情报是否直接改成本或价格？ | 否；先审核为成本参考，再由人决定。 |
| 是否改变 `computeWorkbench` 阶段顺序？ | 否；价格关系拍板前不改需求计算，拍板后仍按①→④执行。 |
| 是否引入概率或 AI 专属视觉？ | 否；沿用证据状态、既有 token 和弹层语言。 |

**成本回路本身没有红线变更建议；自由范围事件与自动学习的已拍板契约变更见附录 A，价格→销量的数学关系仍待定义。**

### 分期原则

- **P0 先修全局可理解性和输入诚实性**：不依赖 AI 抓取能力，不改主链。

### P1：自动学习、自由范围事件与审核闭环

### 设计验收总门槛

无论分期，以下任一出现即不通过：成本自动映射价格或销量；AI 候选未经确认写入；价格关系未定却暗中联动销量；概率/置信区间话术回归；原因或事件名称被改成必填；图上新增长解释；参考补录/颜色/窗口进入 `WorkbenchParams`；为展示中间阶段而在 UI 另算第二套模型；跨卡导航改变参数而非只定位。

| 数据层 | 统一样本要求 | 目的 |
|---|---|---|
| 本品周历史 | 扩展为至少 52 个连续历史周，固定种子生成；保留真实缺采状态，不用 0 补点 | 让自动学习有可展示的样本窗，而不是 8 周历史伪装成年季节学习。 |

| 预测周 | 由完整日期生成，覆盖上述 12 个月；跨年使用 `YYYYWww` 作为显示与技术标识，不以单独 `weekNumber` 充当跨年主键 | 避免 2026W52 与 2027W01 后身份、排序和事件落点失效。 |
| SI / 成本 | 均覆盖 2026-11—2027-10 的 12 个月；SI 每月有待确认状态，成本每月有版本与来源状态 | ③和④不再在主图窗口外失去输入。 |
| 促销与特殊事件 | 使用同一模拟日历；所有事件以真实日期/周区间定位 | 让①特殊事件、②大盘事件与跨卡导航引用同一时间对象。 |

生成必须是确定性的：固定 fixture、固定种子、固定日历推导；不得在渲染时随机生成，也不得把模拟学习结果写成真实市场结论。

### A.3 统一时间模型：同一范围，不同原生粒度

| 卡 / 阶段 | 计算与输入粒度 | 全期呈现 | 跨粒度规则 |
|---|---|---|---|
| 结果主图 / ① | 周 | 全 12 个月的预测周；X 轴以月份分组、保留 `YYYYWww` 读数 | 月→周只按周完整日期定位；不把月值均摊成另一套销量。 |
| ②大盘 | 月 | 同一 12 个预测月 | 周只读取所属月的大盘修正比值；大盘指数不是销量，不做容量拆分。 |
| ③库存 | SI 月输入；库存/DOS 周计算 | 12 个月 SI 全可见；图表覆盖全部预测周 | 沿用月总量→周整数守恒分配；跨月周按既定日期口径归属并在 title 明示。 |
| ④成本及销毛 | 成本月版本；销毛周计算 | 同一 12 个月成本版本与全期销毛 | 周读取当月成本；月销毛=周销毛求和，月末库存取该月最后有效周。 |
| AI 候选 / 事件 | 情报日期 + 目标原生范围 | 任何候选都先映射到同一预测日历 | 只有完全落在可计算范围内才允许应用；范围外交付「仅收藏」，不伪造落点。 |

页面只保存一份 `forecastCalendar`（逻辑设计名）：`horizonStart/horizonEnd`、12 个月键、周 ID、周起止日期、周所属月、月内周列表。所有卡片、事件编辑器、复制假设和导航都从它取时间，不分别生成范围。

### A.4 统一后的页面行为

1. **页首范围**：固定写「预测 2026-11—2027-10 · 12 个月 · 主图周 / 大盘月」；四张卡与复制假设使用同一文本。
2. **主图全期可读**：默认显示全期周柱/线，以月份分组刻度；提供「全期 / 三月 / 近 8 周」视图预设和局部横滚。视图缩放只改变可见范围，不裁剪学习样本或模型输入。
3. **SI 逐月确认**：12 格按四个连续三月组分组（2026-11—2027-01、2027-02—04、2027-05—07、2027-08—10）；每格独立「确认本月」，页级③显示「待确认 N / 12」。不提供一键全部确认。
4. **跨卡导航**：②某月可定位①/③/④该月全部周；周返回②时定位所属月。统一范围后不再出现“Q1 以后无法落主图”的结构性断点。
5. **统一摘要与导出**：预测期总销量、库存缺口、预测期销毛都覆盖同一 12 个月；若引用历史对照，另标历史窗口，不把 8 周历史与 12 月预测直接算同比。
6. **性能与密度**：视图窗口只控制渲染，不重算或裁剪模型；事件/调整长列表继续收进名录与数据表，图上不新增常驻说明。

### A.5 统一方案验收

- 页面、四卡、事件编辑器、数据表和复制假设的预测起止与 12 个月键完全一致；不存在旧的 2026-10 大盘预测起点或 W45–W52 主图终点。
- 跨年周 ID 唯一且排序正确；2027 年的事件、SI、成本和手调不会与 2026 年同周号串值。
- 任一预测月都能定位到主图/库存/销毛对应周；任一预测周都能返回所属月；月周边界有实际日期说明。
- 12 个 SI 月都必须逐一确认，参考预览与人工确认状态明确分离；四个连续三月组不会隐藏未确认月份。
- 统一模拟样本下，自动学习输入窗、参考映射和促销日历可展示；数据不足时显示「无法学习 + 缺少范围」，回退规则显式可见。
- 价格→销量关系未定期间，所有价格调整都显示「暂不联动销量」；不得出现隐式弹性或成本自动换算销量。

### B.4 数据契约与核心功能算法

#### B.4.1 统一日历与类型

```ts
type ISODate = string;       // YYYY-MM-DD
type MonthKey = string;      // YYYY-MM
type WeekId = string;        // YYYYWww，跨年后仍唯一

type WeekRange = {
  startWeekId: WeekId;
  endWeekId: WeekId;
};

type CalendarWeek = {
  id: WeekId;
  date: ISODate;             // 周一
  endDate: ISODate;          // 周日
  weekNumber: number;        // 只用于周号读数，不作唯一键
  monthKey: MonthKey;        // 按周一日期归属
  index: number;             // 全部历史 + 预测周的绝对序位
  forecastIndex: number | null;
  status: 'actual' | 'forecast';
};

type ForecastMonth = {
  key: MonthKey;
  weekIds: WeekId[];
  forecastWeekIds: WeekId[]; // SI 只分摊到预测周
};

type ForecastCalendar = {
  historyThrough: WeekId;    // 2026W44
  horizonStart: MonthKey;    // 2026-11
  horizonEnd: MonthKey;      // 2027-10
  weeks: CalendarWeek[];
  forecastWeeks: CalendarWeek[];
  forecastMonths: ForecastMonth[];
  weekById: Map<WeekId, CalendarWeek>;
  monthByKey: Map<MonthKey, ForecastMonth>;
};

function buildForecastCalendar(input: {
  historyStart: ISODate;
  historyThrough: WeekId;
  horizonStart: MonthKey;
  horizonEnd: MonthKey;
}): ForecastCalendar;

function durationOfWeekRange(
  calendar: ForecastCalendar,
  range: WeekRange,
): number | null; // 同一日历且起≤止时，endIndex − startIndex + 1
```

日历规则：

1. 周统一周一开始、周日结束；`weekId` 由完整日期所属 ISO 周年和周号生成，禁止用 `2026` 常量拼接所有周。
2. `historyThrough = 2026W44`，首个预测周是其下一周；2026-11 中已发生周仍标实际，预测汇总只累计 `forecastIndex != null` 的周。
3. `forecastMonths` 必须恰好为 `2026-11 … 2027-10` 12 项；每月同时保留全部周与预测周，避免 SI 把月总量分摊到已发生周。
4. 所有范围都按绝对 `index` 校验，跨年不比较裸 `weekNumber`；起止不存在或起晚于止返回 `null`，UI 显示错误。
5. 视图窗口只引用日历子集，不裁剪学习样本、大盘计算或库存递推。
