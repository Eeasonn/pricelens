## 一、两条总纲（本方案的地基，所有设计由此推导）

**总纲一：锁量只是约束，不是功能降级。**
锁量影响的是能 Sell-in 的总量上限，仅此而已。SO 滚动预测、量价分析、定价推演一律按完整能力设计：预测总量、预测节奏、回答「卖得动多少」这个问题的功能，不因锁量而缩水。未锁量产品、已锁量产品、不锁量产品共用同一套功能，已锁量的只是在界面上多一条「供给上限」参照线和一个「缺口」视图（见 §三）。上市首月未锁量时，预测直接服务「定多少量、怎么定价」；锁量之后，同一预测转为「缺口管理」——预测与锁量的差值才是决策输入。引擎不变，用途延伸。

**总纲二：慢迭代 + 信任优先。**
每期只做一个业务闭环，不追求一步到位的智能决策。所有测算必须是「玻璃盒」：依据可展开、假设可修改、过程可追溯、人工可覆盖；界面上不出现无出处的结论数字。信任有渐进路径：**先展示（不预测）→ 再推演（用户给假设才动）→ 后参考（建议可拒绝）→ 参数沉淀（复盘证据攒出来）**——平台先当「讲得清的看板」，再当「算得出的工作台」，最后才谈「有积累的参照系」。

## 二、产品定位与版本衔接

- **版本叙事沿用**：1.0 价格分析｜2.0 量价经营分析｜3.0 产品全生命周期管理。本方案是 3.0 的产品化路线，同时承接 UX 需求文档二阶段 backlog（what-if 预演 / margin 瀑布）与会议纪要的近期方向。
- **一句话定位**：把一线手工维护的表格、公式、倍数与汇报材料搬到线上，做成**可推演、可追溯、可复盘**的定价与动态经营工作台。系统提供参照与测算，判断永远由业务人员作出。
- **与现有六大类的关系**：现有能力（数据底座/走势监测/对标比价/促销档期/量价联动/异动预警）是数据与监测层，本方案在其上叠加三层——**复盘层（发生了什么、为什么）→ 推演层（如果……会怎样）→ 计划层（接下来怎么干）**。

```
数据底座（已有：24 国价格/档期/量价/预警）
   │
复盘层 ── 调价事件库·同期对比·大促倍数库        「发生了什么、为什么」
   │
监控层 ── 周度价量偏差·DOS/库存健康（已有预警扩展）「偏离计划了吗」
   │
推演层 ── 上市定价多方案·促销方案测算            「如果……会怎样」
   │
计划层 ── SO 滚动预测·供需缺口·月度滚动          「接下来怎么干」
   ═══════════════════════════════════════
约束带：锁量/供应节奏/渠道库存 —— 横跨监控与计划层，
        只做上限对照与提醒，不改变预测引擎本身
```

## 三、锁量的建模方式（把「不过多影响计划功能」落成结构）

### 3.1 双层模型：需求层 × 供给层

- **需求层（SO 滚动预测）**：输入大盘、上一代表现、价格、激励、可得性，输出未来周/月的 SO 总量与节奏。与锁量完全无关，永远全量输出。断货周按 CENSORED 口径标记，不混入正常预测（沿用 3.0 缺失五分规则）。
- **供给层**：锁量（Sell-in 总量上限）+ 供应节奏 + 渠道库存（INV/DOS）。供给层只做三件事：画上限线、算缺口、出健康度信号。

### 3.2 缺口 = 决策输入（三种情形）

| 情形 | 信号 | 经营动作方向 |
|---|---|---|
| 预测持续高于锁量 | 累计达成超前、缺货风险抬升 | 申请追加量、价格上探、控 Sell-in 节奏 |
| 预测低于锁量 | 达成落后、DOS 抬升 | 促销/激励/降价加速、Sell-in 减速、缩短清库周期 |
| 基本匹配 | 偏差在带内 | 按既定节奏，既定量下改善销毛 |

缺口视图一句话讲清：**「按现在这个卖法，锁定的量会在第几周卖完/卖不完，差多少」**。

### 3.3 一表两用

未锁量产品同一界面，只是少一条上限线——功能零变化、无模式切换。这从结构上保证「锁量不锁量不影响产品计划功能」。

### 3.4 DOS 参考线做成可配置项

90 天上限、年末开门红前 50 天以下等属于讨论中的管理规则与案例，不做统一硬指标：按国家×产品线配置参考线+越线提醒，规则来源在设置里可查。

## 四、信任设计规范（界面宪法）

> 原则：系统输出的每一个数字，业务人员都能回答三个问题——**数从哪来、怎么算出来的、和历史对得上吗**。回答不了的数字不上界面。

### 4.1 三态视觉语法（全站统一）

| 数据形态 | 视觉 | 说明 |
|---|---|---|
| 实际值 Actual | 实线+圆点 | 已发生 |
| 计划/目标 Plan | 阶梯线 | 已确认的计划量、锁量上限 |
| 预测/测算 Forecast | 虚线+浅色区间带 | 参照区间，非单点答案 |

估计值与模拟值一律琥珀色标注（EST/模拟徽章，生命周期 Demo 已有），数据截点（as_of）常显。**实线到哪、虚线从哪开始，一眼可辨，绝不混合。**

### 4.2 依据四件套（任何测算数字点开必有）

① **数据来源**：哪张表、什么口径、截至哪一周；② **历史参照案例**：参数取自哪几次历史事件，可点进复盘库看原文；③ **假设参数**：本次用了哪些假设、当前值多少、可改；④ **计算过程**：公式逐步展开，中间量可见（例：放大倍数 1.5× → 上一代黑五 3 次实测，区间 1.3–1.8，样本量 3）。

### 4.3 假设显式化与情景版本

所有假设集中在假设面板一列展示；修改任何假设生成**新的情景版本**，不覆盖原方案（沿用 3.0 版本分类：Actual / Plan / Baseline / Scenario / Approved / Execution）。多套定价方案=多个并行情景，可对比、可留档、可回看。

### 4.4 参照优先于结论

推演与预测的输出形态是**区间+参照案例**（「参照上一代同期与历史 3 次调价，销量变化预计在 +10%–+22% 区间，中值 15%」），不给单点「答案」。界面文案只出现业务语义（历史参照/同期对比/测算），不出现智能/AI/模型推荐等机器口吻，不出现工程词（沿用两条既有文案铁律）。

### 4.5 偏差公开

周度预测 vs 实际的偏差台账对所有用户可见；平台参考与纯人工经验的历史对照同样留存——用数据回答「这套参照到底准不准」，比任何承诺都有说服力。

### 4.6 人工可覆盖且留痕

参考结论配三键：采纳/修改/拒绝，动作写入状态流（待评估→已审批→已执行→已复盘）。人工修正永远优先于系统参照，且修正本身成为新的复盘素材。

### 4.7 各期信任边界（防止冒进）

| 期 | 平台角色 | 预测能力边界 |
|---|---|---|
| 一期 | 讲得清的看板 | 零预测、零建议，只有事实与复盘 |
| 二期 | 算得出的工作台 | 只有用户给假设才推演，结果=情景版本 |
| 三期 | 有参照的经营台 | 给参考建议，全部可拒绝、偏差公开 |
| 四期 | 有积累的参照系 | 参数从复盘证据沉淀，仍是区间+案例形态 |

## 五、功能模块规划（五个模块）

> 统一格式：解决什么 / 输入 / 输出 / 界面要点 / 信任机制 / 数据依赖。

### M1 调价事件复盘库 ——「每次调价之后发生了什么」

- **解决什么**：量价弹性当前最依赖经验、最缺数据支撑；一线答不出「上次降 8% 之后销量到底怎么变」，汇报只能靠主观估计。
- **输入**：全价格史（含上一代与二级市场）、档期日历、销量。
- **输出**：事件卡=调价时间/幅度/当时档期与竞品动作背景/**前后销量对比（双口径）**/样本说明。双口径：朴素对比（调价前后 N 周销量变化，如实呈现）+ 参照基线对比（扣掉上一代同期走势、季节基准、未调价对照国后的增量），两者并列展示、口径分别标注。
- **界面要点**：挂在价格走势图事件层（编号锚点+图下事件行已有，扩展为可点开的完整事件卡）；支持按国家/产品/幅度区间/事件类型筛选，形成「同类调价案例集」。
- **信任机制**：双口径并列是纪律——只有朴素对比会把大促季的量全记在降价头上；每张卡标注基线怎么取、样本几次、置信度高低。
- **数据依赖**：已有价格史+档期；销量按国×周接入即可起步。

### M2 同期对比与节奏参照 ——「上一代同期是怎么走的」

- **解决什么**：一线预测的核心方法就是「上一代同期×变化幅度」，但翻历史全靠手工；纪要明确要求按需叠加、不强行给结论。
- **输入**：上一代/历史同档产品的 SO、价格、调价节点、大促档期。
- **输出**：主图按上市后周龄对齐叠加上一代曲线（价格线+销量线），调价节点与档期随线标注；生命周期节奏曲线（首销爬坡→平稳→衰退→清库的形状参照）。
- **界面要点**：叠加开关默认关，用户按需打开（对齐纪要「由用户自行观察选用」）；线形用虚线+浅色，与实际值区分。
- **信任机制**：叠加只呈现、不评价；提供「同期差异幅度」读数（本代较上一代同期 −12%）作为推演层的手工输入素材。
- **数据依赖**：上一代 SO/价格全史（六块数据之③④）。

### M3 销毛联动 ——「这套促销方案到底赚不赚」

- **解决什么**：成本、促销投入、价格、销量分散在多张表，一线无法快速校验促销方案合理性；领导要看的是销毛，不是价。
- **输入**：成本（月度）、即时激励投入、价格、销量。
- **输出**：现有图表加成本/销毛列与「成交价−成本」销毛带（UX 文档二阶段 backlog 合流）；销毛变化瀑布拆解（价×量×结构×投入，方案审批前的测算件）；促销方案投入产出测算（投入 vs 预估增量×单台销毛，含大促后回吐扣减项）。
- **界面要点**：销毛数据随成本月度刷新，版本化展示（本月成本版/上月成本版）；瀑布图每个分段可点开看计算。
- **信任机制**：成本口径与版本常显；回吐扣减显式列为负项，不藏在总数里。
- **数据依赖**：成本录入（争取中）、激励投入（颗粒度到 SKU×国×周最佳）。

### M4 上市定价推演（玻璃盒 what-if）——「成本涨了，这个价怎么定」

- **解决什么**：纪要明确的近期第一场景——成本上涨周期下如何定价；现状是多套方案靠手工 Excel 各算各的，口径不统一、依据难追溯。
- **输入（四类，对齐纪要）**：大盘判断（趋势+预估）、成本预测（产品线/产业链提供，平台不替代）、上一代表现（M2 直接喂入）、竞品价格判断（上市节点竞品现价+临近换代的下一代价格预估——**历代上市价阶梯可直接从现有价格史产出，作为「下一代竞品会定多少」的参照证据**）。
- **输出**：多套定价方案（基准/进取/稳健起手，可增删），每套=价格×预估销量×销毛的联动测算+关键假设清单；方案间对比表（一屏三列比较，供领导决策）。
- **界面要点**：假设面板全显式（大盘增速、成本涨幅、弹性参照、竞品价格），改假设即时重算为新情景；推演逻辑=一线公式的在线化（上一代同期×变化幅度×事件倍数），**公式可见、参数可改**，不引入黑盒拟合。
- **信任机制**：每个方案标注「销量预估的依据链」——用了哪个历史案例、哪个倍数、谁确认的假设（4.2 四件套全量适用）；方案审批走状态流。
- **数据依赖**：M1 复盘库（弹性参照）+M2（同期）+M3（销毛）+竞品价格阶梯（已有）。

### M5 SO 滚动预测与供需缺口 ——「按现在这个卖法，量够不够、差多少」

- **解决什么**：纪要的周监控/月滚动节奏手工维持；锁量后的经营重心（既定量下改善利润、控 Sell-in、缩清库）缺一个统一的缺口视图。
- **输入**：M1–M4 全部产出+锁量与供应节奏+INV/DOS。
- **引擎（一期先手工、逐步半自动）**：SO(t) = 上一代同期节奏 × 相对变化幅度 × 事件倍数（大促/调价/激励），参数表显式可改；每周实际回灌更新累计达成与偏差，每月成本刷新触发销毛与预测重算。自动拟合参数（弹性池化等）四期前不进。
- **输出**：主图=SO 实际+预测区间带+锁量上限线+供应虚线（生命周期 Demo 线框 A 的产品化）；缺口卡（三情形判定+差距量+预计达成周）；DOS 参考线与越线提醒；偏差台账+FVA 对照（平台参考 vs 纯人工的历史准确度）。
- **界面要点**：周监控只报偏差不动预测，月滚动才重算；偏差超带触发「建议关注」并链接 M1 找同类历史处置案例——建议永远带案例、可拒绝。
- **信任机制**：4.5 偏差公开+4.6 三键留痕全量适用；预测线永为虚线带，锁量线为阶梯实线。
- **数据依赖**：SO 持续滚动接入、锁量值录入、INV/DOS。

## 六、迭代路线（四期，每期一个闭环）

> 慢迭代纪律：每期交付一个业务能独立走通的闭环，验收里**信任机制与功能同权重**；上期没走稳不开下期。

### 一期 · 复盘与在线化（近期启动）

- **范围**：M1 朴素版（事件卡+双口径标注）｜M2 同期叠加｜M3 基础（成本列+销毛带）｜大促放大倍数库（国×档期历史倍数+样本量，替代手工翻表）｜周监控 v0（价/量实际 vs 计划的偏差表，只报不推）。
- **业务闭环**：一线周会与月度汇报不再手工制表；「上次调价效果如何」一分钟调出案例。
- **信任里程碑**：界面每个数字可点开出处；零预测零建议。
- **对应纪要后续事项**：3/4/5/8。

### 二期 · 上市定价推演

- **范围**：M4 玻璃盒完整版；成本上涨场景优先打样；三代竞品价格阶梯参照上线。
- **业务闭环**：定价会从「各带各的 Excel」变成同屏多方案对比+依据可查。
- **信任里程碑**：假设面板全显式；改假设即出情景版本；公式过程可展开。
- **对应纪要后续事项**：1/2/7。

### 三期 · 滚动经营

- **范围**：M5 完整版——一线公式引擎在线化、月滚动重算、周偏差监控正式化、锁量约束层与缺口视图、DOS 参考线、FVA 台账；生命周期 Demo 的线框 A 与阶段 KPI 条落为正式页。
- **业务闭环**：周看偏差、月滚预测、缺口驱动动作（降价/激励/控节奏），动作走状态流到复盘。
- **信任里程碑**：偏差台账公开；参考建议全部可拒绝且留痕。
- **对应纪要后续事项**：议题二的完整落地。

### 四期 · 参数沉淀（数据成熟后，不设时间表）

- **范围**：复盘库证据沉淀为弹性参照表（区间+样本量+适用条件）；跨国事件池化扩样本；竞品定量分析视数据可得性再议。
- **纪律**：即便到四期，输出仍是区间+案例形态，不升格为自动决策。

## 七、数据需求与缺口

| 六块数据 | 去向 | 状态 |
|---|---|---|
| ① 档位大盘（季度）+明年预估 | M4 大盘假设、M5 总量锚 | 可供 |
| ② 竞品构成大盘（季度） | M4 竞品价格判断的背景；定量分析后置 | 部分可供（销量不可得） |
| ③ 全价格史含二级市场 | M1/M2/M4；二级市场价做旧机分流与换机锚参照 | 已有（PriceLens 价格史） |
| ④ 上一代 SO/DOS/INV 全史+当前品滚动 | M2/M5 引擎与缺口 | 可供 |
| ⑤ 成本趋势（历史+滚动） | M3/M4/M5 销毛链 | 争取录入中 |
| ⑥ 即时激励投入（历史+滚动） | M1 事件背景、M3 投入产出、M5 倍数参数 | 颗粒度待确认 |

**三个口径需先拍板**：① SO 与 Sell-in 分开接入（SO=消费者销量，Sell-in−SO=渠道填充，是预测转折的领先信号）；② 激励颗粒度目标 SKU×国家×周，月度/区域汇总会明显折损测算精度；③ 成本按月版本化（每月一个成本版本，销毛可回溯口径）。

**明确不做的**：竞品成本测算（不可得）；竞品量价定量归因（粒度频率不足，先做价格参照）；自动改价执行；供应计划本身（平台只做锁量对照与库存健康提醒，不动供应排产）。
