# PriceLens 设计执行交接文档

本文档是 PriceLens 后续 Agent 的执行规范。它把产品、视觉和工程约束转换成可执行的工作步骤。它不是新的 token 表，也不替代代码中的运行时实现；需要查具体数值时，以 `pricelens/src/theme/tokens.ts` 为准。

## 1. 每次 UI 任务的读取顺序

只要任务涉及页面、组件、图表、布局、样式、token、AgentShell、预警或交互，按以下顺序读取：

1. `PRODUCT.md`：确认用户、业务范围、数据状态、证据和 Agent 边界。
2. `pricelens/DESIGN.md`：确认正式视觉语言、组件规则、图表规则和 Do / Don't。
3. `pricelens/src/theme/tokens.ts`：确认当前可用的颜色、字体、字号、间距、圆角、阴影和动效 token。
4. 相关既有组件：优先复用 `PageHeader`、筛选栏、卡片、表格、图表和 AgentShell 的实现。
5. 复杂页面或新入口：读取或新增 `pricelens/.impeccable/surfaces/<surface>.md`，记录该页面的局部决策。

历史 roadshow、录制页、设计提案和截图只用于理解探索过程，不是正式产品的视觉权威。它们不能自动改变正式页面的 token 或交互。

## 2. 产品判断基线

PriceLens 是华为海外终端品牌方使用的价格情报与量价分析工作台。页面必须帮助用户完成这条路径：

```text
发现信号 → 确认范围与口径 → 查看价格 / RRP / 竞品 / 销量 → 回到事实或证据 → 决定下一步动作
```

设计和实现都应保持以下判断：

- 华为产品是主视角；竞品是稳定的比较参照。
- 折后价是主口径；RRP 是参照；Offer 是文本权益，不是价格线。
- `real`、`simulated`、`mixed` 必须用文字、badge、来源或状态说明显式表达，不能只靠颜色。
- 缺采周保持缺失；不插值、不造点。需要表达时间连续性时可以用虚线跨接，但不能伪造数据点。
- 每个派生数字都能回到“输入事实点 → 筛选条件 → 公式 → 舍入 / 币种 → 输出”。
- 结论必须区分事实、计算、可能原因、证据强度和待核查项。相关性不能写成确定因果。
- Agent 默认只读。筛选、订阅、阈值、情景或配置写入都需要预览、用户确认、版本记录和撤销路径。

## 3. 正式视觉语言

PriceLens 是克制、高密度、可扫描、证据优先的企业级工作台。它使用中性表面建立结构，让对齐、间距、权重和证据状态承担层级表达。

### 色彩语义

- 页面使用 `canvasSoft`，卡片和覆盖层使用 `canvas`，菜单或 hover 内衬使用 `canvasSoft2`。
- `hairline` 是默认 1px 分隔线；`ink` 用于主要文字和主操作；`body` / `mute` 用于次级和元数据。
- 蓝色只用于链接、选中、焦点和有利比较语义。
- 琥珀用于 Offer、混合数据和需要关注的状态；对应文字使用 `warningInk`。
- 红色用于错误或“华为相对更贵”的比较语义。
- 品牌图表颜色是独立词汇：华为保持最强视觉层级，竞品保持跨页面稳定颜色。
- 正式产品壳不引入渐变、发光、玻璃效果或 AI 专属紫色。

### 字体与数字

- UI、中文文案、图表标签和价格使用 Inter-first 系统字体栈。
- 技术标识（周 ID、数据版本、fingerprint、批次 ID）使用 Geist Mono 或等宽字体。
- 默认层级是 20px 标题、16px 正文、14px 控件 / 表格、12px 元数据。
- 对齐比较数字时使用 tabular numerals；货币、正负号和单位保持可见。
- 不增加第二套 display 字体，不用 tracked uppercase 代替层级。

### 间距、形状和深度

- 使用 4px 间距节奏；常用值为 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px。
- 控件、输入框、chip 使用 6px；卡片使用 8px；弹窗使用 12px；pill 只用于紧凑 badge、标签和状态。
- 系统以平面为主：卡片通常使用 L1 阴影，菜单和弹窗可使用 L2 / L5。
- 动效使用 160ms 反馈、240ms 模式切换、320ms 场景交接；`prefers-reduced-motion` 下保留状态变化但移除位移和分阶段运动。

## 4. 页面和组件执行规则

### 页面壳与筛选

- 复用 `PageHeader`、共享筛选栏和既有控件的高度、边框、focus、selected 状态。
- 筛选栏回答“看什么数据”；图表控件回答“如何看这组数据”。不要把两种状态混在一个不可解释的控件里。
- 桌面密度是主要目标；窄屏应通过局部滚动保留表头和关键值，不能裁掉关键内容。

### 卡片、表格和证据

- 新卡片必须表达清晰分组或交互，不得只为增加丰富感而套 card-within-card。
- 表格使用 muted header、hairline 行规则、对齐的数字列和局部横向滚动。
- 证据通过来源、采集时间、覆盖范围、事实行、快照或商品链接呈现；没有快照时显示“暂无快照”。
- 重要图表信息必须有文字摘要或表格替代。

### 图表

- 价格线是主层；折后价是主系列；RRP 是细的参照系列。
- 促销带和事件标注是可选层，必须有明确控制和解释。
- Offer 不画成价格线，用琥珀图标、标签或 popover 表达。
- 华为线使用稳定品牌色和更强线宽；竞品保持可读但降低存在感。
- 长解释下沉到摘要、事件行、tooltip 或详情卡；不要把图表变成大段说明文字。

### AgentShell 与预警

- Agent 与看板共用 token、卡片、hairline、圆角和等宽数字。
- Agent 回复固定为：结论 → 事实 → 计算 / 规则 → 判断边界 → 动作。
- 用户消息可以右对齐墨色气泡；Agent 消息使用结论文字和结构化白卡，不创建第二套聊天视觉。
- 预警必须显示触发事件、规则 / 阈值、前后值、数据状态和证据状态。

## 5. 实现步骤

### Step 1：确定范围和权威

写下本次变更涉及的页面、数据口径、用户动作和证据状态。确认它是正式产品面，还是历史 / 探索面。

完成条件：能指出本次变更的正式入口、主用户任务和数据状态；没有把历史素材当成设计权威。

### Step 2：寻找可复用的 token 和组件

先查 `src/theme/tokens.ts` 与既有组件。需要新颜色、字号、圆角、阴影或动效时，先判断是否已有语义 token 可复用；确实新增时，同时更新 token、`DESIGN.md` 和必要的局部 surface brief。

完成条件：所有新增视觉值都有语义名称和来源；组件中没有为了方便而散落的新硬编码。

### Step 3：写局部设计决策

复杂页面、全新图表或新增 Agent 卡片，在 `pricelens/.impeccable/surfaces/` 建立简短的页面决策文件。至少写清楚：目标、范围、信息层级、状态语义、证据呈现、响应式行为和例外。

完成条件：另一位 Agent 可以只读该文件和 `DESIGN.md`，复现页面的视觉和交互意图。

### Step 4：实现并保持数据语义

保持华为主视角、竞品参照、数据状态显式、缺采不造点和 Agent 只读优先。所有重要数值提供来源、口径或计算路径。

完成条件：页面视觉变化没有改变业务口径；状态和方向不依赖颜色单独传达；键盘 focus 和可访问名称仍然存在。

### Step 5：执行检查

从仓库根目录执行：

```bash
npm --prefix pricelens run design:check
npm --prefix pricelens run design:lint
npm --prefix pricelens run typecheck
```

涉及数据、交互、测试或离线单文件时，再执行：

```bash
npm --prefix pricelens run check
```

需要查看视觉漂移时执行：

```bash
npm --prefix pricelens run design:detect
```

Detector 的 advisory 是待治理线索；只有 primary 或契约 / lint / typecheck 失败才阻断交接。历史 roadshow 和录制目录已在配置中排除，不得通过扩大排除范围来隐藏正式页面漂移。

完成条件：适用检查全部通过；如果保留 advisory，交接说明中列出其范围和是否属于本次变更。

## 6. 提交前交接清单

- [ ] 已读 `PRODUCT.md`、`pricelens/DESIGN.md` 和相关 surface brief。
- [ ] 已确认正式产品入口，没有把历史 roadshow / recording 当作基线。
- [ ] 新视觉值已进入 `src/theme/tokens.ts`，并在设计文档中有语义说明。
- [ ] 华为主视角、竞品稳定颜色、Offer / warning / error 语义保持一致。
- [ ] `real` / `simulated` / `mixed`、缺采、证据和计算边界可见。
- [ ] Agent 回复仍按结论、事实、计算 / 规则、边界、动作组织。
- [ ] 已运行 `design:check`、`design:lint`、`typecheck`；适用时运行完整 `check`。
- [ ] 已说明 detector advisory、数据假设、未覆盖状态和任何有意例外。
- [ ] 若生成离线交付，已确认 `npm run build` 同步根目录 `PriceLens.html`。

## 7. 权威优先级

发生冲突时按以下顺序处理：

1. 用户当前明确决策；
2. `PriceLens-产品说明.md` 的统一业务口径；
3. 当前实现、测试和数据契约；
4. `PRODUCT.md` 的产品上下文；
5. `pricelens/DESIGN.md` 的视觉契约；
6. 历史原型、roadshow、录制和提案文档。

如果无法在这些来源中判断，先写出一个局部 surface brief，明确假设和需要确认的分歧，再实现；不要用个人偏好静默替换系统规则。
