> 为前后端分离双模式、SQLite 匹配小表原则入纲）。配套：`底表结构与真实数据接入
> 契约-2026-11-17.md`、`内部系统数据准备要求-2026-11-18.md`、
> **`PriceLens-部署架构方案-前后端分离-2026-11-18.md`（部署/工程侧总纲）**。

## 0. 总架构：两源 + 三层 + 一配置面

```
┌─ 源系统（内部）──────────────┐      ┌─ PriceLens 配置面（业务维护）──────────────┐
│ A. 街价 offer 抓取底表 (ODS-A) │      │ C1 派生规则表：系列规则/型号别名/对标矩阵/  │
│ B. PSI 周销量底表   (ODS-B)   │      │    分档阶梯/大促档期                        │
└──────────┬───────────┘      │ C2 用户功能配置：市场采集规则/默认店铺/     │
           │ 原样导出（不改值）        │    上一代关系/异常规则/人工裁定             │
           ▼                          │ C3 解析字典：国家/平台/店铺类型/品类        │
┌─ PriceLens 应用内归一层 ──────────────────────────────────────────────────┐
│ DWD 明细清洗：列名归一→拆列→型号正名→去重→汇率自愈→单位错位修正           │
│ DIM 维表构建：产品/渠道/时间/汇率/地区 + 派生维度(系列/分档/cat)          │
│ 事实装载：价格事实(列式包) + 销量事实                                     │
└──────────────────────────────────────────────────────────────────────────┘
```

**分层职责**（IT 落地时建议照此建表）：
- **ODS（源样层）**：内部系统原样产出，不改值不改名——PriceLens 的 v3 数据包
  `offers[] / sales[]` 即此层（§1.1、§2.1）。
- **DWD（明细规范层）**：PriceLens 归一引擎（前端 `offerIngest` / 服务器
  `server/ingest_pack.py` 双实现，逐字对齐契约）在导入时完成；IT 自建数仓时
  可参照 §1.2/§2.2 的规则在数仓层先行落表。
- **DIM（维表层）**：导入时构建（§1.5）；产品/渠道/时间/汇率/地区五张。
- **CFG（配置面）**：业务侧 Excel 维护、PriceLens「导入配置」写入（§3）；规则类
  不编译进应用（零内置），配置表是唯一规则源。
- **匹配小表原则**（2026-11-18 Eason 拍板）：原表上**不加列**——所有「我们加的」
  派生内容（型号正名/系列归属/规格拆列/档位等）以**独立匹配小表**存在、键挂接，
  「原表有的」与「我们加的」一眼可分。服务器 SQLite 已照此物理化：`ods_*` 原样层
  零派生列 + `map_model/map_sku/map_spec_split/map_tier/map_alias` 匹配小表
  （见部署架构方案 §3）。

**部署形态（2026-11-18 前后端分离拍板）**：双模式并存——**服务器模式（内部主力）**
= 本机 Python 服务器（纯标准库）+ SQLite 承载数据，117MB 级全量包直导；
**单文件模式（兜底）** = 双击 PriceLens.html 走浏览器 IndexedDB（小数据/外网）。
数据流与 API 契约见《PriceLens-部署架构方案-前后端分离-2026-11-18.md》。

## 1. 街价 offer 抓取底表（ODS-A）+ 拓展维度

### 1.1 ODS-A：`stg_offer_capture`（源样层，一行 = 一条采集明细）

> 对应 PriceLens 数据包 v3 的 `offers[]`。**字段名保持源表中文原样**（双语表头与
> 同义列名由应用自适应映射，见 §1.2）；值不改不拆。以下 22 列为解析消费列，
> 源表若有额外列原样保留（应用不消费，作为扩展位）。

| # | 列名（规范名） | 类型 | 必备 | 说明 |
|---|---|---|---|---|
| 1 | 时间周期 | date / string | ★ | 采集日期或周号（`20261021` / `2026043` / `202643` 均收） |
| 2 | 品类 | string | ★ | 手机/平板/穿戴/音频/iot/pc（中英文同收） |
| 3 | 品牌 | string | ★ | 源表原文（`HUAWEI` = 我司） |
| 4 | 型号 | string | ★ | 型号名原文（含品牌词也收，正名时自动剥） |
| 5 | 型号规格 | string | — | 原始规格整串 `12+512 GB Black`；**不要预拆** |
| 5a | Category1 / Category2 / info | string | — | 已按业务规格拆列的形态（三列齐 = 拆列形态，跳过自动拆） |
| 5b | tech_date | string | — | 拆列形态的周期列（`YYYY0WW`） |
| 6 | 平台 | string | ★ | `DNS`/`OZON`/`MVM`…（别名归并见 C3-2） |
| 7 | 国家/地区 | string | ★ | 中文名/英文/国家码（映射见 C3-1） |
| 8 | 店铺类型 | string | ★ | 归一到 1P / 3P / 独立站（映射见 C3-3） |
| 9 | 店铺名称 | string | — | 具体卖家店铺（渠道内区分粒度） |
| 10 | 显示店铺名称 | string | — | 渠道展示名（缺省用 `平台 店铺类型` 兜底） |
| 11 | 平台建议零售价-本币 | number | ○ | RRP / 划线价（本币） |
| 12 | 平台成交价-本币 | number | ○ | 折后价（本币） |
| 13 | 货币 | string | ★ | 币种码（RUB/PLN/EUR…） |
| 14 | 汇率 | number | ★ | **1 USD = N 本币**；倒挂行自动自愈 |
| 15 | 是否组合销售 | string | — | Y/N/TRUE/是 |
| 16 | 分期付款 | string | — | 分期政策原文（进明细表） |
| 17 | 促销政策 | string | — | 促销原文（进明细表） |
| 18 | 平台显示折扣率 | number/string | — | `-15%` / `-0.15` 均收 → 负小数 |
| 19 | 平台实际折扣率 | number/string | — | 同上 |
| 20 | 网址链接 | string | — | 取证链接 |
| 21 | 截图命名 | string | — | 取证截图 |
| 22 | 采集时间 | datetime | ○ | 去重排序键（同键同刻保留最低价） |

必备 = ★；○ 强烈建议（缺失降级）；其余可缺省。**唯一键（去重口径）**：
`周 × SKU × 国家 × 平台 × 店铺类型 × 店铺名称`，同键同采集时间保留最低价。

### 1.2 DWD：清洗与拆列规则（导入时自动执行；数仓自建时照此实现）

| 步骤 | 规则 | 产出 |
|---|---|---|
| 列名归一 | 双语表头取中文段、剥括注；同义列映射（商品型号→型号 等 13 组） | 规范列名 |
| 周期规范 | 日期 → 所在 ISO 周周三锚 `YYYYWW`；`YYYY0WW`→`YYYYWW` | `week_id`、`week_wed_date` |
| 国家规范 | 中文名/英文/码 → 两位国家码（29 国字典 C3-1） | `country_code` |
| 平台/店铺类型 | 平台别名归并（`mvm→Mvideo` 等）；店铺类型 → 1P/3P/独立站 | `platform`、`store_type` |
| **拆列（核心拓展）** | phone：`数字+数字 单位 颜色` → 存储+颜色；tablet：`屏幕/联网/存储/特殊屏` → 屏幕+存储（联网并入颜色）；wearable：`表盘mm 联网 材质 颜色` → 表盘+变体；audio：只留颜色 | `romram`（展示）、`rom_key`、`color`、`color_key` |
| 穿戴表盘升级 | 同型号全局 ≥2 尺寸 → 表盘升维度1；唯一尺寸 → 剥词不作维度（GT 6 Pro 口径）；「大/小」脏行按国家覆盖删或清洗 | `cat1` |
| 型号正名 | 同 (品牌， 归一键) 取最高频原文、剥前缀品牌词 | `model_name` |
| id 拼装 | `model_id = own|cmp-品牌slug-型号slug`；`sku_id = model_id__rom_key__color_key`（键含塌缩前旧值，稳定契约） | `model_id`、`sku_id` |
| 去重 | 唯一键内保同刻最低价、有价行优先 | 事实行 |
| 汇率自愈 | 币种中位数自校验倒挂取倒数；(国家×周)→币种中位数补缺 | `fx` |
| 价格折算 | `usd = 本币 / 行内汇率`；单位错位修正（>8× 且 ÷100 落 0.5–2× → ÷100；对称低侧）；>20,000 USD 剔除 | `rrp_usd`、`price_usd` |

### 1.3 拓展维度（计划；DWD 产出，DIM 承载）

| 维度 | 字段 | 口径 | 用途 |
|---|---|---|---|
| 维度1 | `cat1` | phone/tablet=存储规范形（`12+512 GB`）；wearable=表盘（≥2 尺寸型号）；audio=null | 销量 join 键、第四列 |
| 维度2 | `cat2` | tablet=屏幕（`11.5"`）；其余 null | 销量 join 键、第四列 |
| 次级信息 | `info`/`color` | 颜色、联网方式、特殊屏、材质等 | 版本胶囊（不进销量键） |
| **品牌系列** | `series` | 配置表 C1-1 规则派生；未命中兜底：我司=型号名首词、竞品=型号名本身 | 产品树第三列（仅呈现层，不进匹配键） |
| 价格档位 | `tier_code` / `tier_by_country` | 配置表 C1-4 阶梯 × 参考价（rrp 中位数，缺则成交价中位）；分国中位价落档 | 档位筛选、便宜对便宜配对 |
| 参考价 | `ref_price_usd` | model 级 rrp 中位数 combine 成交价中位数 | 档位、定位 |
| 生命周期 | `launch_date` / `first_week` / `last_week` / `eol_date` / `countries` | 事实聚合（首末周三/周号/国家集合） | 树排序、时间轴、国家过滤 |
| 我司标识 | `is_own` | 品牌 = HUAWEI | 全局我司/竞品分流 |
| 行业 | `industry` | 品类列映射（C3-4） | 产业页签 |

### 1.4 事实表：`fact_price_weekly`（一行 = 周 × SKU × 国家 × 渠道 × 店铺）

19 字段：`week_id, sku_id, country_code, channel_id, seller, rrp_local, price_local,
fx, rrp_usd, price_usd, discount_display, discount_actual, bundle, installment,
promo_text, url, screenshot, crawled_at, crawl_status`。
（`channel_id = 国家:平台slug:店铺类型`，店铺区分保留在 `seller`。）

### 1.5 维表五张（DIM，导入时构建）

| 表 | 粒度 | 关键字段 |
|---|---|---|
| `dim_product` | 一行 = SKU（型号×配置×颜色） | §1.3 全部维度 + model_name/brand/romram/color/brand_inline |
| `dim_channel` | 一行 = 国家×平台×店铺类型 | `channel_id`、display_name、shops（店铺数） |

## 2. PSI 周销量底表（ODS-B）+ 拓展维度

### 2.1 ODS-B：`stg_psi_weekly_sales`（源样层，一行 = Product×维度×周期）

> 对应数据包 `sales[]`，六字段（字段名固定英文，值原样）：

| 字段 | 来源列 | 类型 | 说明 |
|---|---|---|---|
| `country` | Management Country/Region | string | 国家码/中文名/英文名均收 |
| `product` | Product | string | 型号名原文；解析失败挂 `salesProductAliases` |
| `category1` | Category1 | string \| null | 手机/平板=存储；穿戴=表盘；音频=null |
| `category2` | Category2 | string \| null | 平板=屏幕（裸数字按英寸收）；其余=null |
| `periodId` | PeriodID | string | **YYYY0WW**（`2026043`）；兼容 YYYYWW |
| `qty` | QTY | number | 台；≤0/非法行计入 skipped |

**粒度**：QTY 按 `Product + Category1 + Category2 + 国家 + PeriodID` 汇总；
同键多行自动求和；颜色等次级信息**不进**销量。

### 2.2 规范化与 join（导入时自动）

周期/国家/维度归一（与 §1.2 同一套字典）；型号解析 = 别名表 → 归一键 →
**我司优先**（同名撞竞品归我司）；join 键：
`(country, product, category1, category2, week) → (model_id, cat1, cat2, week_id)`。
**口径**：型号×国家存在任何销量行 → 该型号该国整模型走真实销量（同维度不同
info 共享同一销量，不摊分）；无销量行的型号回落估算（不混口径）。

### 2.3 事实表：`fact_sales_weekly`（一行 = 周 × 型号 × 国家 × cat1 × cat2）

`week_id, country_code, model_id, cat1, cat2, qty`。

### 2.4 计划拓展维度（PSI 侧建议路线；**2026-11-18 Eason 拍板：暂不实施**，仅留方向备忘）

| 拓展 | 字段建议 | 说明 |
|---|---|---|
| 销量口径标记 | `source`（psi / estimate） | 行级标注真实/估算（当前模型级隐式） |
| 渠道类型拆分 | `channel_type`（1P/3P/独立站） | PSI 若未来出渠道粒度，join 键加此列 |
| 月度/季度聚合 | `month_id` / `quarter_id` | 由 week 派生，呈现层已有；数仓可物化 |
| 同比环比 | `qty_yoy` / `qty_wow` | 呈现层可算；数仓可选物化 |
| 上市至今累计 | `qty_cum_launch` | 生命周期分析 |

## 3. 配置表全集（面向用户/业务，Excel 维护 → 「导入配置」）

> **零内置原则**（2026-11-18 拍板）：C1/C2 的规则与关系数据不编译进应用，
> 配置表是唯一规则源；空表 = 无规则（诚实降级）。生效时机：**读时** = 改完
> 即生效；**派生时** = 参与数据包导入归一，改后点「用当前配置表重新派生」。

### C1 派生规则表（五张，参与 v3 导入归一）

## 4. 数据流转与交付形态

| 通道 | 内容 | 频率 | 入口 |
|---|---|---|---|
| 数据包（v3 原表模式）· 单文件 | `offers[] + sales[]` 原样行（§1.1/§2.1） | 每周（或增量追加后整体重导） | 配置页「导入数据包」；IndexedDB 持久化，整体置换幂等（≤~50MB） |
| 数据包（v3）· **服务器模式（主力）** | 同上原样行 | 同上 | 同一按钮——前端探测到本机服务器时改走 `POST /api/datapack`（File 流式上传，117MB 级直导；Python 引擎派生 + SQLite 落库，`POST /api/rederive` 重派生） |
| 配置导入 | 配置 xlsx（C1+C2+C3 全部页签，与模板同构） | 随业务变更 | 配置页「导入配置」；本地 localStorage + 服务器模式同时 POST（服务器权威、启动镜像同步） |

| 配置导出 | 当前浏览器全部配置键 | 备份/分发 | 配置页「导出配置」 |

诊断三件套（导入后自检）：数据卡行数与「原表归一」条（剔除/修复明细）、
销量 unmatched 黄条、量带悬停口径标注。
