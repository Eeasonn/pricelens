# PriceLens 推演工作台后续路线图建议

> 日期：2026-11-03  
> 前置计划：`docs/plans/2026-11-03-forecast-workbench-multi-agent-plan.md`  
> 定位：当前修复计划完成后的产品化、真实数据、模型验证与发布路线图；不是当前 WP0–WP7 的范围扩张。

## 1. 核心建议

后续工作不要直接从“修复界面”跳到“接一个更复杂模型”。正确顺序是：

```text
修复当前确定性工作台
→ 完成业务规则与模型语义决策
→ 建立真实数据只读 Adapter
→ 影子运行与回测
→ 校准把握度和库存规则
→ 会话／版本／撤销治理
→ Agent 使用同一快照解释
→ 单国单产业灰度
→ 分批推广
```

每一步都有退出门槛；未通过时停留在当前阶段，不靠增加 UI 功能掩盖数据或模型问题。

## 2. 与当前修复计划的衔接

当前 WP0–WP7 完成后，必须形成以下可交接资产：

- 一套默认结果可复算的确定性模型与测试；
- 一个不含禁词、无教学腔、模拟状态明确的页面；
- 一套可会话恢复、可重置、可复制假设的本地草稿；
- 一组桌面、窄屏、键盘、弹窗和跨页证据；
- 一份与实现一致的 surface brief；
- 一份已知限制清单，明确 fixture、阈值和 AI 基线的真实来源。

只有这些资产齐全，才进入本路线图的 R1。真实数据接入不得与当前卡片并行修复混在同一批变更中。

## 3. 路线图总览

| 阶段 | 核心问题 | 主要交付物 | 退出门槛 |
|---|---|---|---|
| R0 决策与证据准备 | 规则由谁负责、模型声称什么、数据是否可用 | 决策记录、数据盘点、回测协议 | 所有阻塞决策有 owner 和书面结论 |
| R1 只读数据 Adapter | 页面能否在不重写组件的情况下读取真实范围 | Adapter、覆盖报告、空态／异常态 | 同一组件可运行 fixture 与真实数据，数字来源可追溯 |
| R2 影子运行与基线回测 | 模型是否优于简单基线、错误发生在哪里 | 回测报告、误差分层、基线对比 | 不劣于约定基线，且风险有明确分桶 |
| R3 把握度与库存规则校准 | ±8%／±2%、DOS 和降幅是否有依据 | 校准报告、规则版本、维护机制 | 区间有覆盖率证据，阈值经业务签字 |
| R4 工作流与 Agent 同源 | 人工推演能否审计、撤销、分享 | 版本化草稿、撤销、导出、Agent 快照 | 页面、导出与 Agent 数字一致；写入可撤销 |
| R5 单国灰度 | 真实用户是否能完成完整任务 | 试点报告、问题清单、回滚证明 | 核心任务完成，数据／模型／交互无阻断问题 |
| R6 分批推广与运营 | 如何长期维护模型、规则和页面 | 发布批次、监控、复盘节奏 | 每批均有覆盖率、误差、质量和回滚验收 |

## 4. R0｜决策与证据准备

### 4.1 需要书面关闭的决策

| 决策 | 默认建议 | 必须记录的内容 |
|---|---|---|
| DOS 70–90 天与降幅 20%／30% | 在核定前只作演示阈值 | 适用产业、国家差异、业务 owner、维护人、版本、生效日期 |
| AI 初始值来源 | 规则计算称“自动基线”最准确；若保留 AI 标，title 必须说明规则来源 | 是否调用模型、模型／规则版本、输入、生成时间、人工覆盖方式 |
| 上一代参照算法 | 当前比值校正只限演示；真实模型需重新评审 | 对齐方式、缺数处理、是否只调形状、是否调幅度、与大盘是否重复计算 |
| 把握度 ±8%／±2% | 不作为统计区间宣传 | 是人工带宽、经验参数还是校准区间；对应样本与覆盖率 |
| SI 跨月周 | 以业务确认的月归属规则为准 | 周一／周四归属、余数、跨年和月计划版本 |
| 手调与库存上限 | 保留人工优先，但必须显示覆盖了供给截断 | 是否允许超可售、预警级别、导出和 Agent 如何说明 |
| 草稿保存与撤销 | 会话草稿与正式情景分开 | 保存时长、分享范围、版本号、撤销深度、权限 |
| 导出内容 | 文本先行，之后再加 PNG／JSON | 字段清单、数字版本、截图范围、敏感信息边界 |

### 4.2 并行开展的只读工作

这些工作可与当前 WP1–WP7 并行，但不修改工作台运行时代码：

- 数据 owner：盘点真实 SO、SI、渠道库存、全流程库存、成本、价格和周历的来源、粒度、时区、缺失率、更新时间与历史深度。
- 业务 owner：收集 DOS 与库存阈值的历史依据，确认它们是预警规则还是实际供给截断规则。
- 模型 owner：起草回测协议，固定评价窗口、基线、误差指标和分层维度。
- 产品 owner：确认参考品、行业事件、产品事件和人工手调的优先级，避免重复计算。
- QA owner：把当前审计截图转为后续视觉回归基线，记录浏览器、视口和数据版本。

### 4.3 R0 退出条件

- 每项决策都有 owner、结论和生效范围；不能用口头“先这样”替代。
- 数据盘点能回答“有没有真实历史、覆盖多少周、缺失多少、何时更新”。
- 回测协议在看结果之前冻结，避免事后挑选指标。
- 若真实 SO／库存／成本不存在，对应功能继续保持模拟状态，不以推算值冒充已接入事实。

## 5. R1｜真实数据只读 Adapter

### 5.1 目标

只替换输入来源，不重写页面、模型调用方式或卡片组件。页面仍可从 fixture 启动，以便开发、离线演示和回归。

### 5.2 建议数据契约

```ts
type WorkbenchDataStatus = 'real' | 'simulated' | 'mixed';

type WorkbenchDataset = {
  id: string;
  version: string;
  status: WorkbenchDataStatus;
  scope: {
    countryCode: string;
    industry: string;
    productKey: string;
    channelKey: string;
    currency: string;
  };
  coverage: {
    firstWeek: string;
    lastObservedWeek: string;
    forecastThroughWeek: string;
    observedWeeks: number;
    expectedWeeks: number;
    missingWeeks: string[];
  };
  freshness: {
    sourceUpdatedAt: string;
    loadedAt: string;
  };
  source: {
    name: string;
    reference?: string;
  };
  weeks: WorkbenchWeek[];
  market: WorkbenchFixture['market'];
  inventory: WorkbenchFixture['inventory'];
  costVersions: WorkbenchFixture['costVersions'];
  references: WorkbenchFixture['references'];
};
```

真实数据不得为了填满 `WorkbenchFixture` 而虚构字段。无法提供的部分应进入显式 unavailable 状态，而不是用 0、插值或另一国数据补齐。

### 5.3 工作拆分

1. **数据流 Agent**：建立只读查询、字段映射、来源与更新时间。
2. **模型 Agent**：验证不同历史长度、缺周、跨年和零销量的纯函数行为。
3. **页面 Agent**：消费 `status / coverage / freshness / unavailable`，不再新增写死下标。
4. **QA Agent**：同一筛选分别运行 fixture、真实、混合、空数据和异常数据。

### 5.4 页面显示规则

- `real`：显示来源、更新时间和覆盖周。
- `simulated`：保持当前轻量模拟徽标。
- `mixed`：指出哪些卡或字段是模拟，不允许只给页面一个含混的“混合数据”。
- 数据不足：显示可用范围和无法计算的输出；不生成完整预测假象。
- 全局筛选只有在 Adapter 真正重取数据后才启用；否则继续显示固定样本说明。

### 5.5 R1 退出条件

- 切换国家／产品时，同一页面组件无需修改。
- 所有卡片的国家、产品、周、币种、来源和版本一致。
- 缺数不变成 0，周／季度不猜映射，空态与异常可区分。
- fixture 测试和真实 Adapter 契约测试同时通过。
- 本阶段只读，不提供正式情景保存或外部写入。

## 6. R2｜影子运行与基线回测

### 6.1 先建立简单基线

至少保留三组基线，复杂模型必须证明自己比它们更有价值：

1. 上周值延续；
2. 去年同季／同周龄季节基线；
3. 当前“季节 × 趋势”规则基线。

参考品、大盘事件、产品事件和库存修正逐层加入，分别记录增量效果。禁止一次性上线所有修正后再声称整体提升无法归因。

### 6.2 回测设计

- 使用滚动原点回测：每个预测原点只能看到当时已经存在的数据。
- 按国家、产业、生命周期阶段、大促／非大促、缺货／非缺货分层。
- 主图预测、库存可售和成本销毛分别评估，不用一个总误差覆盖所有输出。
- 缺货周的 SO 不能直接当真实需求；需保留删失／供给受限标记。
- 记录预测窗长度，不能把下一周与八周后的误差混为一谈。

### 6.3 指标

| 指标 | 用途 | 注意事项 |
|---|---|---|
| WAPE | 总量误差，适合跨周比较 | 同时报告样本量，避免小样本误导 |
| Bias | 判断持续高估或低估 | 分国家／产业查看方向 |
| 峰值周误差 | 验证大促峰是否失真 | 不被普通周平均掩盖 |
| 库存截断触发率 | 检查库存规则是否过度触发 | 与真实缺货记录对照 |
| 缺数率／覆盖率 | 判断结论可用范围 | 必须在结果旁显性显示 |
| 区间覆盖率 | 仅在校准后使用 | 必须同时报告带宽，防止无限放宽 |

不建议事先写死一个通用“准确率必须达到 X%”。验收应采用：相对基线的改善、关键场景不劣化、误差和业务风险可解释。

### 6.4 影子运行

- 页面默认仍展示现有工作台，影子结果只进入评审报告。
- 每周保存输入版本、模型版本、预测值和后续实际值。
- 对误差最大的周回查输入事实、缺货、事件和人工覆盖。
- 影子期没有足够样本时，不做模型复杂度升级。

### 6.5 R2 退出条件

- 回测协议、代码版本和数据版本可复现。
- 当前模型相对简单基线的优劣已分层量化。
- 任何新增的参考品／事件乘子都有单独增量证据。
- 未通过时保留规则基线，不增加复杂模型或 AI 话术。

## 7. R3｜把握度与库存规则校准

### 7.1 把握度

当前 ±8%／±2% 应被视作界面演示参数。后续有三种合法路径：

1. **经验带宽**：明确写“经验参数”，不声称统计覆盖率；
2. **校准区间**：使用回测残差校准，报告样本、覆盖率和带宽；
3. **取消数值带宽**：证据不足时只显示把握度等级和原因。

不得为了视觉一致强行保留一个无依据的 ±8%。

### 7.2 库存规则

将两个不同问题拆开：

- **健康预警**：DOS 越界、库存骤降，只负责提示和解释；
- **供给截断**：`min(基线 SO, 可售)`，只由可售量决定。

DOS 不合理不应自动等价于砍量。若业务需要额外规则，应另有明确公式、证据和测试，不能让健康文案暗示模型实际执行了不存在的逻辑。

### 7.3 规则治理

每条规则至少记录：

```text
规则 id → 适用国家／产业 → 输入字段 → 阈值／公式 → 版本
→ 业务 owner → 证据 → 生效日期 → 回滚版本
```

### 7.4 R3 退出条件

- 把握度的话术、数值和证据完全一致。
- 库存健康与供给截断不再混为同一因果链。
- 规则变更有版本、测试和回滚。
- 页面、复制文本和 Agent 对阈值来源的表述一致。

## 8. R4｜工作流、导出与 Agent 同源

### 8.1 草稿与正式情景分层

| 层级 | 用途 | 存储与治理 |
|---|---|---|
| 会话草稿 | 当前分析和临时调整 | sessionStorage，可重置，不声称共享 |
| 正式情景 | 会议复核、协作和后续追踪 | 显式保存、预览、确认、版本、撤销 |
| 导出快照 | 固化某一次输入与结果 | 包含数据／模型／规则版本，不继续联动 |

正式情景保存不是恢复“推演纪要层”；它是受控的数据版本能力，页面仍可保持当前五层结构。

### 8.2 导出建议

优先级建议：

1. 复制关键假设文本；
2. 导出 JSON，保留参数、结果、版本和来源；
3. 导出主图＋假设的 PNG／PDF；
4. 需要协作时再考虑分享链接，不在第一期默认开放。

任何导出都必须能从当前 `params + result + dataset.version` 重建，不允许另有手填数字。

### 8.3 Agent 接入原则

Agent 只读取结构化快照：

```ts
type ForecastExplainSnapshot = {
  datasetId: string;
  datasetVersion: string;
  dataStatus: 'real' | 'simulated' | 'mixed';
  modelVersion: string;
  ruleVersions: Record<string, string>;
  params: WorkbenchParams;
  result: WorkbenchResult;
  coverage: WorkbenchDataset['coverage'];
};
```

- Agent 不重算周销、库存、销毛，不维护第二套常数。
- 回答顺序保持：结论 → 事实 → 计算／规则 → 边界 → 下一步。
- 对模拟、混合、缺数、人工覆盖和库存截断必须显性说明。
- Agent 提议修改时先给 diff；用户确认后才写草稿或情景，并提供撤销。
- 页面、导出与 Agent 使用同一模型版本和结果快照。

### 8.4 R4 退出条件

- 任意正式情景可预览、确认、版本化、撤销。
- 页面、文本导出、JSON 和 Agent 的关键数字一致。
- Agent 无法绕过库存、禁词、模拟状态和证据边界。
- 失败、取消和迟到响应不会留下半写入状态。

## 9. R5｜单国单产业灰度

### 9.1 试点建议

沿用当前主要上下文，选择一个数据覆盖最完整的国家／手机产业组合；国家不应仅因现有 fixture 是俄罗斯就自动入选，必须以真实数据覆盖和业务配合度为准。

### 9.2 灰度功能范围

- 默认只读预测；
- 本地草稿、手调原因和关键假设复制；
- 正式情景保存只对试点用户开放；
- Agent 默认解释，不开放自动写入；
- 保留一键回到上一模型／规则版本。

### 9.3 灰度任务脚本

每位试点用户完成同一组任务：

1. 核对当前国家、产品、数据版本和覆盖范围；
2. 解释下一季大盘来源；
3. 修改一个预测周并填写原因；
4. 识别库存上限修正周及原因；
5. 复制关键假设并交给另一位同事复核；
6. 从 Agent 打开解释并核对数字；
7. 撤销一次修改并恢复基准。

### 9.4 灰度指标

- 核心任务是否完成、在哪一步中断；
- 是否能区分实际、预测、模拟、人工覆盖和库存修正；
- 页面／导出／Agent 数字是否一致；
- 是否出现无证据因果或错误范围；
- 控制台、布局、键盘和窄屏问题；
- 模型误差与业务误判案例，而不仅是主观满意度。

### 9.5 回滚演练

灰度期间至少实际演练一次：

```text
关闭新模型 → 回退规则基线
关闭真实 Adapter → 回退只读 fixture／上一数据版本
关闭正式保存 → 保留本地草稿
撤回错误规则版本 → 页面与 Agent 同时使用上一版本
```

### 9.6 R5 退出条件

- 核心任务无阻断缺陷；
- 所有高风险口径问题已关闭；
- 回滚真实执行过，不只是文档承诺；
- 业务 owner 与数据 owner 共同签字后，才进入推广。

## 10. R6｜分批推广与持续运营

### 10.1 推广顺序

按“数据覆盖完整 → 模型回测稳定 → 业务 owner 已就绪”排序，不按国家数量平均铺开。每一批只增加可观察、可回滚的一组国家或产业。

### 10.2 例行监控

- 数据：覆盖率、缺周、来源失败、更新时间、异常值；
- 模型：WAPE、Bias、峰值误差、区间覆盖率、库存截断触发率；
- 交互：弹窗完成率、保存／撤销失败、复制失败、跨页草稿恢复；
- 质量：typecheck、测试、设计门禁、控制台、关键截图；
- 信任：模拟／混合状态缺失、禁词、无来源断言、Agent 与页面数字分叉。

### 10.3 复盘节奏

- 每周：数据质量和高误差周；
- 每个模型／规则版本：回测、业务复核、回滚点；
- 每个推广批次：用户任务、可访问性、窄屏和性能；
- 每次口径变更：同步 PRODUCT、DESIGN、surface brief、测试和导出结构。

## 11. 建议的后续团队分工

| 角色 | 下一步责任 | 不应承担 |
|---|---|---|
| 产品 owner | 决策关闭、试点范围、业务验收 | 直接修改模型公式 |
| 数据 owner | 数据字典、覆盖、来源、更新与质量 | 用插值补齐无法提供的事实 |
| 模型 owner | 基线、回测、校准、误差分层 | 在没有证据时提高复杂度 |
| 前端 owner | Adapter 消费、状态、工作流和视觉一致性 | 在组件内重新计算业务指标 |
| Agent owner | 同源快照、解释、写入确认与撤销 | 维护第二套模型或数字 |
| QA owner | 契约、回归、灰度任务和回滚证据 | 只凭测试全绿批准发布 |
| 集成 owner | 阶段门禁、依赖、发布与回滚 | 并行修改所有工作包而失去归因 |

## 12. 风险登记与触发动作

| 风险 | 触发信号 | 立即动作 |
|---|---|---|
| 真实数据不足以支撑预测 | 覆盖低、缺周多、更新滞后 | 降级为不可计算或有限范围，不造完整曲线 |
| 缺货被当成需求下降 | 低 SO 与低库存同时出现 | 标记供给受限，从普通需求训练中剔除或单独处理 |
| 参考品与大盘重复修正 | 加入参照后误差系统性偏大 | 回到分层回测，关闭重复乘子 |
| 把握度被误解为统计保证 | 用户引用 ±8% 作为承诺 | 暂停数值带宽，补校准或改经验参数话术 |
| 健康预警误触发砍量 | DOS 越界但可售充足却减少预测 | 分离健康与供给截断，回滚错误规则 |
| 页面／Agent 数字分叉 | 同一周出现不同结果 | 停止 Agent 写入，统一结构化快照 |
| 全局筛选半联动 | 范围标签变化但数据不变 | 禁用控件或明确固定样本，不静默接受筛选 |
| 离线版与在线版分叉 | 同版本显示不同结果 | 同源构建、版本校验、关键路由离线回归 |
| 多功能同时上线无法归因 | 误差变化无法定位 | 回退到最近可解释版本，按层重新启用 |

## 13. 不建议现在做的事

- 不先上大模型或复杂机器学习，再寻找数据与回测证据。
- 不为了“生产化”直接隐藏模拟状态或删除所有边界说明。
- 不把全局筛选控件提前接通到一个不响应的数据页。
- 不恢复纪要层、库存分叉线或展示层品牌指标。
- 不在没有校准时把把握度称为统计置信。
- 不让 Agent 重新计算公式或直接写正式情景。
- 不在当前修复阶段同时做大范围真实 Adapter 重构。
- 不把“测试全绿”当作模型正确、业务可发布或灰度成功的充分条件。
