# 竞品 SKU 匹配规则 SOP（PriceLens）

版本：2026-10-20 v1.0（手机/平板/音频定稿；穿戴为提案，待穿戴接口人穷举情形后定稿）
落地位置：`pricelens/scripts/ingest_real.py::pair_configs`（数据接入时自动执行）；人工纠偏/追加走 `pricelens/data/real/overrides.json`。

## 1. 名词与层级

- **型号（model）**：产品名，如 Pura 90s Pro Max / iPhone 17 Pro / Galaxy Tab S11。
- **配置（config）**：影响价格的规格组合。颜色**不属于**配置。
- **SKU**：型号 × 配置 × 颜色。
- **对标（benchmark）**：我司「型号 × 配置」→ 友商代表 SKU 的映射，**按国家维护**。

## 2. 通用前置规则

1. **分国产出**：友商 SKU 在该国无采集数据 → 不产出对标，不跨国借用。
2. **颜色不参与匹配**：对标取该国「采集周覆盖最多的颜色」为代表色，其余颜色在图表次级菜单可切换。
3. **只比裸机价**：赠品/套装不参与友商对比。组合销售（`是否组合销售=Y`）行的取数处理见 §8 待办。
4. **影响价格的配置维度必须进配置**（价格不同的规格必须分开比对）：
   - 手机：RAM + ROM；
   - 平板：屏幕尺寸 + 联网方式（WiFi/LTE/5G/Cellular）+ RAM + ROM + 屏幕工艺（柔光屏 PaperMatte / Nano-Texture Glass 单列配置）；
   - 穿戴：表盘尺寸 + 蜂窝（GPS/Cellular）[+ AMOLED/Solar 等计价变体]；
   - 音频：无（仅颜色）。
5. 同型号不同屏幕尺寸（如 MatePad Pro 12.2" vs 13.2"）视为不同配置参与一一对应。

## 3. 手机 / 平板（已定稿 2026-10-20）

记我司该型号在该国的配置集合为 O，友商为 C：

| 情形 | 规则 | 例 |
|---|---|---|
| \|O\|=1，\|C\|>1 | 我司唯一配置 ← C **全部**（友商多配置默认全显，一贵一便宜都看得到） | 华为单配置 vs iPhone 256/512 两档 |
| \|C\|=1 | O **全部** ← C 唯一配置 | 我司两档都对该友商唯一档 |
| 都多 | **一一对应**：优先同 ROM；同 ROM 再看 RAM 是否一致；无同 ROM 则 ROM 就近（容量差最小）；每个友商配置只被用一次 | 12+256←12+256，12+512←12+512 |
| 平板补充 | ROM/RAM 同分时按**屏幕尺寸就近** | MatePad Pro Max 13.2" 12+256 ← iPad Pro M5 13" 12+256 |

实例（R国）：Pura 90s Pro Max 12+256 ← iPhone 17 Pro 12+256、S26 Ultra 12+256；12+512 ← 两者 12+512。
实例（沙特）：17 Ultra 数据只有 16+512/16+1TB → 12+256 ← 16+512（就近）。

## 4. 穿戴（提案，待定稿）

当前提案：**表盘尺寸档**（<43mm 小表 / ≥43mm 大表）就近 + **蜂窝属性一致**（我司非蜂窝只对友商 GPS/蓝牙版）+ 同型号变体最多取 4 个（就近排序）；友商仅 1 配置 → 我司全部对其唯一项。

待接口人澄清清单：
1. 华为大/小表盘与友商尺寸的对应关系（41/42mm 算小表？46/47mm 大表？Apple 40/44mm 旧款？）；
2. 材质（铝/钛/织物流苏表带）是否影响价格、是否要进配置维度；
3. 蜂窝版是否参与对比（当前：我司非蜂窝不对蜂窝版）；
4. 我司源数据缺表盘尺寸的型号（如 GT 7 Pro 规格只有颜色）如何处理；
5. 儿童表等无可比对象时的处理（当前：留空）。

## 5. 音频（已定稿）

无规格差异（仅颜色），型号间 **1:1** 直接对配。

## 5b. 矩阵未覆盖时的自动匹配（已实现，供业务勾兑）

矩阵没有给出竞品的「国家 × 我司型号」：① 先沿用矩阵在其他国家给同一我司型号配过的竞品（该国有数据者，按出现国家数排序）；② 不足 3 个按同产业、该国成交价 USD 中位数价差 ±35% 内就近补齐，品牌按优先序每品牌先取一个（手机 Apple>Samsung>Xiaomi>Honor>OPPO>vivo；平板 Apple>Samsung>Xiaomi>Honor>Lenovo；穿戴 Apple>Samsung>Garmin>Xiaomi>Honor>Amazfit；音频 Apple>Samsung>Sony>Bose>Xiaomi>JBL>Soundcore）。对标标 `source=auto`，清单输出到 `docs/竞品自动匹配清单-<日期>.md/.xlsx` 供业务逐行保留/替换/删除。

## 6. 未命中与替代

- **矩阵有、数据无**（174 条）：默认**不匹配**（图中该竞品留空，待补采）。清单见 `data/real/ingest_report.md`。
- **代际替代**（用下一代顶替，如矩阵写 Watch Ultra 2、数据只有 Ultra 3/4）：可选，需在 overrides 标 `substitute: true`，图表显示替代品真实名称。是否批量启用待拍板。
- **人工指认**：`overrides.json::matrix_aliases`（把矩阵写法指认到数据型号，可带 spec 过滤）、`benchmark_manual`（人工追加对标，绕过自动规则）。

## 7. 变更流程

- 规则变更：改 `ingest_real.py::pair_configs` → `npm run ingest` → `npm run check`；
- 数据纠偏：只改 `overrides.json` → 重跑 ingest；
- 每次运行产出 `data/real/ingest_report.md`（覆盖面/清洗动作/未命中清单/对标样例）作为验收单。
