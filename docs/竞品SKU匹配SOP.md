# 竞品 SKU 匹配规则 SOP（PriceLens）

版本：2026-10-20 v1.0（手机/平板/音频定稿；穿戴为提案，待穿戴接口人穷举情形后定稿）；2026-11-25 §3 手机/平板改为 Eason 重述五条
落地位置：`pricelens/scripts/ingest_real.py::pair_configs` / `pick_version`（数据接入时自动执行；规则变更后用 `scripts/reemit_benchmark.py` 重发对标行）；人工纠偏/追加走 `pricelens/data/real/overrides.json`。

## 1. 名词与层级

- **型号（model）**：产品名，如 Pura 90s Pro Max / iPhone 17 Pro / Galaxy Tab S11。
- **配置（config）**：影响价格的规格组合。颜色**不属于**配置。
- **SKU**：型号 × 配置 × 颜色。
- **对标（benchmark）**：我司「型号 × 配置」→ 友商代表 SKU 的映射，**按国家维护**。

## 2. 通用前置规则

1. **分国产出**：友商 SKU 在该国无采集数据 → 不产出对标，不跨国借用。
2. **颜色不参与匹配**：对标取该国「采集周覆盖最多的颜色」为代表色，其余颜色在图表次级菜单可切换。
3. **只比裸机价**：赠品/套装不参与友商对比。组合销售（`是否组合销售=Y`）行的取数处理见 §8 待办。
4. **影响价格的配置维度必须进配置**（价格不同的规格必须分开比对）：
   - 手机：RAM + ROM；
   - 平板：屏幕尺寸 + 联网方式（WiFi/LTE/5G/Cellular）+ RAM + ROM + 屏幕工艺（柔光屏 PaperMatte / Nano-Texture Glass 单列配置）；
   - 穿戴：表盘尺寸 + 蜂窝（GPS/Cellular）[+ AMOLED/Solar 等计价变体]；
   - 音频：无（仅颜色）。
5. 同型号不同屏幕尺寸（如 MatePad Pro 12.2" vs 13.2"）视为不同配置参与一一对应。

## 2b. 矩阵文件结构与默认块（2026-11-09 定稿）

源文件 `产品竞品矩阵.txt`，TSV 九列：区域 / 国家 / 产业 / 系列 / 产品 / 价格挡位（USD）/ 品牌-竞品1..3；国家、产业、系列列留空承接上一行（合并单元格语义）。

- **默认块**：国家列写「默认」的行块（区域列「全部」）对**所有有采数国家**生效；分国块只写与默认不同的差异行。2026-11-09 起矩阵 = 默认块（全品类 36 行）+ 沙特/阿联酋/南非/墨西哥/巴西分国块，其余国家全部套默认。
- **让位规则**：分国块显式声明「国家 × 我司型号」（该行产品解析成功即算声明）后，默认块对这一对**不再产出对标、不再改档位**；未声明的产品全部套默认。声明按产品粒度——分国块只写手机几款时，该国穿戴/平板仍走默认。
- **价格档位**：默认块的挡位同样按国声明（`dim_product.tier_by_country`）；被分国块声明者以分国为准。
- **每国默认我司型号**（`dim_region.default_own_models`）：分国块优先，默认块按行序补缺口。
- 完全不在任何矩阵块出现的「国家 × 我司型号」（旧代际产品等）仍走 §5b 自动匹配；此时「矩阵他国同款竞品」先验只来自现行矩阵块（2026-11-09 前的分国块知识随块删除失效）。
- 实现：`ingest_real.py` 矩阵两遍处理（第一遍分国块、第二遍默认块×有数据国家）。

## 3. 手机 / 平板（2026-11-25 Eason 重述五条；取代 10-29 / 11-11 / 11-13 各版）

记我司该型号在该国的配置集合为 O，某款友商为 C。**我司每个配置对每款友商只配 1 个版本**，逐行独立判定，按下表顺序短路：

| 顺序 | 规则 | 例 |
|---|---|---|
| ① | 1 我司配置 → 1 友商版本；不出现多版本，不做富余归档 | — |
| ② | ROM + RAM 都一致 → 只借该版本 | Pura 90s Pro Max 12+512 ← iPhone 17 Pro 12+512、S26 Ultra 12+512（不再挂 12+1TB / 16+1TB） |
| ③ | ② 不成立 → 取 **ROM 一致**的版本，RAM 就近；± 等距取低 | MatePad SE 11" 6+128 ← Honor Pad X8b 4+128（同 ROM 有 4+128 / 8+128，与 6 各差 2 → 取低） |
| ④ | ROM 无一致 → 取 **RAM 一致**的版本，ROM 就近；± 等距取低 | MatePad Pro Max 13.2" 12+512 ← iPad Pro M5 13" 12+256 |
| ⑤ | 都不一致 → 先 ROM 就近（等距取低），该 ROM 下多 RAM 再 RAM 就近（等距取低） | Pura 90s Pro Max 12+256 ← 小米 17 Ultra 16+512（当地只有 16+512 / 16+1TB） |

- **版本可共用，不做占用**：友商同一版本可被我司多个配置配到（R国 nova 15 Max 的 8+256 与 8+512 对 X9D 都配 8+256——④ 同 RAM、ROM 就近）。11-13 版「每个友商版本只被一个我司配置占用」会让后处理的高配被迫错位（8+512 被挤到 12+256），已废止。
- 平板先按**屏幕尺寸分桶**（规则不变），桶内再按上表。
- 「就近」= 距离最小；距离相同取更低的那个（− 向优先）；规格未标的排最后。
- 友商仅 1 个配置时，我司该型号的全部配置都对它（① 的自然结果）。
- 实现：`ingest_real.py::pick_version`（选版本）/ `pair_configs`（平板分桶与调用）；`scripts/verify.mjs` 有五条规则的数据守卫。

实例（R国）：Pura 90s Pro Max 12+256 ← iPhone 17 Pro 12+256、S26 Ultra 12+256；12+512 ← 两者的 12+512。
实例（沙特）：17 Ultra 只有 16+512 / 16+1TB → 12+512 ← 16+512（③ 同 ROM）；12+256 ← 16+512（⑤ ROM 就近）。

**历史**：2026-10-20 定稿 → 10-29 修订「我司 1 配置 vs 友商多配置不再全显」+ 全局贪心防挤出 → 11-11 便宜对便宜 + 同 RAM 认领 → 11-13 锚点 + ROM→RAM 两级级联 + 配置占用 + 富余归档 → **11-25 五条**。废止富余归档的直接原因：一对多的行会把全中版本挤出前端每配置前 3 款（AE nova 15 Max 8+256 的真全中 X9D 8+256 排到第 4 被截），并让 Agent「价格优势」拿友商低配价当对标（R国 nova 15 12+256 曾对到 A57 8+128）。

## 4. 穿戴（提案，待定稿）

当前提案：**表盘尺寸档**（<43mm 小表 / ≥43mm 大表）就近 + **蜂窝属性一致**（我司非蜂窝只对友商 GPS/蓝牙版）+ 同型号变体最多取 4 个（就近排序）；友商仅 1 配置 → 我司全部对其唯一项。

待接口人澄清清单：
1. 华为大/小表盘与友商尺寸的对应关系（41/42mm 算小表？46/47mm 大表？Apple 40/44mm 旧款？）；
2. 材质（铝/钛/织物流苏表带）是否影响价格、是否要进配置维度；
3. 蜂窝版是否参与对比（当前：我司非蜂窝不对蜂窝版）；
4. 我司源数据缺表盘尺寸的型号（如 GT 7 Pro 规格只有颜色）如何处理；
5. 儿童表等无可比对象时的处理（当前：留空）。

## 5. 音频（已定稿）

无规格差异（仅颜色），型号间 **1:1** 直接对配。

## 5b. 矩阵未覆盖时的自动匹配（已实现，供业务勾兑）

矩阵没有给出竞品的「国家 × 我司型号」：① 先沿用矩阵在其他国家给同一我司型号配过的竞品（该国有数据者，按出现国家数排序）；② 不足 3 个按同产业、该国成交价 USD 中位数价差 ±35% 内就近补齐，品牌按优先序每品牌先取一个（手机 Apple>Samsung>Xiaomi>Honor>OPPO>vivo；平板 Apple>Samsung>Xiaomi>Honor>Lenovo；穿戴 Apple>Samsung>Garmin>Xiaomi>Honor>Amazfit；音频 Apple>Samsung>Sony>Bose>Xiaomi>JBL>Soundcore）。对标标 `source=auto`，清单输出到 `docs/竞品自动匹配清单-<日期>.md/.xlsx` 供业务逐行保留/替换/删除。

## 6. 未命中与替代

- **矩阵有、数据无 → 置空（2026-11-09 Eason 拍板，不加猜测）**：矩阵竞品名点不中数据型号时**一律留空**，不做同族/相近代际猜测——`Fenix 8 Pro ≠ Fenix 8`（砍掉 Pro 档=换产品）、`Amazfit Active ≠ Active Max`、`JBL Wave Buds ≠ Wave Buds 2`（代际顶替）、`Galaxy S26+ ≠ S26`、`Lenovo Legion Tab ≠ Tab`。清单见 `data/real/ingest_report.md`，逐条勾兑：补采、改矩阵名、或走 `matrix_aliases` 人工指认。
- **两条例外（仍是同品识别，非猜测）**：① 矩阵名带代际数字的短写（`Amazfit Active 2` → 数据 Active 2 Round/Square 双形状变体）；② 尺寸命名指现行代（`iPad Pro 13"` → 数据 iPad Pro M5、`iPad Air 13"` → M4，候选多出 token 全为芯片代号 m4/a16 时取最新代）。
- **代际替代**（用下一代顶替，如矩阵写 Watch Ultra 2、数据只有 Ultra 3/4）：可选，需在 overrides 标 `substitute: true`，图表显示替代品真实名称。是否批量启用待拍板。
- **人工指认**：`overrides.json::matrix_aliases`（把矩阵写法指认到数据型号，可带 spec 过滤）、`benchmark_manual`（人工追加对标，绕过自动规则）。

## 7. 变更流程

- 规则变更：改 `ingest_real.py::pair_configs` / `pick_version` → 重生对标行 `python3 scripts/reemit_benchmark.py`（只重发对标、不重跑全链：读最终维表 + `matrix_resolution.json`，默认只替换手机/平板行，幂等；`--dry-run` 先看差异）→ `python3 scripts/build_handoff_config.py`（交接预填表同步）→ `npm run check`（verify 含五条规则守卫）。维表本身也变了才走 `npm run ingest` 全链；
- 竞品配置变更：改 `产品竞品矩阵.txt`（分国块写差异、默认块写全量口径，见 §2b）→ 重跑 ingest（ZA 采数在库时需接 `reconcile_za_products.py` 回填小册子型号）→ `npm run check`；
- 数据纠偏：只改 `overrides.json` → 重跑 ingest；
- 每次运行产出 `data/real/ingest_report.md`（覆盖面/清洗动作/未命中清单/对标样例）作为验收单。
