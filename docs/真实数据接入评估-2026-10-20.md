## 二、标准数据结构（`pricelens/src/dataModel/types.ts`）

星型模型，维表 + 一张事实表：

- **dim_region**：国家（启用 = 有数据）、本币、`core_platforms`（国家主要电渠，过滤为数据中存在的）、`default_platform`、`default_own_models`（每产业默认我司型号 = 矩阵该国首个有数型号）。
- **dim_product**：SKU（颜色级）。`sku_id = own|cmp-品牌-型号__配置__颜色`，`model_id` 为型号 id；`industry` 六产业；`romram` 为配置显示文案（手机 `12+256 GB`、平板 `11.5" WiFi 8+128 GB [PaperMatte]`、穿戴 `46mm [GPS|Cellular|AMOLED]`、音频 `—`）；`tier_code` 型号级（按参考美元价落**产业各自阶梯**，见 dim_tier）；`countries` 有数国家。
- **dim_channel**：国家 × 平台 × 店铺类型（1P/3P/独立站）= 渠道，`display_name` 如 "OZON 1P"；具体店铺名挂事实行。
- **dim_time**：24 周 ISO 周三锚；**dim_fx**：币种 × 月 的行内汇率中位数（本币/USD）；**dim_promo**：分国大促（含适用平台）；**dim_tier**：六产业 USD 阶梯与标签。
- **dim_benchmark**：**分国**我司型号 × 配置 → 竞品代表色 SKU（`sort` 同配置内 1=主竞品；`source` = matrix / substitute / manual；`note` 矩阵原文）。
- **fact_price_weekly**：一行 = 周 × SKU × 国家 × 渠道 × 店铺。价格四列（官网建议零售价 = 账面价/RRP、官网成交价、平台建议零售价、平台成交价 = 折后价）+ 行内汇率 + 两列 USD + 三列折扣率 + 组合销售 + 分期原文 + 促销原文 + 网址 + 截图名 + 采集时间。

**口径定案**（与之前拍板一致）：主线图单平台——未选平台 = 该国默认电渠；渠道内多店铺取**最低在架价**，取价店铺随点带出（时点摘要可见「JARIR 独立站 · Jarir Bookstore」）；USD 按行内汇率逐行折算，不再有「参考汇率 80」；RRP 取所选渠道行的官网建议零售价（缺则平台划线价）。

## 三、竞品匹配规则（SKU 级，`scripts/ingest_real.py::pair_configs`）

1. **手机/平板**：RAM+ROM，优先 ROM 相同（再看 RAM），其次 ROM 就近（平板叠屏幕尺寸就近）。华为 1 配置 × 友商多配置 → 友商全显（平板按就近排序取前 4 个，防尺寸×内存×联网变体爆炸）；华为多配置 × 友商 1 配置 → 全部对该配置；都多 → 一一对应。
2. **穿戴（本轮设计）**：按表盘尺寸档（<43mm 小 / ≥43mm 大）就近 + 蜂窝属性一致（我司非蜂窝只对友商 GPS/蓝牙版）；友商 1 配置 → 全对；华为 1 配置（源数据常无尺寸）→ 友商同蜂窝属性各尺寸最多 4 个。
3. **音频/IoT/PC**：配置均为单一，1:1。
4. 竞品代表色 = 该国周覆盖最多的颜色（并列取字典序）；竞品在该国无数据 → 不产出对标（不跨国借用，避免「对标 key 不含国家」的雷）。

示例（R国）：Pura 90s Pro Max 12+256 ← iPhone 17 Pro 12+256 / S26 Ultra 12+256；12+512 ← 同 ROM 对应。沙特：← S26 Ultra / iPhone 18 Pro Max / 17 Ultra（后者 16+512 就近）。

## 五、补录入口（未来更新数据怎么做）

1. **新一周数据**：把同 29 列的 xlsx 放进 `pricelens/data/real/incoming/`（sheet 名须为「全量数据」），执行 `npm run ingest`（= `python3 scripts/ingest_real.py`），按唯一键（周×SKU×国家×渠道×店铺）合并、采集时间新者优先，全部维表与事实包重建；再 `npm run check` 构建单文件。
2. **纠偏映射**：只改 `pricelens/data/real/overrides.json`——`matrix_aliases`（矩阵名指认到数据型号，可标 `substitute`）、`brand_fixes`（品牌错标）、`model_aliases`（源数据型号异写合并）、`benchmark_manual`（人工追加对标）、`core_platform_overrides`（补/改国家默认电渠）。
3. **矩阵/电渠/日历变更**：直接替换仓库根的三份 txt，重跑 ingest。
4. 每次运行产出 `data/real/ingest_report.md`（覆盖面、清洗动作、未命中清单、对标样例、日历解析），作为接入验收单。

## 六、需要你拍板的事项

1. **沙特/阿联酋等 11 国默认电渠**是按数据量兜底的（见第一节），请确认或改 overrides。
2. **RRP 口径**：源表的「官网建议零售价」在同一 SKU 同周不同平台页面上并不一致（如 Mate X7 在 DNS 为 1,588 美元、M.Video 为 1,904 美元），甚至偶有低于成交价。当前按所选渠道取值；若要「全平台唯一官方阶梯」，建议改为取同周各平台中的**最大值**或仅取 1P/官网行。
3. **代际替代**：是否接受第四节的"下一代替代"映射，接受则我批量写进 overrides。
4. **offer 标记密度**：真实数据几乎每行都有分期/促销文本，开启「offer 权益」后每周都有图标；建议只对含促销政策（非纯分期）的点显示，或按大促日历内的周显示。
5. **仓库公开性**：仓库与 Pages 是公开的，本轮起产物内嵌真实爬取价格与内部竞品矩阵；本轮已本地提交但**未推送**，请确认是否照常推送双分支。
