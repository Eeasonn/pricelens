# PriceLens Copilot Agent 产品与前端完整方案

> 文档状态：规划稿  
> 更新日期：2026-10-29  
> 方案范围：图表筛选、数据查询、预警咨询及其前端展示、交互、状态、接口、安全和分阶段交付  
> 实施约束：本文仅提供产品与技术规划，不包含功能实现

## 1. 方案概述

### 1.1 产品定位

PriceLens Copilot Agent 是一个**嵌入价格分析工作流、只读优先、结果可追溯的智能分析副驾**。

它不改变 PriceLens 现有“筛选—看图—查明细—定位预警”的主流程，而是通过自然语言缩短操作路径，帮助用户快速完成：

1. **图表筛选**：产品、国家、渠道、时间、币种、RRP 等条件的设置与切换。
2. **数据查询**：最新价、历史价、环比、折扣、平台价差、竞品价差等。
3. **预警咨询**：解释触发原因、规则阈值、前后变化、影响范围和证据。

### 1.2 推荐形态

采用：

> **全局右侧 Copilot 面板 + 页面上下文入口 + 可切换全屏模式**

不单独增加一个与看板割裂的 Agent 顶级页面。

### 1.3 核心原则

- **对话不是结果终点**：结果必须落成可检查的图表、表格、预警解释和证据。
- **预览与应用分离**：Agent 生成筛选预览，用户明确点击后才应用到看板。
- **数字确定性计算**：模型不直接猜数字，所有数值来自统一查询和计算引擎。
- **事实、推断、建议分区**：避免将相关性表达为确定因果。
- **只读优先**：查询和解释默认只读；修改预警配置必须确认并重新鉴权。
- **上下文可追溯**：每次回答绑定当时的页面、筛选、数据版本和规则版本。
- **复用现有设计体系**：延续 PriceLens 的页头、卡片、筛选、图表、表格和预警视觉语言。

## 2. 用户、任务与边界

### 2.1 目标用户

主要用户：

- 价格经理；
- 产品经理；
- 国家／区域 GTM 操盘人员；
- 经营分析人员。

次要用户：

- 数据管理员；
- 运营管理员；
- 需要复核答案、查询口径和审计记录的管理人员。

### 2.2 核心任务

| 任务 | 用户问题示例 | 系统输出 |
| --- | --- | --- |
| 图表筛选 | “只看最近 8 周，USD，对比 iPhone，带上 RRP” | 筛选预览、图表预览、应用与撤销 |
| 数据查询 | “最近有价周哪个平台最便宜？比主竞品低多少？” | 结论、比较图、数据表、计算口径、引用 |
| 预警咨询 | “这条折扣预警为什么触发？影响大吗？” | 触发规则、前后值、公式、证据、影响范围 |
| 结果下钻 | “打开这个价格点的依据” | 商品链接、采集时间、真实快照、看板定位 |
| 阈值模拟 | “阈值改成 2.5% 会怎样？” | 历史触发数模拟、前后差异、确认修改 |

### 2.3 明确不做

不扩展为：

- 自动改价；
- 自动修改竞品矩阵；
- 自动执行经营动作；
- 无证据的业务因果咨询；
- 虚构销量、收入、毛利影响；
- 开放网页搜索；
- 通用文档写作、邮件、日程或 IM 助手；
- 任意 SQL、任意 JavaScript 或任意 URL 执行平台。

## 3. 主流 Copilot/Agent 形态调研

### 3.1 Microsoft Power BI Copilot

报表内 Copilot 面板保持分析现场，独立全屏形态适合跨报表任务；答案可包含可视化、摘要、筛选依据和参考脚注。

对 PriceLens 的启示：

- 面板与全屏应共存；
- 回答需要展示“如何得到答案”；
- 结果应能回到原始图表继续分析。

官方资料：

- [Power BI Copilot 概述](https://learn.microsoft.com/en-us/power-bi/create-reports/copilot-introduction)
- [答案依据与参考](https://learn.microsoft.com/en-us/power-bi/create-reports/tutorial-copilot-power-bi-discover-data)

### 3.2 Tableau Agent

Tableau Agent 以工作表对话面板为入口，可创建或更新图表；遇到高基数筛选时要求用户选值；计算字段需要用户审查后接受。

对 PriceLens 的启示：

- 歧义不应静默猜测；
- Agent 结果应允许用户继续使用原生筛选器修改；
- 重要配置需要明确确认。

官方资料：[Tableau Agent 使用文档](https://help.tableau.com/current/online/en-us/web_author_einstein.htm)

### 3.3 ThoughtSpot Spotter

Spotter 支持首页、Liveboard 等入口；高级分析展示计划、查询步骤和验证过程；外部写工具调用需要明确授权。

对 PriceLens 的启示：

- 展示可审计的动作摘要，而不是隐藏思维链；
- 上下文入口应靠近图表和预警；
- 写操作授权必须强于普通查询。

官方资料：

- [Spotter 概述](https://docs.thoughtspot.com/cloud/26.10.0.cl/spotter.html)
- [高级分析](https://docs.thoughtspot.com/cloud/26.10.0.cl/spotter-advanced-analysis.html)
- [工具权限](https://docs.thoughtspot.com/cloud/26.10.0.cl/spotter-connectors-use.html)

### 3.4 Databricks Genie

Genie 的回答可展开查看问题理解、相关数据、SQL 和逻辑步骤；支持历史、重跑、共享和只读查询。

对 PriceLens 的启示：

- 结果需要可展开的计算依据；
- 历史结果与最新数据重跑应分离；
- 查询和写入采用不同权限。

官方资料：

- [Genie 使用文档](https://learn.microsoft.com/en-us/azure/databricks/genie-agents/talk-to-genie)
- [概念与权限](https://learn.microsoft.com/en-us/azure/databricks/genie-agents/concepts)

### 3.5 Snowflake Cortex Analyst

Cortex Analyst 通过 API 与宿主应用集成，SSE 事件包括状态、内容增量、警告和错误；问题模糊时返回澄清选项。

对 PriceLens 的启示：

- 前端需要结构化流式事件协议；
- 警告与终止性错误应分开；
- 澄清应成为标准交互，而不是异常补丁。

官方资料：

- [Cortex Analyst 概述](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst)
- [REST/SSE 协议](https://docs.snowflake.com/en/user-guide/snowflake-cortex/cortex-analyst/rest-api)

## 4. 与现有 PriceLens 的结合

### 4.1 可复用基础

- 技术栈：React 18、TypeScript、Ant Design 5、ECharts 5、Vite，见 `pricelens/package.json:17`。
- 共享页面壳：`AnalysisShell`，适合让 Agent 面板跨页面保持，见 `pricelens/src/App.tsx:62`。
- 统一筛选状态：`FiltersState`，见 `pricelens/src/state/filtersTypes.ts:45`。
- 统一价格查询：`SeriesQuery`、`buildSeries`，见 `pricelens/src/dataModel/types.ts:116`、`pricelens/src/dataModel/aggregate.ts:467`。
- 现有预警规则、产品级阈值和看板定位能力，见 `pricelens/src/dataModel/alerts.ts:23`。
- 现有图表、明细表、快照弹窗、TSV 复制和预警样式。

### 4.2 需要补齐的基础能力

1. **图表焦点发布机制**  
   当前可见窗口主要存在于 `Dashboard` 局部状态。需要只读发布：
   - 当前子视图；
   - 可见时间窗口；
   - 选中周；
   - 选中系列；
   - 当前图表筛选口径。  
   参考：`pricelens/src/pages/Dashboard.tsx:21`

2. **历史预警规则快照**  
   必须保存触发时：
   - 规则类型；
   - 阈值；
   - 规则版本；
   - 输入数据点；
   - 数据版本；
   - 触发时间。  
   没有快照时只能写“按当前规则重新计算”。

3. **真实证据关联**  
   当前快照仍存在演示注册表路径。Agent 只能引用真实事实行关联的截图；没有截图时明确显示“暂无快照”。  
   参考：`pricelens/src/chart/PriceTrend/SnapshotModal.tsx:27`

4. **数据覆盖提示**  
   不同国家、产品的有效周数差异较大。数据点不足时不能强行计算环比、趋势或价格结论。

## 5. 信息架构与入口设计

### 5.1 全局入口

位置：共享 `PageHeader` 右侧。

入口文案：

> **问 PriceLens**

状态表现：

- 默认：Agent 图标 + 文案；
- 运行中：小型运行状态点；
- 后台完成：未读完成标记；
- 无权限或离线：入口仍可见，但打开后说明能力边界。

面板跨页面保持，不因业务页面切换而卸载。

### 5.2 页面上下文入口

| 入口 | 位置 | 携带上下文 |
| --- | --- | --- |
| 问此图 | 图表工具栏右侧 | 页面、子视图、筛选、可见窗口 |
| 问此产品 | 产品摘要、图例 | 主品、对比区、当前国家与渠道 |
| 问此周 | 明细表时间列、价格点 | 产品、周、渠道、价格点 |
| 解释此预警 | 预警矩阵、事件行 | 预警 ID、产品、规则、时间 |
| 查看口径 | Agent 回答中的口径链接 | 打开现有数据说明对应章节 |

现有筛选条继续保留，Agent 不替代手动操作。

### 5.3 快捷键

- `Cmd/Ctrl + K`：打开 Agent 并聚焦输入框。
- `Esc`：关闭当前最上层浮层；不默认取消正在运行的任务。
- `Enter`：发送。
- `Shift + Enter`：换行。
- 中文输入法组合期间不触发发送。

## 6. 面板与页面布局

### 6.1 右侧 Dock 模式

宽桌面下，主内容与 Agent 同屏：

```text
┌──────────────────────────────────────────────────────────────┐
│ PriceLens 页头                              [问 PriceLens]   │
├───────────────────────────────────────┬──────────────────────┤
│                                       │ Agent 顶部工具条     │
│ 现有筛选条                            │ 新对话 历史 全屏 关闭 │
│                                       ├──────────────────────┤
│ 当前图表 / 明细 / 预警                │ 上下文 Chips         │
│                                       │ R国 · 2个产品 · 8周  │
│                                       ├──────────────────────┤
│                                       │ 用户消息             │
│                                       │ Agent 执行步骤       │
│                                       │ 结论与结果卡         │
│                                       │ 引用与后续问题       │
│                                       ├──────────────────────┤
│                                       │ 输入框        发送   │
└───────────────────────────────────────┴──────────────────────┘
```

规则：

- `≥1440px`：右侧 dock。
- 默认宽度 `440px`，可调整至 `400–560px`。
- 主内容同步收窄，不产生整页水平滚动。
- dock 非模态，用户仍能操作看板。
- 页面状态变化后，旧回答不变；下一次提问使用新上下文。

### 6.2 覆盖抽屉模式

`1024–1439px` 时默认使用覆盖式抽屉：

- 保留左侧页面上下文；
- 不强行挤压图表；
- 可切换全屏；
- 点击遮罩只关闭面板，不取消后台查询。

### 6.3 全屏模式

```text
┌──────────────┬──────────────────────────┬───────────────────┐
│ 会话历史     │ 当前对话                 │ 证据与审计        │
│              │                          │                   │
│ 搜索         │ 上下文快照               │ 数据版本          │
│ 最近会话     │ 执行步骤                 │ 事实行与公式      │
│ 固定的会话   │ 图表 / 表格 / 预警卡     │ 商品链接与快照    │
│              │ 输入区                   │ 操作与确认记录    │
└──────────────┴──────────────────────────┴───────────────────┘
```

右侧证据栏可折叠，不能挤压主对话至不可读宽度。

### 6.4 小屏模式

- `<1024px`：全屏对话。
- `<768px`：单列结果卡。
- 宽表内部横向滚动。
- 图表必须提供表格替代。
- 不维持对话与看板双栏。

## 7. 对话区详细设计

### 7.1 顶部工具条

包含：

- 标题“PriceLens Agent”；
- 当前运行状态；
- 新对话；
- 历史；
- dock／全屏切换；
- 关闭。

运行中标题可显示：

> 正在查询价格数据…

但不展示无约束的长篇“正在思考”。

### 7.2 上下文区

默认显示“跟随当前页面”。

Chips 示例：

- `R 国 · 手机`
- `主品：Pura…`
- `对比：2`
- `最近 8 个数据周`
- `USD`
- `含 RRP`
- `多产品对比`

规则：

- 超过两行折叠为“＋N”。
- 点击 chip 可查看完整口径。
- 每次提问生成不可变上下文快照。
- 页面变化后提示“页面口径已变化”，不回溯修改旧答案。
- 用户可以移除某个非必要上下文，但不能绕过数据权限。

### 7.3 消息列表

用户消息简洁右置或整行展示。

Agent 消息采用全宽结构化内容：

1. 理解口径；
2. 工具执行状态；
3. 结论；
4. 图表／表格／预警卡；
5. 引用；
6. 后续建议。

不堆叠头像和装饰性气泡，避免挤占数据展示空间。

### 7.4 建议问题

空态根据当前页面生成三类问题：

**图表筛选**

- “只看主品和第一名竞品”
- “切换到最近 8 周并显示 RRP”

**数据查询**

- “最近有价周哪个平台价格最低？”
- “主品与主竞品的价差是多少？”

**预警咨询**

- “解释当前产品的最新预警”
- “哪些预警与折扣变化有关？”

回答后的建议必须可执行，例如：

- “只看 DNS”
- “定位到触发周”
- “与主竞品比较”
- “打开依据”

### 7.5 输入区

包含：

- 多行文本输入；
- 上下文添加入口；
- 发送／停止按钮；
- 可选的当前能力提示。

运行中允许继续编辑草稿，但不隐式并发修改同一执行计划。

## 8. 结果卡完整规格

### 8.1 公共结构

每张结果卡包含：

- 结论标题；
- 结果类型；
- 上下文摘要；
- 事实／推断／建议分区；
- 数据版本；
- 实际覆盖时间；
- 最大采集时间；
- 渠道与卖家；
- 计算／规则版本；
- 引用；
- 警告；
- 可用动作。

历史卡重新打开时显示：

> 这是基于当时数据版本的结果。

提供“按最新数据重跑”，不得静默刷新。

### 8.2 筛选预览卡

内容：

- 变更前／变更后对比；
- 主品、对比品、国家、渠道、时间、币种、RRP 等差异；
- 被移除或替换的条件；
- 数据覆盖警告；
- 图表预览。

动作：

- 应用到看板；
- 继续修改；
- 取消。

应用后：

- 显示“已应用 · 撤销”；
- 撤销恢复完整页面、筛选、子视图和焦点快照。

### 8.3 图表结果卡

图形规则：

- 趋势：折线图；
- 平台／产品比较：条形图；
- 构成或分布仅在现有语义支持时使用；
- 不允许模型随意创造图形。

展示规则：

- dock 内高度 `180–260px`；
- 支持图表／表格切换；
- 显示币种、时间、渠道和口径；
- 支持展开全屏；
- 支持“在看板打开”“定位此周”“查看明细”。

### 8.4 数据表卡

- 默认显示 5–8 行；
- 支持展开、复制；
- dock 内使用紧凑表；
- 全屏或看板中复用完整 `TrendTables`；
- 数值列保持现有格式化和对齐规则。

### 8.5 预警解释卡

固定结构：

1. 触发结论；
2. 规则类型和阈值；
3. 前后值；
4. 计算公式；
5. 影响产品、国家、平台和时间；
6. 数据点与证据；
7. 建议检查事项；
8. 看板定位／模拟阈值。

视觉上复用现有 `TYPE_STYLE`、`TypePill` 和 `alertDigest`。

### 8.6 引用卡

引用类型至少区分：

- 原始事实行；
- 派生计算及公式；
- 预警规则；
- 大促日历；
- 商品 URL；
- 页面快照。

没有真实快照时显示：

> 有价格记录，暂无页面快照。

不能用演示图补足。

## 9. 三条核心端到端流程

### 9.1 自然语言图表筛选

用户：

> R 国手机里，只看 Pura 90s Pro Max 12+256 和 iPhone 17 8+256，最近 8 周，USD，带上 RRP。

Agent 流程：

1. 识别两个产品、配置、时间、币种和价格类型。
2. 检查国家、产品、时间覆盖和图表线数限制。
3. 展示“预览口径”，明确尚未修改当前看板。
4. 返回筛选差异和图表预览。
5. 用户点击“应用到看板”。
6. 前端校验 `FilterPatch`。
7. 更新 `FiltersContext`、筛选条、URL、图表和明细。
8. 显示“已应用 · 撤销”。

若会覆盖复杂的手动对比区，先展示前后差异确认。

### 9.2 数据查询、澄清与下钻

用户：

> 最近一个月，Pura 在 R 国哪个平台最便宜？比主竞品低多少？

Agent 先澄清：

> “最近一个月”是最近有价周、近 4 个数据周均值，还是整个自然月？

选项：

- 最近有价周；
- 近 4 周均值；
- 整个自然月。

执行步骤：

- 解析主竞品；
- 查询各平台最低在架价；
- 计算同配置价差；
- 检查数据质量与证据；
- 返回结论、比较图和数据表。

继续问“为什么更低”时：

**事实**

- 同周出现某促销记录；
- 当前价格低于前一周；
- 某平台价格低于其他平台。

**可能解释**

- 促销与降价同时出现，可能相关。

**限制**

- 当前数据无法证明唯一因果；
- 不推算未提供的销量或收入影响。

用户可点击“打开依据”查看商品 URL、采集时间和真实快照。

### 9.3 预警咨询与阈值模拟

用户从预警行点击“解释此预警”：

1. Agent 固定该预警上下文。
2. 读取预警事件。
3. 读取触发时规则快照。
4. 查询前后有价周。
5. 查询同周竞品和平台价格。
6. 展示触发公式、阈值和影响范围。

建议仅包括：

- 核对促销记录；
- 检查商品页面证据；
- 对比其他平台是否同步；
- 判断是否为单平台短期变化。

不直接给出确定降价指令。

用户继续：

> 如果把这类预警阈值改成 2.5% 会怎样？

Agent 先只读模拟：

- 历史触发数变化；
- 哪些事件会新增或消失；
- 影响的产品和时间范围。

只有用户点击“应用此阈值”后，才进入：

`展示对象和前后值 → 服务端鉴权 → 原子更新 → 同步前端 → 提供版本化撤销`

## 10. Agent 执行过程展示

### 10.1 动作时间线

只展示可审计的动作摘要：

- 理解问题与口径；
- 解析产品／渠道／预警；
- 查询价格序列；
- 计算差异；
- 检查证据；
- 生成回答。

每一步状态：

`等待 → 运行中 → 成功／警告／失败／已取消／跳过`

可展开查看：

- 业务化输入摘要；
- 查询行数；
- 耗时；
- 数据版本；
- 警告；
- 输出引用；
- request/run/tool ID。

不展示系统提示词或模型隐藏思维链。

### 10.2 流式输出

- 工具状态先流式出现。
- 结果卡原子化提交。
- 数字和引用校验完成后，再流式生成自然语言解释。
- 图表不随文本 token 反复重绘。
- 工具列表更新不对整个消息列表做重排动画。

### 10.3 取消与重试

- 前端通过 `AbortController` 取消读取。
- 服务端同步取消实际运行。
- 已完成的只读结果保留，标记“已停止，以下为部分结果”。
- 重试创建新的 attempt，并关联原请求。
- 写操作使用幂等键，禁止重复执行。
- 超时后允许继续等待或查询后台状态，不诱导盲目重试。

## 11. 异常、空态与恢复

| 状态 | 展示方式 | 用户动作 |
| --- | --- | --- |
| 产品无法匹配 | 显示候选或未匹配字段 | 选择候选、修改输入 |
| 时间范围无数据 | 显示实际覆盖范围 | 调整时间 |
| 数据点不足 | 说明无法计算环比／趋势 | 扩大范围 |
| 单平台数据 | 说明无法进行平台比较 | 查看现有数据 |
| 部分失败 | 保留成功结果，标明缺失部分 | 只重试失败步骤 |
| 权限不足 | 不泄露隐藏产品、价格或截图地址 | 查看可访问范围 |
| 低置信度 | 显示待确认口径和候选 | 确认后重跑 |
| 数据陈旧 | 显示数据截止时间 | 使用旧数据或等待更新 |
| 上下文已变化 | 保留旧结果，提示当前页面已变化 | 基于新上下文提问 |
| 断流／离线 | 保留已完成内容 | 重连、查询运行状态 |
| 工具超时 | 显示耗时和当前步骤 | 取消、等待、重试 |
| 结果校验失败 | 阻止带数字的最终回答 | 重新查询或明确无法回答 |

“无数据”“无筛选结果”“计算失败”“权限不足”必须使用不同文案。

| 动作 | 默认策略 |

- 页面；
- 筛选；
- 子视图；

- 数据版本。

- `agent=dock|full`
- `ac=<conversationId>`
- `am=<messageId>`，可选

- Agent 不加入现有业务 `Page` 枚举。
- dock 开关可继续使用 `replaceState`。
- 全屏模式可压入历史记录，使浏览器后退返回看板。
- URL 只放 ID，不放对话正文或大型筛选快照。

## 15. 数据流、工具与 API

### 15.1 查询数据流

```text
用户输入
→ 冻结上下文
→ 创建运行
→ 服务端鉴权与规划
→ 工具查询与计算
→ 结构化结果卡
→ 数字和引用校验
→ 自然语言解释
→ 完成
```

### 15.2 应用筛选数据流

```text
Agent 返回 FilterPatch
→ 前端 schema 与业务校验
→ 用户确认
→ FiltersContext 执行
→ 现有 URL / 图表 / 明细联动
→ 上报审计事件
```

### 15.3 工具白名单

- `catalog.resolve`：解析产品、配置、渠道和预警。
- `series.query`：基于 `SeriesQuery` 查询。
- `series.compare`：计算价差、环比、折扣等指标。
- `alerts.query`：查询当前或历史预警。
- `alerts.explain`：读取规则快照和证据。
- `alerts.simulate`：只读模拟阈值。
- `alerts.update`：需确认和独立权限。
- `view.preview`：生成 `FilterPatch`，不写页面。
- `view.apply`：由前端在用户确认后执行。

不允许模型提交任意 SQL、JavaScript 或 URL。

### 15.4 REST 契约建议

- `GET /agent/capabilities`
- `POST /agent/conversations`
- `GET /agent/conversations?cursor=…`
- `GET /agent/conversations/{id}/messages?cursor=…`
- `POST /agent/runs`
- `POST /agent/runs/{id}/clarify`
- `POST /agent/runs/{id}/cancel`
- `POST /agent/runs/{id}/retry`
- `POST /agent/actions/{id}/confirm`
- `GET /agent/runs/{id}/audit`
- 后续：`POST /agent/conversations/{id}/share`

每次运行至少携带：

- 用户消息；
- 客户端请求 ID／幂等键；
- 会话 ID；
- 上下文快照及指纹；
- 数据版本；
- 页面能力版本。

### 15.5 SSE 事件建议

使用可 POST 的 `fetch` 流，而不是仅支持简单 GET 的 `EventSource`。

| 事件 | 内容 |
| --- | --- |
| `run.started` | runId、messageId、上下文快照、数据版本 |
| `plan.updated` | 高层步骤及状态 |
| `tool.started` | 工具名、业务化输入摘要 |
| `tool.completed` | 输出引用、行数、耗时、警告 |
| `tool.failed` | 错误码、是否可重试 |
| `clarification.required` | 问题、候选项、恢复令牌 |
| `confirmation.required` | 动作、前后差异、过期时间 |
| `result.upsert` | 类型化图表／表格／预警／引用卡 |
| `content.delta` | 自然语言增量 |
| `run.completed` | 完成原因、最终事件序号 |
| `run.failed/cancelled` | 可恢复信息 |
| `heartbeat` | 长连接保活 |

所有事件携带：

- `schemaVersion`
- `runId`
- `seq`

断线后按最后序号恢复，避免重复卡片和重复写操作。

### 16.1 前端负责

- 页面视图撤销；

### 16.2 后端／Agent 服务负责

- 模型意图理解；
- 工具规划与执行；
- 用户身份和数据权限；
- 服务端数据隔离；
- 会话与运行持久化；
- SSE、取消、超时、重试和幂等；
- 数字与引用校验；
- 历史预警规则快照；

- 预警配置写入和版本控制；
- 分享、审计和质量评估。

演示环境可以使用本地只读工具适配器，但：

- 不在单文件 HTML 中内置模型密钥；

- 不把演示路径描述为生产安全边界。

## 17. 视觉、动效与可访问性

### 17.1 视觉一致性

- 复用现有颜色、圆角、阴影、间距和字号 token。
- 结果卡沿用现有卡片层级。
- 预警复用现有类型色和 pill。
- 选中态继续浅蓝底、蓝描边。
- 不新增一套“AI 专属”高饱和渐变视觉。
- Agent 的运行色只表示状态，不与涨跌语义混用。

### 17.2 动画

- 面板、卡片：`120–180ms` 淡入／位移。
- 工具状态仅更新当前步骤，不做全列表重排动画。
- 图表不随流式文本反复重绘。
- 自动滚动只发生在用户已经位于底部时。
- 用户向上阅读后，不强制拉回底部。

减少动态模式下：

- 禁用平滑滚动；
- 禁用闪烁运行点；
- 禁用自动面板滑动；
- 保留即时状态变化。

### 17.3 键盘与读屏

- dock 非模态，不锁焦点。
- 全屏模态约束焦点，关闭后归还触发器。
- 消息列表使用 `role="log"`。
- `aria-live="polite"` 只播报步骤完成、澄清和最终回答。
- 严重错误一次性 assertive。
- 运行区使用 `aria-busy`。
- 停止按钮具有明确可访问名称。
- 图表必须有文字摘要和数据表替代。
- 预警状态不只靠颜色。
- 引用按钮名称包含来源和时点。

## 18. 长会话与性能

### 18.1 渲染策略

- 初始只加载最近约 30–50 条消息。
- 向上游标分页。
- 超长会话进行渲染窗口化。
- 图表卡按可见性懒挂载。
- 离开渲染窗口后释放 ECharts 实例。
- 大表与原始工具结果按引用加载。
- 本地演示查询按 `dataVersion + queryHash` 缓存。
- 重计算可放入 Web Worker。

### 18.2 运行控制

- 新运行取消过期的前端读取。
- 旧事件按 `runId/seq` 丢弃。
- 服务端对长对话使用“最近完整轮次 + 早期摘要 + 固定上下文快照”。
- 不无限发送完整历史。

### 18.3 建议性能目标

- 面板打开可交互：`<150ms`
- 普通 UI 操作响应：`<100ms`
- 简单查询：P50 `<5s`、P95 `<12s`
- 200 条消息历史下，输入和滚动保持可用
- 断线恢复后不出现重复消息、卡片或写操作

## 19. 安全、权限与审计

### 19.1 权限

服务端按用户身份重新校验：

- 国家；
- 产业；
- 产品；
- 渠道；
- 事实行；
- 快照；
- 预警配置。

`capabilities` 只用于 UI 展示，不能代替鉴权。

无权限错误不能泄露：

- 隐藏产品名称；
- 隐藏价格；
- 截图地址；
- 其他国家或渠道数据。

### 19.2 模型与数据安全

- 默认只向模型发送完成任务所需的最小聚合结果。
- 原始事实行仅在证据解释确有需要时提供。
- 对话正文不写入 URL。
- 历史默认私有。
- 模型输出使用 React 文本渲染，不注入生成 HTML。
- 商品链接校验协议与域名，继续使用 `noopener noreferrer`。
- 快照使用有权限校验的短期地址。
- 工具白名单和结构化输入用于防止提示词注入扩大权限。

### 19.3 数字可追溯

每个派生数字必须能展开：

```text
输入事实点
→ 筛选条件
→ 计算公式
→ 舍入 / 币种规则
→ 输出
```

每条预警解释必须能展开：

```text
触发事件
→ 当时规则与阈值
→ 前后值
→ 数据点与采集时间
→ 证据
```

### 19.4 审计展示

在运行卡或全屏右侧提供“活动与审计”：

- 操作者与时间；
- run/request ID；
- 页面与数据版本；
- 工具名称、耗时和状态；
- 筛选前后差异；
- 用户确认、应用和撤销；
- 预警阈值旧值／新值；
- 分享与权限变化；
- 模型／编排版本；
- 结果校验状态。

普通用户查看业务化摘要，管理员按权限查看技术细节。审计记录由服务端追加写入，前端只读。

## 20. 分阶段交付

### 20.1 阶段 0：契约与证据底座

**交付**

- 语义字典与指标定义；
- 工具 schema；
- 服务端查询与权限；
- 数据版本；
- 预警规则快照；
- 真实事实行与截图关联；
- 图表焦点只读接口。

**验收**

- 同一 `SeriesQuery` 的 Agent 与看板结果逐点一致。
- 历史预警能恢复当时阈值和输入证据。
- 无真实截图时正确降级。
- 所有结果卡都带数据版本和覆盖范围。

### 20.2 阶段 1：MVP——三类任务完整闭环

**交付**

- 全局 dock；
- 上下文 chips；
- 消息与输入；
- 基础历史；
- 筛选预览、应用和撤销；
- 数据查询图表／表格；
- 引用与看板下钻；
- 当前预警解释；
- 工具时间线；
- 取消、重试、基础错误和无结果；
- 服务端鉴权与基础审计。

**验收**

- 三条核心路径均端到端可用，而非只返回文本。
- 建立至少 30 条标准问题集。
- 支持范围内意图／实体解析准确率 `≥90%`。
- 数值与确定性引擎一致。
- 数字引用覆盖率 `100%`。
- 筛选应用与手工操作结果一致。
- 撤销可精确恢复。
- 越权请求全部被服务端拒绝。
- 取消和重试不产生重复写入。

### 20.3 阶段 2：复杂分析与可靠性

**交付**

- 多步查询；
- 澄清；
- 部分失败恢复；
- 全屏模式；
- 持久历史；
- 旧结果重跑；
- 阈值模拟与确认修改；
- SSE 断线恢复；
- 后台运行状态；
- 完整可访问性；
- 长会话性能优化。

**验收**

- 模糊问题不会静默猜测关键口径。
- 断流重连后事件和卡片不重复。
- 单平台、单周、缺采、无权限、低质量数据均有专门状态。
- 仅键盘可完成三条核心流程。
- 200 条消息会话通过滚动、输入和内存验收。
- 每个结果均可追溯真实证据。

### 20.4 阶段 3：协作、治理与质量运营

**交付**

- 只读分享；
- 用户反馈；
- 人工复核；
- 管理员审计；
- 经验证的高频问题／答案模板；
- 数据和模型保留策略；
- 成本监控；
- 离线单文件降级策略。

**验收**

- 分享链接不能绕过原数据权限。
- 被分享者默认只读，不能续写或修改预警。
- 审计可还原完整筛选和阈值修改链路。
- 高频问题具有准确性回归集。
- 模型或语义变更可比较质量与成本。
- 离线版不包含密钥，并明确标识在线 Agent 不可用。

## 21. 默认产品决策

| 事项 | 默认方案 |
| --- | --- |
| “最近”的基准 | 相对当前数据最新有价周，并显示明确日期 |
| 历史会话 | 默认私有，服务端保存；保留期由管理策略配置 |
| 分享 | 默认关闭，开启后也只读并重新鉴权 |
| 旧结果刷新 | 不自动刷新，由用户显式重跑 |
| 图表上下文 | MVP 使用全局筛选，后续补精确可见窗口和焦点 |
| 历史预警 | 有规则快照才称“当时触发原因” |
| 数据覆盖不足 | 少于两个有效点不计算环比，不补值 |
| 快照缺失 | 显示无快照，不使用演示图替代 |
| 因果解释 | 只表达证据支持的事实和可能解释 |
| 经营建议 | 提供检查和观察方向，不自动给出降价幅度 |
| 离线单文件 | 保留看板，不承诺完整在线 Agent |
| 模型供应商 | 保持供应商无关，以工具契约和评测集为稳定层 |

## 22. 成功指标与主要风险

### 22.1 成功指标

**效率**

- 图表筛选任务完成时间下降；
- 数据查询所需手动操作次数下降；
- 预警解释定位时间下降。

**质量**

- 数字与确定性引擎一致率 `100%`；
- 数字引用覆盖率 `100%`；
- 支持范围内意图／实体解析准确率 `≥90%`；
- 关键口径歧义静默猜测率趋近 `0`。

**安全**

- 越权请求服务端拦截率 `100%`；
- 无真实证据却声称有证据的回答数为 `0`；
- 写操作未经确认执行数为 `0`。

**体验**

- 三条核心流程可仅键盘完成；
- 取消、重试和断线恢复不产生重复内容；
- 长会话输入、滚动和结果展开保持可用。

### 22.2 主要风险

按优先级排序：

1. 权限与数据泄露；
2. Agent 与看板业务口径不一致；
3. 历史预警不可重放；
4. 模型过度解释或虚构因果；
5. 各国数据稀疏导致结论不可靠；
6. 真实截图与证据链不完整；
7. 长会话成本和性能；
8. 面板挤压现有图表空间。

这些风险应优先于继续增加聊天能力。

## 23. 最终推荐

PriceLens Agent 最合适的方向不是“在看板旁边加一个聊天框”，而是：

> **以页面上下文为起点，以确定性工具为执行层，以图表、表格和预警卡为结果，以证据和审计为信任基础的嵌入式分析副驾。**

第一版就应完成三条闭环：

- **问一句 → 预览筛选 → 应用看板 → 撤销**
- **问一句 → 查询计算 → 图表／表格 → 打开证据**
- **点预警 → 解释规则 → 查看前后值 → 定位看板**

全屏、多步分析、阈值模拟、历史分享和治理功能可在此之上分阶段扩展，但**数字可信、权限可靠、证据完整和交互闭环**应从第一阶段就作为硬性要求。
