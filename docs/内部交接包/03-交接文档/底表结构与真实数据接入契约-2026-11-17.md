## 0. 总览：两张源表 → 一个数据包（+ 一张配置表）→ 应用

```
公司系统产出（原表样式）                数据包 v3（只装原样行）              PriceLens 稳定版
──────────────────────              ─────────────────────              ────────────────
OFFER 看板明细  ──原样倒包──▶  offers[]（中文双语表头原样）─┐
PSI 周销量表    ──原样倒包──▶  sales[]（PSI 源行原样）    ─┴─▶ pricelens-data-pack v3 ─▶ 配置页「导入数据包」
                                                                     │ 导入时应用内归一派生（offerIngest）：
配置表 xlsx（Eason 维护）                                            │ 拆列→穿戴升级→系列→分档→渠道→汇率→维表
  系列规则/型号别名/对标矩阵/分档阶梯/大促档期 ──▶ 配置页「导入配置」──┘ （规则读入参与派生，§9）
```

- **内部系统不再需要构建任何维表/派生字段**——series、tier、对标矩阵、渠道维、
  汇率表、分档、cat1/cat2、穿戴表盘升级等全部由 PriceLens 导入时自动完成；
- 规则类内容（谁归哪个系列、谁对标谁、分档线、大促日期）走**配置表 xlsx 五页签**
  （§9），个人级生效、随时改随时导；改完点数据包区「用当前配置表重新派生」即时重算
  （系列规则例外：读时生效，改完立即反映在产品树，无需重派生）；
- v1/v2 规范化包（内部系统产全部 dims + 事实包）继续兼容——适合内部系统成熟后
  走批产的高阶路线，字段契约见 §2.2–§5；
- 原表模式样例（金标验证用）：`docs/底表样例/pricelens-sample-raw-datapack-*.json`
  （v3 包，RU/PL/DE 三国 22,225 行原样行；金标：SKU 658/658 对齐、事实行 22,225/22,225
  精确一致），复跑生成：`node pricelens/scripts/build_sample_raw_datapack.mjs --countries RU,PL,DE`。

## 2. OFFER 表（价格侧）契约

**v3 原表模式（推荐）：offer 明细行原样塞进数据包 `offers` 数组即可**——中文双语表头
（如 `时间周期\nperiod`）与同义列名（`商品型号`/`规格` 等）引擎自适应；两种形态都收：

- **原始形态**：`型号规格` 单列（`12+512 GB Black`、`11.5"/WIFI/8+256 GB Black`、
  `46mm GPS Black`…），引擎按产业拆列（与构建管线 parse_romram 逐字对齐）；
- **规格拆列形态**：`Category1`/`Category2`/`info` 三列 + `tech_date`（YYYY0WW），
  按下方拆列规则预处理好过的表——引擎识别后直接采用拆列结果（Category1 的语义
  = 维度1：拆了列就是维度，GT 6 Pro 类空 cat1 = 型号级）。

核心必备列（缺任一拒包并提示）：`时间周期`（或 tech_date）、`品类`、`品牌`、`型号`、
`国家/地区`、`平台`、`店铺类型`、`货币`、`汇率`。其余列（店铺名称/显示店铺名称/价格/
划线价/折扣率/组合销售/分期/促销/网址/截图/采集时间）缺省补默认。

以下 §2.1–§2.4 是**拆列与派生口径**（引擎在导入时执行，内部系统无需预加工；
v1/v2 规范化路线则由内部系统按此产出）。

### 2.1 列映射

| 源列 | 内部落点 | 说明 |
|---|---|---|
| country（Management Country/Region） | `country_code` | 归一规则见 §4.2；R国=Russia→`RU` |
| model | `model_name`（→ model_id） | 与 PSI `Product` 同一口径，见 §4.5 |
| Category1 | 穿戴→`romram`（表盘）+`cat1`；手机/平板→`cat1`（存储） | 手机/平板的显示文案 `romram` = Category1 |
| Category2 | 平板→`cat2`（屏幕），显示并入 `romram` 前缀 | 其余产业恒空 |
| info | `color`（颜色/联网等次级信息） | 不参与销量匹配 |
| tech_date（YYYY0WW） | `week_id`（YYYYWW） | `2026043 → 202643`，见 §4.1 |
| 平台/店铺/价格/划线价/汇率/链接/截图… | `FactPriceWeekly` 对应字段 | 沿用既有 29 列口径不变 |

### 2.2 内部形态（不变 + 新增字段）

`DimProduct`（颜色级 SKU）新增两个可选字段，**显示文案仍走 `romram`，新字段只做结构与匹配**：

```jsonc
{
  "sku_id": "own-huawei-watch-gt-6__41mm__black",
  "model_id": "own-huawei-watch-gt-6",
  "industry": "wearable",
  "brand": "HUAWEI", "is_own": true, "series": "WATCH GT", "model_name": "Watch GT 6",
  "romram": "41mm",            // 显示文案（手机=存储；平板=屏幕+存储；穿戴=表盘；音频='—'）
  "color": "Black",
  "cat1": "41mm",              // ★新增 维度1（§1 表）；null=未标注/产品级
  "cat2": null,                // ★新增 维度2（平板=屏幕）；其余 null
  "tier_code": "...", "tier_by_country": {...}, "ref_price_usd": ...,
  "launch_date": "...", "eol_date": null, "first_week": "...", "last_week": "...",
  "countries": ["RU"]
}
```

`FactPriceWeekly`（一行 = 周×SKU×国家×渠道×店铺）**零改动**。

### 2.3 系列归组（`series` 字段从哪来——源表没有，产出 DimProduct 时派生补上）

**offer 原表里没有「系列」列**。产品树第三列（Mate / WATCH GT / Xiaomi 数字系列 / Galaxy S…）
是管线在生成 DimProduct 时按「品牌 + 型号名 → 系列」规则推导的派生字段。内部系统产出
DimProduct 时同样要给出这一列，规则两张表（都可原样复刻，输入只有 brand 与 model_name）：

| 谁 | 规则表 | 形态 | 例 |
|---|---|---|---|
| 我司（is_own=true） | `pricelens/scripts/ingest_real.py` `OWN_SERIES_RULES` | 型号名归一键**前缀** → 系列名，20 条 | `matepadpro→MatePad Pro`、`watchgt→WATCH GT`、`matex→Mate`、`pura→Pura`、`nova→nova` |
| 竞品（is_own=false） | `pricelens/scripts/series_rules.py` | 品牌×型号名**正则** → 系列名，约 90 条 | `Xiaomi 15/16/15T→Xiaomi 数字系列`、`Redmi Note 14→Redmi Note`、`Redmi 13→Redmi 数字系列`、`Galaxy S25/S26→Galaxy S`、`iPhone 17→iPhone 17` |

归组口径（产品树呈现层拍板，不影响任何匹配键）：
- **多系列品牌按产品线成组，系列名不带代际**：S25 与 S26 同在「Galaxy S」，折叠 Fold/Flip
  同在「Galaxy Z」，代际区分留在型号层；
- **少系列品牌（苹果）按代际成组**：iPhone 17 / iPhone 16 各自成系列；
- **纯数字命名线标「数字系列」**（Redmi 数字系列），字母/名字线用裸产品名（Galaxy S、HONOR X）；
- **未命中回退型号名本身**（型号即系列）；我司未命中前缀表回退型号名首词。

兜底行为：数据包导入**不校验 series**——内部系统不填也不会拒包、不丢数据，但产品树
第三列会退化成「一型号一系列」（树变长）。建议按上表填齐。

注意：**系列只进呈现层，不进任何匹配键**。PSI 销量 join（§3.3）到 `model_id + cat1/cat2`
为止，与 series 无关；对标矩阵匹配也按型号，不按系列（矩阵行里的「系列」写法是解析糖）。

### 2.4 同类「源表没有、产出时派生」的字段一览

DimProduct 里除了 §2.1 的拆列，还有几列同样不来自 offer 原表——**v3 原表模式下全部
由 offerIngest 在导入时自动派生**（系列走配置表规则，见 §9）；v1/v2 路线由内部系统产出时补齐：

| 字段 | 来源 | 缺省行为 |
|---|---|---|
| `series` | §2.3 两张规则表 | 树第三列退化为型号即系列，不丢数据 |
| `tier_code` / `tier_by_country` | 价格分档（按 ref_price 分位段） | 档位筛选失效 |
| `ref_price_usd` | 各国均价基准 | 分档与对标便宜对便宜配对失效 |
| `launch_date` / `first_week` / `last_week` | 首末采集周推导 | 时间轴型号生命周期标注缺失 |
| `countries` | 该 SKU 实际有价格事实的国家集合 | 树按国家过滤失效 |

对标矩阵 `dim_benchmark` 与型号别名（我司侧 `model_aliases` 采集清洗、PSI 侧
`salesProductAliases` §4.6）是另外两条独立通道，见 §5 dims 与 §4.6。

## 3. PSI 表（销量侧）契约

源表：PSI 周表（Product SKU 拆列 + QTY 按 Product+Category1(+Category2)+PeriodID 汇总后）。

### 3.1 源列 → 数据包 `sales[]` 行（canonical 形态）

| PSI 源列 | canonical 字段 | 类型 | 说明 |
|---|---|---|---|
| Management Country/Region | `country` | string | 国家码/中文国名/英文国名均可，§4.2 归一 |
| Product | `product` | string | 型号名；对不上的挂 §4.6 别名表 |
| Category1 | `category1` | string \| null | 手机/平板=存储；穿戴=表盘；音频=null |
| Category2 | `category2` | string \| null | 平板=屏幕；其余=null |
| PeriodID | `periodId` | string | **YYYY0WW**（`2026043`）；兼容 YYYYWW |
| QTY | `qty` | number | 台；≤0 或非法行计入 skipped |

```jsonc
// sales 数组元素（PSI 源行原样承载，应用导入时归一）
{ "country": "R国", "product": "Watch 6", "category1": "42mm", "category2": null, "periodId": "2026043", "qty": 2577 }
```

### 3.2 应用内解析结果（自动，无需内部系统做）

```jsonc
// FactSalesWeekly：同键（国家×型号×cat1×cat2×周）多行自动求和
{ "week_id": "202643", "country_code": "RU", "model_id": "own-huawei-watch-6", "cat1": "42mm", "cat2": "", "qty": 2577 }
```

### 3.3 匹配键（join 语义，销量只到 Category1+Category2 粒度）

| 产业 | join 键（PSI 侧 → 内部侧） |
|---|---|
| 手机 | (Product, Category1, PeriodID) → (model_id, cat1=存储, week_id) |
| 平板 | (Product, Category1, Category2, PeriodID) → (model_id, cat1=存储, cat2=屏幕, week_id) |
| 穿戴 | (Product, Category1, PeriodID) → (model_id, cat1=表盘, week_id)；Category1 空 = 型号级 |
| 音频 | (Product, PeriodID) → (model_id, cat1='', cat2='', week_id) |

覆盖与兜底（`dataModel/volume.ts`）：
- 数据包 `sales` 非空即全局切真实口径；**某型号某国存在任何销量行 → 该型号该国整模型走 PSI**
  （同维度不同 info 的配置共享同一销量 = Eason 口径）；
- 某型号某国完全没有销量行 → 该系列回落估算口径（不混口径）；
- 真实口径的销量周独立于价格采集周（有销量的周直接出柱，不要求当周有价格事实）。

## 4. 归一化规则（实现：`pricelens/src/dataModel/salesIngest.ts`，纯函数，单测 45 断言）

### 4.1 周期间
- `YYYY0WW`（7 位，第 5 位固定 `0`）→ `YYYYWW`（6 位，周补零）：`2026043 → 202643`、`2026005 → 202605`；
- 兼容已是 `YYYYWW` 的输入；周号 1–53 之外 = 该行 skipped。

### 4.2 国家（Management Country/Region）
- 国家码直接收（大小写不敏感）；中文国名按 dim_region（`R国`/`德国`…）；英文别名内置
  （Russia→RU、Germany→DE、Brazil→BR、South Africa→ZA、Saudi→SA、UK→GB、UAE→AE…29 国）；
- 解不出 = 该行 unmatched（配置页会显式提示条数，补别名后重导）。

### 4.3 存储（Category1，手机/平板）
- 规范形 `12+512 GB` / `12+1 TB` / `256 GB`；`12+512gb`、`12+512`、`12+1T`、`8/128 GB` 全归一；
- 匹配键 = (RAM, ROM_GB) 数值对（`12+1T` ≡ `12+1 TB` ≡ 键 `12|1024`），单位无关。

### 4.4 表盘 / 屏幕
- 表盘：`42mm`/`42 mm`/`42MM` → `42mm`（两位数尺寸，不会吞存储数字）；
- 屏幕：`11.5'`、`11.5"`、`11.5寸`、`11-inch`、`13 in` → `11.5"`；PSI Category2 列语义已知，
  裸数字 `13.2` 也按英寸收。

### 4.5 型号解析（Product → model_id）
- 匹配键 = 小写 + 去空白/标点（NFKC，保留中日韩）：`Watch 6` ≡ `watch6`；
- **同键冲突我司优先**（`Watch 6` 同时命中华为与 Honor 竞品 → 归我司；PSI 是华为内部销量）；
- 解不出 = unmatched。

### 4.6 别名表（数据包 `salesProductAliases`）
- `Record<PSI 原文, 内部 model_name>`，如 `{"MatePad Pro 2026款": "MatePad Pro 2025"}`；
- 内部系统第一次接真实数据后，把 unmatched 明细对到这里重导即可。

## 5. 数据包（`pricelens-data-pack`，单文件 JSON，v1/v2/v3 三代兼容）

**v3 原表模式（2026-11-18，推荐）**——只装原样数据，派生全部在应用内：

```jsonc
{
  "kind": "pricelens-data-pack",
  "v": 3,
  "generatedAt": "2026-11-18T...",
  "offers": [ /* §2 offer 原样行（中文双语表头或拆列形态），唯一必填数据段 */ ],
  "sales": [ /* §3.1 PSI 源行，可整表原样倒入 */ ],
  "salesProductAliases": { /* §4.6 可选 */ },
  "monthly": [ /* 可选，ZA 月度 */ ]
}
```

导入链路（v3）：`applyDataPack` 读配置表五键（§9）→ `offerIngest.buildFromOffers`
归一派生（列名归一→拆列→穿戴升级→去重→汇率自愈→维表/事实/系列/分档构建）→
编码成事实列式包 → 与 v2 同管线置换提交。诊断三件套：数据卡「原表归一」条
（行数→事实行、剔除明细、自动修复明细）+ 销量 unmatched 黄条 + 「用当前配置表
重新派生」按钮（重跑归一，配置改后一键生效）。

**v2 规范化包（内部系统产全部维表的高阶路线）**：

```jsonc
{
  "kind": "pricelens-data-pack",
  "v": 2,                          // v1（无销量段）仍可导入，销量视为空 → 估算口径
  "generatedAt": "2026-11-17T...",
  "dims": { "region": [...], "product": [...], "channel": [...], "time": [...],
            "fx": [...], "promo": [...], "benchmark": [...], "tier": {...} },
  "factPackB64": "...",            // 价格事实列式包（gzip+base64，格式不变）
  "monthly": [...],                // ZA 运营商册子月度事实（不变）
  "sales": [ /* §3.1 PSI 源行，可整表原样倒入 */ ],
  "salesProductAliases": { /* §4.6 可选 */ }
}
```

导入链路（稳定版已具备，2026-11-14 建，本轮扩 v2）：配置页「导入数据包」→ 结构校验
（先解码校验后整体提交，失败不污染内置）→ 维表/价格/销量原位置换 → IndexedDB 持久化 →
刷新后两段式启动载入。诊断三件套在配置页数据信息卡：
- `销量行 N`（解析成功的事实行数）；
- unmatched > 0 → 黄条「N 行因国家/型号名未匹配被丢弃（可修 salesProductAliases 别名后重新导入）」；
- skipped（周期/QTY 非法）条数并入同一提示。

## 6. 迁移操作手册（内部系统 → 真实数据）

**路线 A（推荐）：内部系统倒原表 → v3 原表模式包 + 配置表**
1. 内部系统把 offer 明细导出为 JSON 行数组（列名原样，双语表头/同义列都收）、
   PSI 周表按 §3.1 导出 → 组装单文件：

   ```jsonc
   {
     "kind": "pricelens-data-pack",
     "v": 3,
     "generatedAt": "2026-11-18T...",
     "offers": [ /* offer 明细行原样，一行一条采集明细 */ ],
     "sales": [ /* PSI 源行原样，§3.1 */ ],
     "salesProductAliases": {},  /* 可选 */
     "monthly": []               /* 可选，ZA 月度 */
   }
   ```

2. 稳定版配置页「导入数据包」→ 看数据卡计数与「原表归一」诊断条
   （剔除行数/自动修复明细）→ 量价页量带悬停应标「PSI 真实销量」（若有 sales）；
3. 配置页「下载配置表模板」→ 在新五页签里维护规则（系列规则/型号别名/
   对标矩阵/分档阶梯/大促档期，schema 见 §9）→「导入配置」；
4. 改过别名/矩阵/阶梯/档期后，点数据包区「用当前配置表重新派生」重算
   （系列规则即时生效，无需此步）。

**路线 B（高阶）：内部系统产规范化包（v1/v2）**
内部系统按 §2.2/§5 自建维表与事实列式包——适合批产成熟后；结构与校验不变。

**验收清单（两边对完即收工）**

## 7. 口径决策记录（谁拍的、为什么）

1. **穿戴表盘=配置维度**（Eason 2026-11-17 (a)）：从 color 字段提升为 romram/cat1；
   唯一尺寸型号不作维度（GT 6 Pro 特例同一规则）；
2. **销量不摊分**（Eason 原话「不同 info 的销量视为一致」）：同维度配置共享整份销量；
3. **我司优先解析**：PSI Product 撞名竞品型号时归我司（PSI 是华为内部销量）；
4. **整模型切换口径**：型号×国家有 PSI 行即整模型真实，避免同一系列一半估算一半真实；
5. **YYYY0WW 只在入口归一一次**：应用内一律 YYYYWW（dim_time 同键）；
6. **cat1/cat2 与 romram 双轨**：显示文案不动（平板仍「11.5\" 12+256 GB」），匹配走结构字段，
   未回填字段自动回落解析（新旧数据包都能跑）；
7. **原表没有、后加的内容全部配置表化**（Eason 2026-11-18）：内部系统只倒原表，
   系列规则/型号别名/对标矩阵/分档阶梯/大促档期走配置 xlsx 五页签（§9）；
8. **系列读时生效**：改系列规则立即反映在产品树（effectiveSeriesOf 读时派生），

## 9. 配置表五页签（2026-11-18 新增：原表没有、后加的规则全走配置）

配置页「下载配置表模板」即含新页签；「导入配置」个人级生效（localStorage），
导出/导入与既有八页签同一文件。**2026-11-18 二轮拍板（Eason）：系统前端零内置、
全部显性配置**——系列规则/分档阶梯/型号别名的规则数据不编译进应用，配置表是
唯一规则源；**空页签 = 无规则（诚实降级）**。交接包配置表已预填全量规则
（系列 133 条 / 矩阵 950 条 / 阶梯 6 产业 / 档期 66 条 / 别名 1 条）。

| 页签 | 列 | 生效时机 | 空表行为 |
|---|---|---|---|
| 系列规则 | 品牌、规则、系列名 | **读时**（改完立即生效，无需重导数据包） | 型号即系列（我司=型号名首词、竞品=型号名本身） |
| 型号别名 | 品牌、原始型号、目标型号 | v3 apply / 重新派生 | 无别名 |
| 对标矩阵 | country_code、own_model_id、own_romram、competitor_sku_id、sort、note | v3 apply / 重新派生 | 恢复数据层矩阵（v3 包 = 无矩阵） |
| 分档阶梯 | 产业（phone/tablet/wearable/audio/iot/pc）、阶梯（逗号 USD 价格点） | v3 apply / 重新派生 | 该产业无档位（'—'） |
| 大促档期 | country_code、促销名、开始日期、结束日期、深浅（浅/中/深）、平台（逗号，留空=全部） | v3 apply / 重新派生 | 无大促带 |

填写细则：
- **系列规则**：`规则` 默认按型号名**前缀**匹配（同时匹配归一键——写 `matepadpro`
  也能命中 MatePad Pro 2025）；`re:` 开头 = 正则（锚定树上显示的型号名开头，
  如 `re:^16 Pro`）；**系列名可写 `{n}/{w}`** 引用正则第 1 捕获组（`iPhone {n}`
  一条覆盖任意代际）。我司竞品同一张表，品牌列区分（`HUAWEI` = 我司）。未命中
  规则的型号走兜底：**我司=型号名首词、竞品=型号名本身**（型号即系列）。
- **型号别名**：`原始型号 → 目标型号` 按「品牌 + 归一键」匹配（归一 = 小写、去
  品牌词/连接词/网络词，`华为 MatePad SE 11` ≡ `MatePad SE 11`）。价格侧型号合并
  与 PSI 销量解析共用此表。
- **对标矩阵**：有数据行 = **整体替换**矩阵层（v3 包无内置矩阵时它就是唯一矩阵源）；
  人工裁定（配置页编辑/看板手动改组）不受影响，语义不变。`competitor_sku_id`
  须为当前数据中真实存在的 SKU id。
- **分档阶梯**：一行一个产业，价格点升序逗号分隔（如 `200,400,600,800,1000`），
  落档规则 `<200 / 200-400 / … / 1000+`。
- **大促档期**：日期 `YYYY-MM-DD`；深浅缺省按 `深`；平台留空 = 全平台生效。

导入诊断：配置页「导入配置」预览逐页签显示行数；校验失败整份拒绝（正则无效/
阶梯非正数/档期日期倒挂等都会明确报行）。
