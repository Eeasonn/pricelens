## 1. 交付方式（2026-11-23 起三条路径，按优先级）

- **方式 A（首选）服务器文件投递**：把 offer 表存为 `data/offers.csv`、PSI 表存为
  `data/sales.csv`（或 `sales.xlsx`），放进部署目录 `data/` 即完成——服务器检测到
  文件变化自动重派生（约 10-60 秒），前端 ~15 秒自动刷新。**每周替换 = 换这两个文件。**
- **方式 B 配置页直连**：部署包 `data/config_tables.xlsx`（四页签）业务侧回填后原位替换。
- **方式 C（兼容）v3 JSON 组装**：按下述规范组装 `pricelens-data-pack` JSON，配置页
  「导入数据包」上传——上传后自动拆写为 data/ 下 CSV（与方式 A 殊途同归）。

### 方式 C 的 JSON 结构

一个 JSON 文件（建议命名 `pricelens-datapack-<日期>.json`），结构：

```jsonc
{
  "kind": "pricelens-data-pack",
  "v": 3,
  "generatedAt": "2026-11-18T12:00:00Z",
  "offers": [ /* 街价 offer 明细，一行一条采集记录，字段名原样 */ ],
  "sales":  [ /* PSI 周销量，一行一条 */ ],
  "salesProductAliases": {},  // 可选，首次导入后按提示补
  "monthly": []               // 可选，暂不使用（ZA 运营商月度专用）
}
```

`offers` 与 `sales` 是仅有的两个数据段。**字段名保持你们源表的原样**（英文新格式、
中文旧格式、双语表头、同义列名 PriceLens 都能自适应，见 §2），字段值也保持原文——
不要预清洗、不要拆列。

## 2. 街价 offer 明细（`offers` 数组）

### 2.1 列名（自适应，以下任一形态都收）

PriceLens 内置了列名归一：双语表头（`时间周期\nperiod` 取换行前的中文）、括注
（`汇率(1USD=本币)` → `汇率`）、以及以下同义列映射：

| 规范列名 | 可接受的同义列名 |
|---|---|
| 时间周期 | 周期、日期（或规格拆列形态的 `tech_date`） |
| 型号 | 商品型号、型号名称 |
| 型号规格 | 规格、商品规格 |
| 国家/地区 | 国家地区、国家、地区 |
| 平台 | 电商平台、渠道平台 |
| 店铺类型 | 渠道类型 |
| 店铺名称 | 卖家名称 |
| 显示店铺名称 | 展示店铺名称 |
| 采集时间 | 抓取时间、采集日期 |
| 网址链接 | 网址 |
| 截图命名 | 截图 |
| 是否组合销售 | 是否组合 |

**已按业务规格拆好列的表也直接收**：含 `Category1 / Category2 / info / tech_date`
列的表会被识别为「拆列形态」，直接采用拆列结果（不再自行拆 `型号规格`）。

### 2.2 必备列（缺任一将拒绝导入并明确提示缺哪个）

```
时间周期（或 tech_date）  品类  品牌  型号  国家/地区  平台  店铺类型  货币  汇率
```

其余列缺省时 PriceLens 补默认值（店铺名称→"—"、价格→空、网址/截图→空），
不阻断导入，但明细表的相应列会显示"—"。

### 2.3 字段值细则

| 列 | 要求 | 说明 |
|---|---|---|
| 时间周期 | 采集日期（`2026-10-21` 或带时间的 ISO 串）或周号（`2026043`/`202643`） | 日期自动归到所在 ISO 周的周三锚；`YYYY0WW` 七位自动转 `YYYYWW` |
| 品类 | 手机 / 平板 / 穿戴 / 音频（英文 smartphone/tablet/wearable/earbuds/iot/pc 也收） | 未识别品类的行会被剔除并计数 |
| 品牌 | 源表原文（如 `HUAWEI`、`XIAOMI`、`SAMSUNG`、`APPLE`） | 品牌 = HUAWEI 识别为我司产品 |
| 型号规格 | 原文整串，**不要拆**（如 `12+512 GB Black`、`11.5"/WIFI/8+256 GB Black`、`46mm GPS Black`） | 拆列规则见 §4，引擎自动做 |
| 国家/地区 | 中文名（`R国`、`德国`、`沙特`…）或英文/国家码 | 29 国映射内置；未识别国家行剔除并计数 |
| 平台 | 源表原文（`DNS`、`OZON`、`MVM`…） | 别名归并内置（`mvm`→`Mvideo` 等） |
| 店铺类型 | `平台型零售商/平台第三方卖家/marketplace/跨境3p/官网` 或 `1P/3P/独立站` | 统一归到 1P/3P/独立站；无法识别按 3P |
| 货币 | 币种码（`RUB`、`PLN`、`EUR`…） | |
| 汇率 | **1 USD = N 本币**（如 RUB 给 80，不要给 0.0125） | 偶发倒挂行系统按币种中位数自校验自动取倒数；缺汇率行按（国家×周）中位数补 |
| 平台建议零售价-本币 / 平台成交价-本币 | 数值（本币） | USD 由系统按行内汇率折算 |
| 分期付款 / 促销政策 / 是否组合销售 | 原文（可选列） | **源表只有综合 offer 信息时**：整段原文填「促销政策」列即可（分期描述/赠品描述都塞这段），「分期付款」「是否组合销售」留空——系统自适应（列空 = 对应权益行不出，**不做虚假拆分**）；有独立列则按列给 |
| 是否组合销售 | `Y/N/TRUE/FALSE/是` | |
| 采集时间 | 任意常见日期时间格式或 Excel 序列数 | 明细表「记录」列的时间 |

## 3. PSI 周销量（`sales` 数组 / `sales.csv`）

### 3.1 行结构（**2026-11-22 拍板：7 列新口径**，周粒度；Product 与 SKU 分列）

源表列名固定英文（PSI 系统导出原样即收）：

| # | 源表列 | 说明 |
|---|---|---|
| 1 | Management Region | 管理大区（中东非/亚太/拉美/欧洲/欧亚）——国家上卷层 |
| 2 | Management Country/Region | 国家（中文全名/英文/两位码均收，如 `沙特阿拉伯`/`Saudi Arabia`/`SA`） |
| 3 | Product | **型号级**（`HUAWEI nova 13` / `MatePad 11.5吋 2023`，不含规格） |
| 4 | Product SKU | **SKU 级原文**（含规格/颜色/渠道串，如 `HUAWEI nova 13 12GB+256GB 星耀黑 双卡 公开渠道版 英规`）——匹配表人工回填的键② |
| 5 | Period ID | **周 `YYYY0WW`**（`2026043`）；兼容 `YYYYWW`。2026-11-22 拍板：**周粒度** |
| 6 | PSI Type | 销量口径（当前 `周度`） |
| 7 | QTY | 台；≥0；同键多行自动求和；非法行计入 skipped |

兼容形态：旧 6 列（`country / product / category1 / category2 / periodId / qty`）继续收。
行业未知时按 Product 串前缀自动识别（MatePad→平板、WATCH/Band/手环→穿戴、
FreeBuds/FreeClip/FreeLace/FreeArc/Eyewear→音频、其余→手机）。

**粒度与口径**：QTY 按 `国家 × Product × Product SKU × Period × 口径` 承载（同键求和；
颜色等次级信息不进销量 join 键）。销量与街价的 join 由 **map_product 统一匹配表**
完成（offer 侧键 = 国家+产业+品牌+型号+SKU；PSI 侧键 = Product+SKU）——
`config_tables.xlsx`「匹配表(补录)」页签是人工核对与补配对的工作台。
**某型号某国有任何真实销量行 = 该型号该国整体走真实销量口径**；无销量行的型号回落
估算口径（两口径不混算，与既有拍板一致）。真实销量物理化于 `data/pricelens.db` 的
`fact_sales` 表（周粒度），平板可按柔光/非柔光（category3）拆分。

## 4. 系统自动完成的加工（你不做，仅供理解）

- **拆列**：手机=存储进维度1；平板=存储+屏幕双维度（WiFi/LTE 并入颜色）；穿戴=表盘
  升维度（同型号 ≥2 个尺寸才作维度，唯一尺寸型号不作维度——GT 6 Pro 口径）；
  音频=只到产品；颜色等其余信息进版本胶囊。
- **系列归组**：产品树第三列（Mate / WATCH GT / Xiaomi 数字系列…）**全部来自配置表
  「系列规则」页签**（系统零内置规则——不导配置表则型号即系列）。
- **型号正名与别名**：同 (品牌，归一键) 取最高频原文；品牌词从型号名剥离。
- **分档**：按配置表「分档阶梯」页签落档（该产业无行 = 无档位）。
- **解析字典**：国家/平台/店铺类型/品类的原文识别用出厂词汇表，可被配置表
  C3 四页签（国家别名/平台别名/店铺类型别名/品类映射）全量替换。
- **渠道维 / 汇率表 / 时间维 / 地区维**：全部从 offers 行自动聚合。
- **对标竞品**：来自配置表「对标矩阵」页签（业务侧维护，见 §5）。
- **数据清洗**：同键重复行保留同刻最低价；>20,000 USD 异常价剔除；汇率倒挂自愈。

## 6. 导入与自检（组装完交给业务侧后，按此验收）

1. **推荐走服务器模式**（2026-11-18 前后端分离）：业务侧双击
   `PriceLens-Server/启动PriceLens.bat` → 浏览器 localhost:8321 → 配置页
   「导入数据包」选你的 JSON——**全量包（117MB 级）直接可导**（服务器 Python
   引擎派生 + SQLite 落库，约 10-60 秒；单文件模式仅支持 ≤~50MB）。
2. 配置页数据卡应显示：`服务器数据包（v2 · Python 引擎派生）`、事实周行数 ≈ offers
   行数、SKU 数、「原表归一」诊断条（剔除行数与原因明细，应与你了解的数据质量一致）。
3. **2026-11-23 增订验收**：`data/pricelens.db` 可查 `fact_sales`（周销量物理化，行数≈
   PSI 行数去重后）与 `map_product`（匹配状态 matched/offer_only/psi_only 分布）；
   服务器自动重派生后 `/api/ping` 的 meta.sales 应等于 PSI 行数。
4. 若出现黄条「销量归一提示：N 行因国家/型号名未匹配被丢弃」→ 把未匹配型号清单
   给业务侧在 `config_tables.xlsx` 匹配表补配对（或 `salesProductAliases`）后重导。
4. 抽查验收（业务侧执行）：
   - 换不同存储配置，量价页量柱随存储分开（手机）
   - 穿戴型号多尺寸出多条量柱、唯一尺寸型号（GT 6 Pro 类）走型号级
   - `2026043` 的销量出现在 2026W43
   - 音频量柱 = Product+周期汇总值（颜色不拆）
   - 量带悬停标「PSI 真实销量」（有 sales 段时）

## 7. 常见问题

- **问：要不要把 color_size 拆成三列再给我？** 答：不用。给原始整串即可（新格式
  `color_size` 列 / 旧格式 `型号规格` 列），系统按产业自动拆（§4）。
  **2026-11-22 拍板：PSI 表给 7 列（Management Region / Management Country/Region /
  Product / Product SKU / Period ID / PSI Type / QTY），Product 与 SKU 分列、周粒度。**
- **问：汇率用哪天的？** 答：源表自带的「汇率」列（采集当时），逐行折算；不要统一成
  月末汇率。缺汇率的行会被（国家×周）中位数补齐。
- **问：型号名和采数口径不一致怎么办？** 价侧：同归一键自动合并；对不上的型号在
  `salesProductAliases` 补别名。PSI 侧：`salesProductAliases` + 业务侧「型号别名」配置表。
- **问：周度增量的做法？** 每周重出全量 JSON 再导一次即可（导入是整体置换，幂等）；
  也可以只给增量行追加进 `offers` 数组后整体重导。服务器模式下全量包直导无压力。
- **问：全量包多大能导？** 服务器模式（PriceLens-Server）无实质上限（117MB 级
  实测口径约 10-60 秒）；单文件模式上限约 30-50MB（浏览器内存天花板）。
