## 一、高影响问题（按影响排序）

### 1. 「选中」语义一屏三套、子导航无当前态（跨页一致性 · 影响定位能力）
- **位置**：04 配置页子导航（竞品对标/默认店铺/异常守卫/上一代关系/汇率/大促日历）；10 情报中心模块 chip；08 大盘右上分段控件；05 Agent 抽屉上下文 chip；04 品类分段控件。
- **观察**：① 配置页六个子导航全部同款蓝链接，当前项「竞品对标」无任何区分（无下划线/底色/字重差）——同屏顶栏「配置」反而用墨色+下划线做了正确示范；② 情报中心四枚模块 chip 全部穿着 select-soft 蓝底选中装，「可用」就发选中色，没有一枚表示「当前在看哪节」；③ 大盘分段选中只靠白底浮起，文字同色；④ Agent 抽屉「当前页·配置」chip 是唯一符合 filter-selected 契约的实现；⑤ 配置页品类分段又是第四套（灰轨白底墨字）。
- **依据**：DESIGN.md components 只定义一种 filter-selected（select-soft 底 + select-soft-ink 字）且要求「Reuse their … selected-state language」；「Blue is reserved for links, selected controls, focus」——所有锚点同时穿选中色时，选中不再可读；导航必须指示当前位置（成熟准则）。
- **建议**：收敛为一种选中语言（建议以 Agent 抽屉 chip 为基准）：配置页当前子导航用墨字+短下划线（与顶栏同语法）或 select-soft 态；情报中心模块 chip 常态=白底蓝字链接，仅当前节用 select-soft；大盘分段选中改 select-soft 底+深蓝字。

### 2. 大盘页与全局上下文三重矛盾且页面不表态（信任问题）
- **位置**：08 顶部上下文条（拉美/墨西哥 · 平板 · MatePad Pro Max）vs 页内说明（「阿联酋」）vs 分段控件（智能穿戴）vs 时间控件（周 2026W39→46）vs 图轴（2025-08→2026-08 月度快照）。
- **观察**：行业、地区、时间三个维度同时与可见的全局筛选冲突，页面无任何衔接说明（对照：09 预测页对同类冲突有明示「全局筛选仅作上下文展示，不改变本页计算口径」）。
- **依据**：DESIGN.md「Scope controls answer *what data?*」+ evidence-first——失效的 scope 控件比没有更糟。大盘页是 GFK 锚定的模拟演示面（badge 已有），但演示不豁免口径表态。
- **建议**：在「模拟数据」badge 行补一句口径衔接（如「演示口径：阿联酋 · 智能穿戴 · 月度快照，与左侧全局筛选无关」）；或让分段切换同步改写上下文条产业字段；粒度/时间控件若不驱动本页则置灰并注明。

### 3. DESIGN.md 未跟上量价页「合并单图」拍板（文档债，实现本身是最新决策）
- **位置**：02 量价走势页 vs DESIGN.md Charts 节。
- **观察**：2026-11-10 Eason 已拍板「销量和价格成本不分两个图，同一绘图区加成本细线」（de7b98d 已实现：柱贴绘图区底缘、右轴销量三档刻度、成本细线常驻）；但 DESIGN.md 仍写「Volume is drawn as its own band under the price layer」「销量 台 badge 在 volume band 顶部左侧」「owner pill 在 volume 标题之下」——规范与实现脱节，任何按文档执行的 Agent/评审都会把新形态判为违规。评审者同时指出合并结构的真实代价：成本细线（左轴）从销量柱（右轴）中部横穿。
- **依据**：DESIGN.md 自身的 deliberate exception 机制（「record a deliberate exception in the relevant surface brief」）未被走完。
- **建议**：① 把合并单图作为已拍板决策正式写进 DESIGN.md Charts 节 + `.impeccable/surfaces/` 对应决策文件（含右轴刻度、「销量 台·模拟」caption 位置、owner pill 新位置）；② 顺手处理成本线与柱的几何穿插（错层或避让）。

### 4. 颜色语义局部松动（四处，均违反「颜色永不单独承载状态」的成文语义）
- **位置与观察**：
  - 07 预警「平台价差」类型 chip 为紫色（取样 ≈#8a5fd8/#6d28d9 一族，两处一致）——不在任何文档化色板，撞 DESIGN.md「Do not add AI-purple」红线（虽是数据分类色非装饰色，但未经 token 文档化）；
  - 07 收件箱「待处理」状态 badge 与「调价」类型 chip 同款蓝药丸（同为 ≈#e8f1ff/#0053c2）——同一行两个维度无法区分；
  - 09「SI 未全部确认（待确认 12/12）」红字 + 07「档位间距 低于触发」红字——红色被用在门禁/触发常态提示上（09 处红字紧邻琥珀「模拟数据」badge，双警示色相邻稀释层级；注：DESIGN.md AgentShell 节允许预警卡复用 error 语义，「低于触发」属边界情形，「SI 未确认」则明显更宜琥珀/mute）；
  - 10 情报中心「示例数据」徽章用 select-soft 蓝而非琥珀/中性（卡内「（示例判断）」用的 warning-ink 才是对的）。
- **建议**：紫色类型色要么收敛到已文档化家族、要么在 tokens.ts/DESIGN.md 正式补类型色 token；状态列改中性样式（白底+hairline+mute 字）把蓝让给选中/链接语义；「SI 未确认」改 warning-ink；「示例数据」改琥珀或 mute。

### 5. 预警中心首屏被 KPI 砖稀释、计数四处重复
- **位置**：07 顶部两排统计砖（约 320px 高）+ 悬置的「让 Agent 解释最新预警」按钮。
- **观察**：「3」同时出现在「3 条最新预警」「3 待处理」、看板「全部 3」chip、收件箱副标四处；「观察中 0 / 已解决 0 / 数据陈旧 0」零值砖长期占位；收件箱 448px 才开始，监控看板被挤出 900px 视口。
- **依据**：DESIGN.md 北极星「restrained, high-density analysis」。
- **建议**：两排砖并为一排紧凑状态行；零值缩为小徽标；「让 Agent 解释」并入收件箱卡头右侧。

### 6. 图表双页组件语言漂移（价格走势 vs 量价走势）
- **观察**：① 图例——01 浮动系列胶囊+右上复选框，02 新增顶部图例行且保留浮动胶囊+轴 caption，成本/价格/销量在 02 内各被标注 2–3 次；② 数值格式——悬停卡「2,244」逗号千分位 vs 图上「2 244」空格千分位（formatPrice 应只有一种）；悬停卡头只有「08-26」无周 ID，与全页「2026Wxx」语言脱节；③ 插值——02 华为价格线末段是平滑 U 形曲线，01 同产品同周是阶梯线（曲线强加「下滑回升」叙事）；④ 「时间轴同步」胶囊只在 02 出现且文字竖排两行、蓝描边抢眼，01 时间轨左侧为空。
- **依据**：DESIGN.md「Reuse their height, border, focus, and selected-state language」+「formatPrice rules」；同图同系列统一插值是成熟准则。
- **建议**：图例二选一（建议保留浮动胶囊+轴 caption，撤顶部图例行或反之）；数值全收敛 formatPrice；卡头改「2026W35 · 08-26」双标识；插值统一阶梯；时间轴同步两页同位+单行文案。

### 7. 悬停明细卡的信息缺口与浮层秩序
- **位置**：06 悬停卡（08-26）。
- **观察**：① 产品列只有 Apple/Samsung 两行、价差列全「——」——经语境核对：该周（W35）华为基准在 MX 尚无数据，属数据诚实呈现；但用户侧「为什么没有基准/价差」无从得知，缺一句「基准当周无数据」的状态说明；② 一条全宽虚线（y≈1.42K）不标数值、不挂图例，与游离的「销毛利率·模拟」胶囊互不关联，且与「拖动选择时间段」提示叠成三层浮层、间距仅约 13px；③ 右缘终点标签「1 115」与「1 042」字面相触，同区域还挤着 1 159/1 326 与多条虚线桥；④ Samsung 行 RRP 4,064 vs 折后 1,061（≈−74%）不合品类常态——与已知挂账「rrp==price 脏行守卫靠 ref_price 兜底待议」同族，建议一并核对字段与币种映射。
- **建议**：基准缺席时卡内显式说明；毛利虚线与胶囊互相锚定（胶囊贴线左端+数值）并纳入图例体系；终点标签做避让；RRP 脏值核对后在明细中显式标注数据状态。

### 8. Agent 抽屉与情报中心的文案减法
- **观察**：① Agent 输入框下方「平台预设网关 · GLM 叙述 · 本地兜底」——实现名词写给业务用户；② 上下文条同一机器串出现两遍（可读 ID 与 SKU slug 前缀逐字重复）；③ 情报中心同一筛选范围一屏写两遍（副标题行 + 「联动全局筛选」行相距 60px），且页面一图三名（INTELLIGENCE CENTER / MX 眉题 + 「GTM 情报工作台」+ 导航「情报中心」）；④ 渠道占位卡「来源：待接入」却挂蓝色「展开溯源 →」链接——无源之链；「待接入」在一个模块里出现四次。
- **依据**：DESIGN.md「Missing evidence is stated … rather than represented by a decorative placeholder」+ 界面文案去工程词。
- **建议**：删实现细节行（如需披露收进帮助 tooltip）；机器串留一处（显示名+短指纹）；范围只在「联动全局筛选」行出现一次；待接入时不渲染溯源链接；「待接入」保留 chip+来源行两处。

### 9. 配置页「矩阵直配只读」有表达、缺解释
- **位置**：04 「矩阵」孤词徽章、chip 内矩阵小标、27 个禁用编辑按钮。
- **观察**：禁用视觉成立，但全页没有一句「为什么不可编辑」；「矩阵」二字单独悬浮，首次来的数据管理员只能猜；禁用标签 ≈#b8b8b8 对浅灰底对比度 ≈1.6:1 偏虚。
- **建议**：给矩阵徽章与禁用编辑加同一句说明（tooltip 或卡头 12px mute 行）：「竞品关系由对标矩阵统一下发，此处只读」；禁用标签加深一档（mute）+ not-allowed 光标。

### 10. 大盘图例可分性硬伤 + 小项合并
- **观察**：① 08 图例 HONOR ≈#4497c7 与 GOOGLE ≈#418faf 色相几乎相同，而 GOOGLE（0%→63%）恰是摘要句的叙事主角，柱内 44%/63% 大段难以归属；WHOOP/GARMIN 同族绿也偏近；② 图例「`<OTHERS>`」代码式写法应为「其他」；柱顶万台数字行无就近单位标注；③ 09 折叠条「· 数据与操作」前导圆点读作标点残留；④ 导航不一致——预警/配置页顶栏无「情报中心」入口，大盘/预测页有；且大盘/预测页对当前所属区块无选中标记（预警页有加粗+下划线）；⑤ 02 销量柱 5 根只标了 3 根数值；02 owner pill 把产品名截成「Mate…」而周围大量留白，「本组对比 (2) →」mute 灰弱似说明文字；⑥ 05 抽屉输入框焦点边框是深灰墨色而非 select-accent 蓝、抽屉顶边 2px 蓝亮线未文档化（若为「Agent 激活」信号应补记 DESIGN.md）；⑦ 04 模型分组标题条底色 (244,248,255) 不在文档色板，需对 tokens.ts 核对补记或改落既有色。
- **建议**：GOOGLE 换可分色相或段内文字标注；其余逐条小修。

## 二、待核对项（评审者无法从截图定责，主 Agent 语境标注）

1. **同一产品两页线形不一致**：01 价格走势页华为红线只覆盖 2026W42+，02 量价页同产品红线却从约 W36 起有完整走势且 W37 峰值 1,405（01 里 1,405 是 Samsung W37 蓝 spike）。可能是取价渠道/代表版本/聚合口径差异，需核对——若两页对同一产品同一周给出不同价格，属高优先级数据呈现问题。
2. **量价页左侧大空白**：评审者判为「渲染/过滤缺陷」，语境核对为 MX MatePad Pro Max 2026-W42 前后上市的数据覆盖现实（01 华为线同样只在右缘），符合「缺采不造点」契约；但「稀疏覆盖时是否收缩时间域/给空态提示」值得作为设计议题讨论。
3. **Samsung RRP 4,064 脏值**：与已知挂账 rrp==price 同族，见上文第 7 条④。

## 三、符合项（勿在后续修改中修平）

- 品牌图色纪律：Apple 黑/华为红最强线宽/Samsung 稳定蓝；蓝色未作数据色；销量柱用华为红系。
- 「图上只留数据与控件」铁律成立，长文案全部下沉明细卡/摘要/事件行。
- 数据状态文字标识全面落实：模拟数据 badge（08×2、09 琥珀）、03「真实·有延迟」诚实空值、情报中心「示例数据/待接入」逐处可读。
- 09 预测主图对图表契约执行度最高（华为填充/预测描边/右轴价格/琥珀库存修正/五项图例/文字标注），可作其它图的基准。
- 表面秩序：中性面板+白卡+1px hairline+克制阴影，无渐变/发光/AI 紫装饰；圆角纪律良好；配置页整页共享稳定左缘锚线，27 行高密度列表无散排。
- 悬停锚定方式正确（十字线+端点圆点，卡片贴锚不遮锚）；周环比 chip 带显式「+」号，方向不由颜色单传。
- 01 浮动系列胶囊挂系列起始价位、可不看图例对线——好做法，只需加标签防碰撞。
- Agent 抽屉复用壳层 token，无第二套聊天视觉；「当前页·配置」chip 是最标准的 filter-selected 实现（可作收敛基准）。
- 诚实的主操作策略：空态不造假 CTA；「（固定样本）」标注严谨。

## 四、整体印象（三评审者共识）

一套 token 纪律很强、克制高密度的企业工作台，基础扎实、无装饰化倾向。最大的短板不在风格而在**状态语义的一致性与口径诚实性**：选中态一屏多套、大盘页三维矛盾不表态、文档与最新拍板脱节；其次是颜色语义的局部松动与文案层面的减法（实现细节外泄、重复串）。均为局部修正，不需要动骨架。
