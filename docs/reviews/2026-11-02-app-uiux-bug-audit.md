证据来源：当前工作树源码、`PRODUCT.md`、`pricelens/DESIGN.md`、页面 surface brief、当前本地路由的 AX 树和已有静态回归结果。

两份用户提供的产品设计 `.docx` 作为业务背景和术语来源；若其中的旧页面路径、旧测试路径或旧模型表述与当前用户要求、代码契约冲突，以当前用户要求和仓内交接规范为准。已同步修正交接文档中的旧测试路径，并把 Demo 历史段从“实际”改为“历史段（模拟）”。

## 已确认的 P1

### 1. 预测页 Agent 入口没有命中预测意图

- 复现：打开 `?p=forecast`，点击“让 Agent 解释”。
- 当前行为：按钮写入“解释当前简单版预测的关键假设、证据和风险”，但 `core.ts` 的预测判断只匹配“量价预测、价格下调、价格上调、预测情景”等词。
- 浏览器复现：在 `?p=forecast` 点击按钮并发送后，Agent 返回“已按当前页面整理 3 个产品的价格结果”，卡片标题是“当前页面价格走势摘要”，没有预测假设、供给约束或情景结果。
- 结果：请求落入普通价格摘要，而不是预测解释。
- 位置：`pricelens/src/pages/ForecastPage.tsx:83`、`pricelens/src/agent/core.ts:145,372`。
- 修复：改成结构化 `forecast_explain` 意图；文本兼容分支至少补“简单版预测”。

### 2. Agent 预测数字与预测页数字不一致

- 当前 Agent 仍固定使用基准价格 499、基准需求 4,600、弹性 −1.85、供给上限 7,200。
- 预测页使用 `simple-demo-v1`、价格约 999、弹性 −1.70、周度可供量和事件因子。
- 位置：`pricelens/src/agent/core.ts:317-331`。
- 影响：用户会把两套数字视为同一模型，直接破坏证据可信度。
- 修复：Agent 只能消费预测页生成的 `ForecastSnapshot`，不能再次计算或保留旧常数。

### 3. 全局筛选器可变，但预测结果固定

- 页面仍显示可改变的国家、币种、产品和 Agent context chips。
- 计算固定读取 R国、直营电商、Pura 90 Pro、USD 的 Fixture。
- 位置：`pricelens/src/pages/ForecastPage.tsx:49-56,86-103`、`pricelens/src/pages/forecast/forecastFixture.ts:71-89`。
- 修复：接入 dataset registry；没有数据时显示空态。Demo 阶段若暂时锁定范围，必须锁定入口并把“固定演示范围”放在筛选器附近，而不能只放在页面脚注。

### 4. 历史“实际周”不是观测数据

- W1–W10 仅通过 `status='actual'` 标记，SO、需求和库存仍由同一预测公式计算。
- 位置：`pricelens/src/pages/forecast/forecastModel.ts:295-345`。
- 修复：增加 `observedSO`、`soStatus`、`dataStatus`，历史段显示观测值，模型输出单独显示；缺货周作为删失观测。

### 5. 页面把固定先验写成“模型学习”，并宣称 P50

- 位置：`forecastFixture.ts:109-149`、`ForecastKpiStrip.tsx:14`、`ForecastChart.tsx:139`、`CalculationPath.tsx:90`。
- 当前没有拟合样本、残差、置信区间或分位数校准。
- 修复：暂时显示“固定先验 / 待学习 / 模型点估计”；完成学习和校准后再显示 P50、样本量和区间。

## 已确认的 P2

### 6. 价格响应未实现一周滞后

数据规范要求调价后一周生效，当前 `forecastModel.ts:301-302` 使用当周价格。需要增加调价周测试和 lag kernel。

### 7. 促销 / 激励成本未进入利润链

`ForecastInputWeek` 没有 `incentive`，`weeklyGrossMargin` 直接用 SO × 单台销毛。完整 Fixture 接入后会高估促销场景的利润。

### 8. DOS 口径仍是当周需求

`forecastModel.ts:347` 使用当周无约束需求；完整数据规范要求滚动四周需求。促销周和事件周会出现口径偏差。

### 9. 周度主账没有 Sell-in 列

`WeeklyLedger.tsx:45-58` 展示了库存结果，却没有展示推动库存的 Sell-in，用户无法逐周复核库存恒等式。

### 10. 预测页的双入口是过渡实现

`PageHeader` 和 `ChartContentBar` 都能进入预测页。当前通过 `suppressCurrent` 避免两个 `aria-current`，视觉上仍有两个同名入口。等共享页头 WIP 收口后，应确定一个主入口。

### 11. 共享页头仍显示“情报中心（施工中🚧）”

位置：`pricelens/src/components/PageHeader.tsx:28`。情报中心已经可达，施工中文字会降低完成度，也会让 Agent 建议和真实入口之间产生不一致。应改为正式名称或明确的状态 badge。

### 12. Agent 卡片路由依赖文案正则

`AgentPanel.tsx` 的结果动作会根据 prompt 中是否包含“预测”来判断是否进入预测页。后续统一文案或引入 `forecast_explain` 意图时，如果只改显示文字而没有同步路由判断，会再次出现结果卡动作跳错页面。应让结果卡携带结构化 `action.target`，文字只作为展示。

### 13. 主动预警缺失价格可能显示为 `$0`

`AgentContext.alertRecords()` 当前对缺失价格使用 `0` 作为回退值，Agent 主动预警的摘要可能把“缺少价格”呈现成真实的零价。应保留 `null`，在 UI 显示“— / 暂无价格”，并在证据状态中说明缺失原因。

### 14. Agent 停止运行后审计事件可能不完整

`AgentContext.stop()` 会先递增 `runSequence`，随后 `catch` 分支因序号变化直接返回，因此运行时间线可能只有状态变更，没有追加 `run.cancelled` 事件和取消消息。若产品要求每次运行可审计，应在 stop 路径显式完成当前 run 的取消事件，再丢弃迟到响应。

### 15. overview / pricing 路由被静默降级

`PageContext` 将 `overview`、`pricing` 列入 `DISABLED_PAGES`，`setPage` 会把它们回退到 `dashboard`。如果旧链接、书签或 Agent action 仍指向这两个 page，用户看到的是另一个页面，却没有“入口已停用”或“已回退”的反馈。若这是刻意的产品下线，应同步移除可达入口和旧 action；若仍要兼容链接，应提供明确的迁移提示并记录一次导航事件。

### 16. 跨页面事实截止周不一致

浏览器复核发现预警中心显示“最新采集 2026W41”，而预测页范围卡写成“真实价格事实截止 2026-W42”。如果两页读取不同数据源，必须明确标出来源和各自 as-of；如果属于同一批次，则应由共享 freshness contract 生成，避免用户把时间差误解为数据缺失或预测窗口变化。

### 17. 配置页缺少高密度长列表的导航与定位

配置页 AX 树超过 600 个节点，上一代关系、竞品匹配、店铺与规则连续堆叠，当前没有明显的分区索引 / 搜索入口。用户在窄屏或回访配置时难以定位并确认保存范围。应增加可见分区导航、字段搜索、未保存状态与保存结果反馈，并为长列表提供局部滚动而不是整页迷失。

## 量价走势四项反馈的当前完成度

源码复核显示，这四项并非都处于“待合并”状态。当前 `VolumePrice.tsx` 已包含一部分对应实现，但仍有两项达标缺口：

| 反馈 | 当前实现 | 结论 | 下一步 |
| --- | --- | --- | --- |
| 两个主产品并排不能读 | 外层 `minWidth: 880`，面板区使用局部 `overflowX: auto`；两个面板各占 50%，超过 3 个面板才横向展开 | 基本达标 | 在 390 / 768 宽度用真实双主品复核滚动焦点、面板最小可读宽度和键盘可达性 |
| 极差卡覆盖在图表顶部且保持可见 | 两张卡已移到主图上方，并按绘图区左右缘排列 | 部分达标 | 当前是普通文档流块，不是 sticky / overlay；需要固定在图表顶部的阅读层，避免滚动图形或窄屏时再次占高、遮挡或脱离选区 |
| 成本与销毛双 Y 轴、独立 X 轴 | `MarginCostBand` 已有独立成本销毛带和右侧刻度，但 `marginCostDomainOf` 把成本与销毛合在同一值域；X 轴仍复用下方 `PanelTimeTrack` | 未达标 | 分离 cost / margin scale 与轴标识；为成本销毛带提供明确独立 X 轴，同时保持与主图观察周、拖选、键盘联动 |
| 单主产品降低品牌色负担 | 当前面板背景为中性色，品牌色主要用于折线、柱和小标记 | 基本达标 | 验证单主品与多主品、空态、缺采时不恢复大面积品牌底色；去掉不必要的品牌图例重复 |

继续修改量价走势时，必须额外检查：删除中间面板、平台切换、时间同步、缺采、窄面板、拖选、键盘观察周、局部横滚和离线构建。不要把“卡片已移到图上方”直接写成“sticky overlay 已完成”。
